## Research question
How can an individual-device (user-level) federated recommender system unlearn a sensitive user attribute (e.g., gender, age) so that the model no longer leaks it — while (i) keeping adversarial training stable despite non-IID sparse per-user data and random client sampling, and (ii) preventing the same attribute from leaking through the uploaded gradients?

## Problem definition
Federated recommender systems (FedRecs) keep raw interaction data on-device but still encode sensitive attributes into user embeddings, exposing them to attribute inference attacks; federated learning alone does not satisfy the "right to be forgotten" (GDPR/CCPA). Group-level attribute-unlearning methods (distribution alignment, post-training tuning) require aggregating data across users and are inapplicable to user-level FedRecs where data is strictly isolated per device. The authors frame two challenges: CH1 stable adversarial training without global pre-training; CH2 preventing gradient-based attribute leakage (e.g., DLG/iDLG reconstruction).

## System or model being studied
User-level FedRecs: each client is one user's device holding a private interaction vector; user embeddings stay local, item embeddings and scoring parameters are uploaded and aggregated. Recommendation objective uses a matching score (e.g., BPR loss). Representative recommendation backbones (names in truncated section).

## Threat model
- Adversary objective: infer a protected user attribute y (gender/age) from embeddings or reconstruct attribute labels from gradients transmitted during federated communication.
- Adversary knowledge: honest-but-curious server / eavesdropper on server-client communication observing gradients (gray-box on the training protocol). Embedding-based inference assumes access to user embeddings; gradient-based reconstruction (DLG/iDLG) assumes access to uploaded gradients.
- Adversary access: server-side aggregation channel and/or released model; no access to raw on-device interaction data.
- Adversary capabilities: run a gradient-matching reconstruction (DLG) optimizing dummy (embedding, label) to match observed gradients; run an attribute classifier on embeddings.
- Attacker budget: not quantified in provided text (iterative optimization).
- Phase: training (gradient leakage during federated rounds) and inference/deployment (attribute inference from learned embeddings).
- Targeted / untargeted: targeted at recovering a specific protected attribute.
- Digital / physical: digital.
- Adaptive / non-adaptive: evaluated against known non-adaptive attacks (DLG/iDLG); no attacker adapting to DSVAE is described in provided text.

## Trust assumptions
Server performs correct aggregation but is a potential inference adversary; the communication gradient is observable and therefore untrusted for privacy. Users are honest. The defense assumes the protected attribute label is available locally for the per-user adversarial objective.

## Attack or failure mechanism
Two leakage channels: (1) embedding leakage — standard user embeddings encode the attribute; (2) gradient leakage — even with embedding-level adversarial unlearning, DLG/iDLG can reconstruct the true label from raw gradients via a closed-form final-layer solution (yi* = ŷi' − δi). A plain VAE injects stochasticity only on the σ path, leaving the deterministic µ path exploitable by DLG.

## Proposed defense or method
FedAU2 = adversarial attribute unlearning + two components:
- Selective Unlearning Trigger (SUT) (CH1): per-user adaptive perturbation budget via a Gradient Reversal Layer. A binary trigger applies unlearning only when the adversarial classifier predicts the attribute correctly (ϵu = ϵ if ŷu = yu else 0), using prediction correctness as a cheap proxy for margin/gradient-norm, eliminating global pre-training and stabilizing training under heterogeneity.
- Dual-Stochastic Variational AutoEncoder (DSVAE) (CH2): injects stochasticity on both µ and σ paths so the deterministic path DLG relies on is perturbed, masking the attribute label in gradients. Theoretical corollaries argue the dual-stochastic design disrupts DLG's µ-path correction term where a standard VAE does not.

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Defense evaluated only against known, non-adaptive gradient attacks (DLG/iDLG); an attacker aware of the dual-stochastic perturbation (e.g., averaging over samples, or attacking the σ statistics) is not evaluated.
- Requires the protected attribute label locally to drive adversarial unlearning — a strong assumption and itself a sensitive datum on-device.
- The SUT proxy (prediction-correct ⇒ apply unlearning) may misfire early in training or for minority-attribute users, and single-attribute focus (gender/age) may not extend to multiple correlated attributes.
- Injected stochasticity trades off utility; the utility cost at strong privacy is not visible in the provided text.
- No formal privacy guarantee (not differential privacy); protection is empirical/heuristic against a specific reconstruction procedure.

## Design implications
Privacy for federated agents/recommenders must defend BOTH the representation and the gradient channel; scrubbing an attribute from embeddings does not stop gradient reconstruction. Per-client adaptive control (rather than a global schedule) is a viable pattern for heterogeneous, non-IID federated fleets.

## Implementation implications
GRL-based adversarial unlearning plus dual-path stochastic bottlenecks can be added client-side without server changes; correctness-gated triggering avoids a global pre-training phase, easing deployment in sparse-participation settings.

## Evaluation implications
Attribute-unlearning defenses should be tested against gradient-reconstruction attacks (not just embedding classifiers) and ideally against adaptive attackers; report the utility/privacy Pareto frontier.

## Deployment implications
Relevant to on-device federated personalization where "right to be forgotten" and attribute-inference resistance are compliance requirements; the local-only design fits strict per-device data isolation.

## Monitoring and incident implications
Gradient channels are an audit surface: monitor for reconstruction-style probing and log per-round aggregation. Absence of a formal guarantee means residual attribute leakage risk should be tracked, not assumed eliminated.

## Applicability boundaries
Findings apply to user-level federated recommenders and attribute-inference/gradient-leakage threat models. They do NOT establish security against adaptive attackers, do not provide DP-style guarantees, and do not directly transfer to LLM-agent prompt/tool-injection threats. Peripheral to agentic tool/prompt security; relevant as a privacy-preserving-ML and federated-identity pattern.
