## Research question
Why do existing federated-learning (FL) backdoor defenses fail under domain skew (differing feature distributions
across clients), and how can an FL system stay backdoor-robust without sacrificing benign accuracy when client
updates are naturally heterogeneous?

## Problem definition
FL backdoor defenses (distance-based, statistical-distribution, model-refinement) assume client-data homogeneity so
malicious updates appear as outliers. Under domain skew (same class, different features across clients — e.g.,
MNIST/USPS/SVHN/SYN digits), benign update heterogeneity increases: t-SNE shows Digits features overlap chaotically
vs. MNIST's clean clusters. This lets poisoned updates blend into the natural diversity and causes defenses to
misclassify benign updates as outliers — collapsing detection.

## System or model being studied
DoBlock, a backdoor-robust FL framework for domain skew. Key idea from an ablation: a stable backdoor requires BOTH
trigger injection AND target-label manipulation (either alone yields ASR <4% or severe main-accuracy loss);
combining them yields >99% ASR that survives aggregation. DoBlock therefore blocks the propagation of malicious
trigger–label associations by architectural separation: each client has (a) a lightweight "domain infuser" (Conv1 →
domain embedder/classifier producing domain maps → Conv2 → FiLM affine modulation) that only adapts input features to
client-specific style (brightness/contrast/texture) and is deliberately incapable of learning label associations, and
(b) a local model that maps features→labels. ONLY the domain infuser is aggregated across clients (cross-domain style
knowledge sharing); the local model stays private and is excluded from aggregation, so malicious feature–label
associations cannot propagate to benign clients.

## Threat model
- Adversary objective: high Attack Success Rate (triggered inputs → attacker's target label) while keeping high main
  task accuracy on clean data.
- Adversary knowledge/capability: a malicious FL client that obeys the FL protocol; has access to its own data,
  model, and gradients; poisons its local training via trigger injection (x̂ = (1−δ)⊙x + δ⊙Φ) plus target-label
  manipulation; cannot access or alter other clients' data/labels, and cannot interfere with aggregation itself.
- Attacker budget: standard poisoning of its local dataset; supports pixel-level, model-replacement, Sybil, clean-
  label, and stealthy (Neurotoxin-style) attacks — the defense aims to cover all.
- Phase: training-time (FL aggregation rounds).
- Targeted / untargeted: targeted (trigger→target label).
- Digital / physical: digital.
- Adaptive / non-adaptive: evaluated against multiple known attacks; NOT explicitly evaluated against an adaptive
  attacker designed to defeat DoBlock's infuser/local-model separation.

## Trust assumptions
Assumes an honest server performing aggregation of the domain infuser; assumes clients keep local models private
(never aggregated); assumes benign feature–label associations can be learned adequately from each client's own clean
local data (i.e., local-only label learning does not unduly harm accuracy); assumes the infuser's limited capacity
genuinely prevents it from encoding trigger–label backdoors.

## Attack or failure mechanism (that DoBlock counters)
Backdoor success in FL depends on establishing a stable trigger–label association in a client's local model and then
propagating it globally through aggregation. Domain skew both (a) hides malicious updates within heterogeneous benign
updates (defeating outlier detection) and (b) makes the global model prone to overfitting that amplifies backdoor
effect. DoBlock's ablation isolates the two necessary components (trigger + label manipulation) and blocks
propagation by removing the label-association-bearing component (local model) from aggregation.

## Proposed defense or method
DoBlock (above): aggregatable, capability-limited domain infuser (FiLM-based style modulation) shared across clients
+ private, non-aggregated local model. This restricts feature→label association learning to local clean data and
shares only benign domain/style knowledge, blocking backdoor propagation pathways while enabling cross-domain
generalization.

## Datasets and benchmarks
Five domain-skew datasets: Digits (MNIST/USPS/SYN/SVHN), PACS, VLCS, Office-Caltech10, DomainNet.

## Evaluation methodology
Compare Main Accuracy (MA), Attack Success Rate (ASR), and Robust Accuracy (RA) against FedAvg and many defenses/
robust-aggregation baselines (FedHEAL, FedDG-GA, gPerXAN, Multi-Krum, Foolsgold, MMA, DnC, FLAME, RFA, Alignins,
etc.) across the five datasets and multiple backdoor attacks; ablation isolating trigger injection vs. label
manipulation (Table 1); t-SNE visualization of domain skew.

## Metrics
MA (main task accuracy on clean data, higher better), ASR (attack success rate, lower better), RA (robust accuracy,
higher better). Author headline: DoBlock keeps ASR below 2.5% while achieving the highest MA.

## Main findings
- Author claim: existing FL backdoor defenses fail under domain skew — benign heterogeneity conflates with malicious
  updates (shown across Tables 2–4; e.g., FedAvg ASR ~99% on Digits; several defenses still >95% ASR).
- Author claim (ablation, Table 1): both trigger injection AND label manipulation are necessary for a stable backdoor
  (trigger-only ASR <4%; label-only ASR 10–22% with severe MA loss; combined >99% ASR).
- Author claim: DoBlock maintains ASR < 2.5% while achieving the highest MA across the five domain-skew datasets —
  robustness without sacrificing benign performance; first backdoor-robust FL specifically designed for domain skew.

## Negative results
The paper's central negative result is about the baselines: distance/statistical/refinement defenses (Multi-Krum,
FLAME, RFA, DnC, etc.) fail to suppress ASR under domain skew (many remain >95% ASR), and generalization-oriented
domain-skew methods (FedHEAL, FedDG-GA, gPerXAN) lack any mechanism to detect malicious updates. Foolsgold/MMA/
Alignins reduce ASR only at large MA cost on some domains.

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Because local models never aggregate, cross-client label knowledge is not shared; benefit hinges on each client
  having enough clean local data to learn good feature→label maps — clients with scarce data may suffer (not
  characterized in the excerpt).
- No adaptive attacker specifically targeting the infuser (e.g., encoding associations into style channels) or
  exploiting FiLM modulation is evaluated — robustness is against known, non-adaptive attacks.
- The claim that the infuser is "incapable of embedding malicious associations" is architectural/intuitive, not
  formally proven; capacity limits are a heuristic guarantee.
- Server is assumed honest; a malicious server aggregating infusers is out of scope.
- No code/artifact link in the text ⇒ reproducibility depends on re-implementation.

## Design implications
Capability isolation / least privilege at the architectural level is an effective backdoor-propagation control:
sharing only a component that structurally cannot learn the malicious feature→label mapping blocks propagation
without needing to detect malicious clients (which is unreliable under heterogeneity). "Don't aggregate what can
carry the attack" is a transferable principle for federated/collaborative agent systems.

## Implementation implications
For heterogeneous FL, prefer partitioning the model so that only benign, low-capacity, style/representation
components are aggregated while decision-bearing components remain local; combine with (not replace) robust
aggregation. Where cross-client label knowledge is essential, quantify the accuracy cost of local-only label
learning.

## Evaluation implications
FL backdoor defenses MUST be evaluated under domain skew, not just i.i.d. homogeneity — homogeneity-era results
overstate robustness. Report MA/ASR/RA jointly (some baselines cut ASR only by destroying MA). Add adaptive attackers
that target the specific defense architecture.

## Deployment implications
Applicable to cross-silo/cross-device FL with naturally heterogeneous clients (healthcare, finance, IoT). DoBlock
trades cross-client label-knowledge sharing for backdoor isolation; deploy where local data suffices for local label
learning and where an honest aggregation server can be assumed.

## Monitoring and incident implications
Detection-based monitoring is unreliable under domain skew (benign≈malicious); DoBlock shifts to prevention by
isolation. Still, monitor per-client MA/ASR and infuser drift; retain provenance of aggregated infuser updates for
incident analysis since local-model compromise stays contained to one client.

## Applicability boundaries
Findings apply to backdoor-robust FL for image classification under domain skew with an honest server and adequate
local data. They should NOT be generalized to label-distribution skew only, to settings needing global label-
knowledge sharing, to malicious-server threat models, or directly to LLM/agent prompt/tool security. Relevance to
agent security is adjacent: a clean instance of capability-isolation / least-privilege as a propagation control in a
multi-party learning system.
