## Research question
Can text embeddings used by LLMs / RAG vector databases be transformed so that adversaries who obtain the embeddings cannot reconstruct the original sensitive input text (embedding inversion), while preserving downstream task utility?

## Problem definition
Text embeddings encapsulate sensitive input features and are vulnerable to inversion attacks that reconstruct the original text. Existing defenses (noise superposition, perturbation, differential privacy) either degrade downstream utility or treat embeddings at the feature level independently, ignoring the mutual relationship along the embedding-construction pipeline. The goal is a privacy-utility trade-off superior to prior defenses.

## System or model being studied
Embedding models producing dense vectors e = Pooling(h) from a Transformer encoder (BERT/T5/LLaMA family), consumed by downstream NLP tasks (retrieval, classification, generation). Eguard inserts a projection network (implemented as a 24-layer RoBERTa encoder) that maps raw embeddings e into a secured space ê between the embedding and any downstream/adversary use.

## Threat model
- Adversary objective: reconstruct original text x from its embedding φ(x) by learning an inverse/decoder model.
- Adversary knowledge: "strong adversary" — can acquire embeddings (e.g., via database breaches) and holds an auxiliary dataset D_aux matching the target-text distribution; an adaptive adversary may also know the defense mechanism.
- Adversary access: access to (defended) embeddings; ability to train a decoder-based transformer (GPT-2) to maximize p(x | φ(φ(x))).
- Adversary capabilities: train inversion decoder on in-domain data; adaptive refinement against the defense.
- Attacker budget: not quantified beyond training a GPT-2 decoder (max seq length 128, Adamax, lr 2e-2, batch 16).
- Phase: inference / deployment (embeddings emitted and exfiltrated); defense trained offline.
- Targeted / untargeted: reconstruction (recover original text) — untargeted w.r.t. content.
- Digital / physical: digital.
- Adaptive / non-adaptive: both non-adaptive and an adaptive (defense-aware) attack are claimed to be evaluated.

## Trust assumptions
Assumes the embedding pipeline/projection network is trusted and not itself exfiltrated; the adversary is downstream of the projection. Assumes a pretrained autoencoder can losslessly substitute latent z for discrete text x when estimating mutual information (H(x|z)=0 assumption). Downstream task heads are trusted and co-trained.

## Attack or failure mechanism
Inversion is modeled as a Markov chain x → e → x̂. Attacker minimizes ||φ(x̂) − φ(x)|| or trains a decoder to maximize likelihood of x given the embedding. Eguard extends the chain to x → e → ê → x̂ and attacks the information flow by reducing recoverable information.

## Proposed defense or method
Mutual-information-optimization defense with two objectives: (1) Global MI (Sensitive Feature Detachment): minimize I(x, ê) via a MINE-style statistical network S_θ (Belghazi et al.), using autoencoder latent z as a lossless proxy for discrete x; regularizer L = ℓ_task + α·I_global. (2) Local MI (Functionality Preservation): keyword-antonym contrastive learning minimizing an upper bound I_local(k,a) (CLUB-style, Cheng et al.) via variational network V, extracting keywords/antonyms with NLTK. Unified objective L = ℓ_task + α·I_global + β·I_local; task heads use cross-entropy (classification), MNRL (retrieval), sequence cross-entropy (generation). Lemmas 1–3 give informal theoretical support (proofs in extended version).

## Datasets and benchmarks
Four tasks: SST (sentiment), NLI (natural language inference), QR (question retrieval), TS (text summarization). Embedding models: T5, RoBERTa, MPNet, LLaMA, Gemma (tables also list LLaMA2, LLaMA3-70B, Gemma2-9B), all frozen; abstract claims "seven embedding models and two ChatGPT embeddings." Inversion decoder: GPT-2. Baselines: FGSM, FreeLB (adversarial training), DPForward, DPSanitization (DP-based).

## Evaluation methodology
Train projection network per embedding model; run inversion decoder against defended embeddings; compare reconstruction (privacy) and downstream utility to baselines. Additional evaluations claimed for robustness to perturbations, unseen datasets, and adaptive attacks (details in extended version).

## Metrics
Privacy/defense: F1, Recall, BLEU on reconstructed vs original text (lower = stronger protection). Utility: Accuracy (SST, NLI, QR), ROUGE (TS) (higher = better preserved).

## Main findings
- Author claim: Eguard blocks >95% of token inversion and maintains >98% task consistency.
- In Table 1, "Ours" yields the lowest F1/Recall/BLEU across T5, LLaMA2, LLaMA3-70B, Gemma2-9B and all four tasks (e.g., F1 dropping from ~93–98% "W/ Attack" to ~3.5–5.6%), outperforming FGSM, FreeLB, DPForward, DPSanitization.
- Author claim: strong robustness to perturbations, unseen datasets, and adaptive attacks.

## Negative results
None explicitly reported as failures. The global-MI objective is noted to introduce a utility-preservation challenge, which the local-MI module is designed to offset (motivation, not a reported negative result).

## Additional limitations identified during review
_(reviewer synthesis)_
- Single inversion decoder family (GPT-2) evaluated; stronger/more recent inversion attacks (e.g., generative embedding inversion, BeamClean) not clearly stressed in main tables.
- The lossless-substitution assumption (H(x|z)=0) is idealized; real autoencoders are lossy, so I(z,ê) only approximates I(x,ê).
- "Adaptive attack" robustness is asserted but the adaptive attacker's exact strategy/strength is not detailed in the extracted text.
- Adds a 24-layer RoBERTa projection network — latency/compute overhead for RAG-scale embedding serving is not quantified here.
- No formal privacy guarantee (unlike DP baselines); protection is empirical against the tested inversion model.

## Design implications
Treating embedding privacy as an information-flow (Markov-chain) problem, and inserting a trained obfuscation stage between embedding and consumer, is a reusable pattern for protecting RAG vector stores / agent long-term memory. Utility must be co-optimized (local MI) or protection collapses task performance.

## Implementation implications
A projection/sanitization layer can sit at the embedding-serving boundary before vectors are written to a database. Requires task-aware training (task heads) and MI estimators; adds a non-trivial encoder to the serving path.

## Evaluation implications
Embedding-privacy defenses should be measured on both reconstruction metrics (F1/Recall/BLEU) and downstream utility, and against adaptive, defense-aware inversion — not only a fixed decoder.

## Deployment implications
Relevant to any system that stores or transmits text embeddings (vector databases, embedding APIs, RAG memory). Database-breach exfiltration of raw embeddings is treated as a realistic exposure; sanitized embeddings limit but do not provably eliminate recoverable content.

## Monitoring and incident implications
No detection/monitoring component; this is a preventive transformation. Residual risk (up to ~5% tokens recoverable per author numbers) means embedding stores should still be treated as sensitive and access-logged.

## Applicability boundaries
Findings apply to text-embedding inversion for LLM/RAG pipelines. Should NOT be read as a formal privacy guarantee, nor generalized to image/multimodal embeddings or to adversaries who compromise the projection network itself. Effectiveness against future stronger inversion attacks is unverified.
