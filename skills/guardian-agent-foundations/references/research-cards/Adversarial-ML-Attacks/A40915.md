## Research question
Can a white-box, weight-based neural-network watermark be designed to defend simultaneously against both forging attacks (fabricating a counterfeit watermark/key by reverse engineering without changing weights) and overwriting attacks (removing the original mark by embedding a stronger counterfeit), while also resisting fine-tuning and pruning?

## Problem definition
Weight-based NNW embeds watermarks directly into parameters. State-of-the-art weight-based methods resist fine-tuning/pruning but remain partially vulnerable to forging and/or overwriting. Forging causes ownership ambiguity (adversary claims ownership via a reverse-engineered key); overwriting invalidates the owner's mark. The paper seeks a mechanism robust to all four.

## System or model being studied
Deep neural networks as protected digital assets: 13 architectures (8 CNNs: AlexNet, VGG-13, VGG-16, GoogLeNet, ResNet-18, ResNet-34, WideResNet-50, MobileNet-V3-L; 3 Transformers: ViT-B/16, Swin-V2-B, Swin-V2-S; 2 text-gen: GPT-2-S, GPT-2-M), across five image-classification datasets and one text-generation task.

## Threat model
- Adversary objective: claim ownership (forging) or invalidate the owner's watermark (overwriting), or remove it via fine-tuning/pruning, while preserving model performance.
- Adversary knowledge: white-box — can access the watermarked model, identify watermark-containing layers, and obtain the original training data.
- Adversary access: full model parameters; can freeze weights (forging) or modify them (overwriting/fine-tuning/pruning).
- Adversary capabilities: gradient-based reverse engineering to derive a counterfeit secret key with weights frozen; adaptive over-strength embedding for overwriting; standard fine-tuning and pruning.
- Attacker budget: limited computational resources (assumption: an adversary with enough compute would just train a new model, making theft pointless).
- Phase: post-training / deployment (model already trained and watermarked).
- Targeted / untargeted: targeted ownership subversion.
- Digital / physical: digital.
- Adaptive / non-adaptive: overwriting adversary can adaptively increase embedding strength; forging adversary optimizes a key against frozen weights.

## Trust assumptions
A fully trusted third-party verifier performs watermark verification. Success criteria are formalized: a forging adversary must pass verification without altering weights; an overwriting adversary must remove the original mark and embed a counterfeit while preserving performance. Because a model can retain *both* marks, the owner can submit a version containing only the original watermark for adjudication.

## Attack or failure mechanism
- Forging: freeze weights, optimize a secret key so a counterfeit watermark passes verification (reverse engineering via gradient backpropagation).
- Overwriting: embed a counterfeit watermark in the same parameters, pushing them in a conflicting direction that erases the original.
- Fine-tuning / pruning: perturb or sparsify parameters to remove the mark.

## Proposed defense or method
NeuralMark, a weight-based method built on a *hashed watermark filter*: (1) Hashed watermark generation — b = H(K) using SHAKE-256 (SHA-3 extendable-output function) from a Gaussian secret-key matrix K (optionally b = H(K||C) with auxiliary content). (2) Watermark embedding — repeatedly use the binary watermark as a *filter* selecting the parameter subset (positions where b=1) over R rounds, then average-pool the filtered parameters and embed via a lightweight binary-cross-entropy embedding loss added to the main task loss (min L_m + λ L_e). Two properties: **Gradient obfuscation** (hash avalanche effect makes minor key changes cause large unpredictable output changes, impeding gradient-based forging) and **Embedding isolation** (distinct hashed filters progressively reduce parameter overlap between owner and adversary — e.g., 100% → 50% → 0% over two rounds, hindering overwriting). Average pooling adds fine-tuning/pruning resistance. Theory (Proposition 1) upper-bounds the forging probability; with n=256 and detection rate ρ >= 88.29%, forgery probability < 1/2^128 (used as the security bound).

## Datasets and benchmarks
Image classification: CIFAR-10, CIFAR-100, Caltech-101, Caltech-256, TinyImageNet. Text generation: E2E. 13 architectures as listed. Attack baselines / prior watermark families: weight-based, passport-based, activation-based methods (e.g., Uchida et al., DeepIPR/passport, greedy residuals). Comparison also to a private-filter-only baseline (shown insufficient against forging).

## Evaluation methodology
Embed NeuralMark during main-task training; evaluate watermark detection rate and clean accuracy under forging, overwriting, fine-tuning, and pruning; analyze filtering-round overlap ratios (five counterfeit watermarks) and performance-convergence curves vs. a clean model.

## Metrics
Watermark detection rate ρ (fraction of matching bits, with security bound 88.29% at n=256); model (task) accuracy; parameter overlap ratio across filtering rounds.

## Main findings
- Author claim: NeuralMark defends against both forging and overwriting (the gap left by prior weight-based methods) while retaining fine-tuning/pruning resistance from average pooling.
- Theoretical security boundary: forging a counterfeit key to reach ρ >= 88.29% has probability < 1/2^128 (n=256), giving high-confidence ownership.
- Embedding isolation: repeated hashed filtering drives owner/adversary parameter overlap toward 0%, preserving the original mark under overwriting.
- Performance convergence of NeuralMark closely tracks a clean model on CIFAR-100/ResNet-18 (negligible utility impact).
- Necessity result: a private filter *without* a hashed watermark resists overwriting but remains forgeable (e.g., identity-matrix key attack); the hash is what closes the forging gap.

## Negative results
The plain private-filter baseline is explicitly shown vulnerable to forging — a documented negative result motivating the hashed design rather than a NeuralMark failure. No NeuralMark failure case is reported in the visible text.

## Limitations stated by the authors
Scope limited to white-box NNW (black-box and box-free watermarking left to future work). Future work: integrating the hashed-filter idea with existing watermarking approaches for broader attack coverage.

## Additional limitations identified during review
_(reviewer synthesis — clearly not author claims)_
- The security bound (Proposition 1) rests on the assumption that the hash produces uniformly distributed outputs (random-oracle style); it bounds *forging by random key search*, not necessarily an optimizer that exploits embedding-loss structure.
- Adversary is assumed compute-limited; a well-resourced adversary (the paper's own out-of-scope case) or one who partially retrains is not covered.
- Overwriting resistance is argued via overlap-ratio reduction; the visible text does not fully quantify residual detection rate under an *adaptive maximal-strength* overwriting adversary across all 13 architectures.
- No adaptive attacker that knows the hashed-filter defense and targets the average-pooling / filter positions is evaluated in the visible text.
- Text-generation watermarking (GPT-2/E2E) results are asserted but detailed robustness numbers were truncated in the extracted text.

## Design implications
Binding the *embedding location* cryptographically to the watermark (hash-as-filter) entangles key, mark, and parameter subset so that forging (needs gradients) and overwriting (needs to hit the same parameters) both become hard — a defense-in-depth pattern for model provenance. Irreversibility (one-way hash) and isolation (non-overlapping filters) are complementary properties.

## Implementation implications
Use an extendable-output hash (SHAKE-256) for adjustable watermark length; repeat filtering to drive down cross-owner overlap; average-pool filtered parameters for perturbation robustness; keep embedding loss lightweight to avoid utility loss.

## Evaluation implications
Watermark schemes should be evaluated against forging AND overwriting AND fine-tuning AND pruning jointly; a scheme robust to removal but forgeable still fails ownership resolution. Provide a theoretical false-claim bound, not only empirical detection rates.

## Deployment implications
For owners distributing model weights (open weights / licensed models), NeuralMark provides a verifiable, hash-anchored ownership claim adjudicated by a trusted third party; the owner retains a single-watermark version for dispute resolution.

## Monitoring and incident implications
Ownership disputes are resolved offline by the trusted verifier via detection-rate thresholding against the security bound; no runtime monitoring is proposed.

## Applicability boundaries
Applies to white-box weight-based NN watermarking / model-IP provenance across CNNs, Transformers, and small LLMs (GPT-2). Adjacent to agent security: concerns model_weights ownership, cryptographic provenance, and forgery/theft — transferable to protecting model artifacts in an agent stack, but it is not about prompt/tool/agent-runtime security. Do not extend the 1/2^128 forging bound beyond the stated assumptions (uniform hash outputs, n=256, compute-limited adversary).
