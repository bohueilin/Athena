## Research question
Can an adversary attack the timeliness/availability (not just integrity) of vehicular cooperative perception (CP) by injecting adversarial perturbations into V2V messages that inflate the CP pipeline's computation latency?

## Problem definition
Cooperative perception fuses V2V-shared sensor features so connected/autonomous vehicles (CAVs) see beyond line-of-sight. Prior CP attacks target integrity (object spoofing/removal). Availability — timely detection, a safety-critical requirement — was unexplored. If CP fails to produce timely detections, downstream autonomous-driving decisions are made blind, risking collisions. Existing integrity defenses require detection results to operate and are thus ineffective if results never arrive on time.

## System or model being studied
Intermediate-fusion SOTA CP pipelines (BEV-feature exchange + deep fusion). Evaluated CP algorithms: AttFusion (OPV2V), Where2comm (W2C), CoAlign, V2VAM. Pipeline stages analyzed: feature extraction, message exchange, deep feature fusion (attention), inference (CNN), post-processing (Non-Maximum Suppression, NMS with O(M²) complexity).

## Threat model
- Adversary objective: maximize the victim's end-to-end CP latency T(·) (availability/denial), pushing per-frame processing beyond safety thresholds (success if latency > 1.5 s, the worst-case time-to-collision threshold).
- Adversary knowledge (white/gray/black-box): white-box attacker controlling a compromised CAV (knows the CP model to compute gradients at the feature level).
- Adversary access: a single compromised/malicious CAV that can manipulate its own outgoing V2V (shared BEV feature) messages injected into fusion.
- Adversary capabilities: add an adversarial perturbation δ to its shared feature Xa; craft it online under asynchronous conditions (only has victim's feature from t−1 when attacking frame t).
- Attacker budget: one compromised CAV; feature-level perturbation (bypasses non-differentiable LiDAR preprocessing); real-time optimization constraints.
- Phase (training / inference / deployment): inference/runtime attack during live V2V operation.
- Targeted / untargeted: targets availability (latency inflation); not object-specific spoofing.
- Digital / physical: digital injection via V2V messages (feature-level), evaluated on a real-world vehicle testbed and benchmark data.
- Adaptive / non-adaptive: attack addresses realistic asynchrony (spatial-temporal feature warping to compensate transmission delay); defenses are discussed but not adaptively co-optimized.

## Trust assumptions
CP implicitly trusts feature messages from participating CAVs and fuses them; there is no timeliness-preserving validation before the expensive fusion+NMS stages. The attacker needs only to be an authenticated participant contributing features. Existing integrity defenses assume detection outputs are available to verify/repair — an assumption CP-FREEZER violates.

## Attack or failure mechanism
The attack exploits NMS's quadratic O(M²) cost by inflating the number of high-confidence, physically plausible, sparsely distributed pre-NMS bounding-box proposals so they survive filtering and cannot be efficiently pruned. Three challenges solved: (C1) non-differentiable point-cloud preprocessing → craft perturbations at the BEV feature level; (C2) latency-inducing loss (new objective, unlike accuracy-degradation attacks) combining Confidence Activation loss (push objectness to threshold τ at many anchors), Shape Regularization loss (avoid oversized/overlapping boxes so more survive NMS), and Vertical Plausibility loss (keep boxes in realistic elevation), unified as Ltotal = λ1 Lconf + λ2 (Lshape + Lvertical); (C3) asynchronous attacker knowledge → spatial-temporal BEV feature warping via affine transform Tt−1→t to predict the victim's state and align the perturbation.

## Proposed defense or method
This is an attack paper; no full defense is proposed. Authors discuss potential defenses: current CP defenses need available detection results (susceptible to CP-FREEZER); tuning hyperparameters to cap proposal counts can bound worst-case latency but risks missing true detections and cannot fully mitigate the slowdown. They call for proactive availability defenses.

## Datasets and benchmarks
OPV2V benchmark (large-scale V2V perception dataset): 11,464 LiDAR point-cloud frames from 2–5 CAV agents, 232,913 annotated 3D vehicle bounding boxes. Victim/attacker chosen as the lowest and second-lowest CAV indices.

## Evaluation methodology
Evaluated on four SOTA CP algorithms across three hardware platforms (e.g., RTX 2080 Super and others; details partly truncated) and a real-world vehicle testbed. Baselines: feature-level PGD and adapted single-vehicle latency attacks SlowLiDAR and SlowTrack. Reports latency in benign vs. attacked conditions and hardware-independent rate-of-increase metrics; success defined by 1.5 s latency threshold with ASR reported across thresholds.

## Metrics
- Average end-to-end CP latency (benign T̄benign vs. attacked T̄attack).
- Relative standard deviation (%RSD) of latency.
- Rate-of-Increase of latency RoI-L = (Tattack − Tbenign)/Tbenign and of pre-NMS proposal count RoI-P (hardware-independent).
- Attack Success Rate (ASR): fraction of frames pushed beyond the 1.5 s latency threshold.

## Main findings
- CP-FREEZER is the first latency/availability attack on CP; it increases end-to-end CP latency by over 90×, pushing per-frame processing beyond 3 seconds with 100% success rate on the real-world vehicle testbed. (Author claim, empirically supported.)
- It substantially surpasses adaptations of existing single-vehicle latency attacks (SlowLiDAR, SlowTrack) and PGD, which were not designed for CP's multi-agent, non-differentiable pipeline.
- NMS's quadratic complexity is the dominant exploitable bottleneck among CP stages; other stages (feature extraction O(linear), CNN inference, message-exchange jamming) offer no practical availability vector for a single attacker.
- Spatial-temporal warping compensates for asynchronous transmission and improves attack effectiveness under realistic V2V timing.

## Negative results
- Wireless jamming of message exchange degrades range (victim reverts to single-vehicle perception) but not availability — not a viable latency attack.
- Attacking the O(N²) attention fusion would require many malicious CAVs (impractical), so it is not the chosen vector.
- Capping proposal counts as a defense reduces worst-case latency but increases risk of missing true detections and cannot fully remove the slowdown (defense trade-off).

## Limitations stated by the authors
- No robust defense is provided; existing CP defenses are ineffective against this threat and only mitigations (hyperparameter capping) are discussed with explicit downsides.
- Attack assumes a white-box compromised CAV.

## Additional limitations identified during review

- White-box assumption (attacker knows the CP model) is strong; black-box/transfer feasibility to unknown CP stacks is not established in the extracted text.

## Design implications
Availability is a first-class safety property for multi-agent/collaborative perception and agentic pipelines: any stage with super-linear complexity (here NMS O(M²)) is an availability attack surface reachable by data injection. Architects should bound worst-case compute per fused message and treat "adversary can inflate work" as a design constraint (sponge/latency-attack class).

## Implementation implications
Add input-cost guards before expensive post-processing: cap/rate-limit proposal counts, use latency-bounded NMS variants, and validate feature messages cheaply before fusion. Multi-agent fusion should isolate per-sender compute so one participant cannot blow up shared processing time.

## Evaluation implications
Perception/agent robustness benchmarks should include latency/availability metrics (RoI-L, %RSD, ASR@latency-threshold), not only accuracy/integrity. Hardware-independent rate-of-increase metrics are useful for cross-platform comparison.

## Deployment implications
CAV / robot-swarm / collaborative-inference deployments need proactive availability defenses and sender attestation, because a single compromised participant can paralyze the collective perception in real time. Timeliness SLAs must be enforced defensively, not assumed.

## Monitoring and incident implications
Monitor per-frame CP latency, %RSD, and pre-NMS proposal counts as runtime telemetry; anomalous proposal-count spikes or latency > time-to-collision thresholds should trigger fallback to single-vehicle perception (degraded but timely) and flag the contributing CAV for containment.

## Applicability boundaries
_(where these findings should and should NOT be generalized)_
Applies to intermediate-fusion vehicular cooperative perception (LiDAR/BEV) and, by analogy, to any collaborative multi-agent inference pipeline with data-dependent compute (availability/DoS via crafted inputs — a "sponge/latency" attack class, agent_to_agent + tool_invocation availability). It does NOT establish results for integrity attacks, non-perception agent tasks, or LLM inference latency directly, though the sponge-example lineage transfers conceptually. Adjacent to agent security: strongly relevant to multi-agent availability threat modeling; specific numbers are CP-model and hardware specific.
