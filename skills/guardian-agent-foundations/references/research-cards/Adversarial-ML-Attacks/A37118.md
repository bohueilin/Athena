## Research question
Can a black-box attack that jointly and adaptively coordinates lexical and syntax-level code perturbations (rather than a single isolated strategy) more efficiently generate functionality-preserving adversarial code that evades LM-based software-vulnerability detectors?

## Problem definition
Language-model (LM)-based vulnerability detectors achieve SOTA but are vulnerable to adversarial code that subtly perturbs lexical tokens and/or syntax to evade detection while preserving behavior. Existing black-box attacks use isolated perturbation strategies (e.g., ALERT: lexical only; DIP: random dead-code insertion) and lack a guided, efficient search over the combined adversarial code space, limiting attack efficacy and realistic robustness evaluation.

## System or model being studied
LM-based vulnerability detectors (black-box; e.g., CodeBERT/GraphCodeBERT/CodeT5-family detectors trained on vulnerability datasets — referenced target models). The proposed system HogVul is a black-box, query-based adversarial code generator (attack tool for robustness evaluation).

## Threat model
- Adversary objective: construct adversarial code cadv that flips the detector's prediction (make vulnerable code classified "safe", i.e., raise false negatives) while preserving functionality F(cadv)=F(c) and compilability: argmax P(M(cadv)=1−y), s.t. cadv=c+δ, F(cadv)=F(c).
- Adversary knowledge (white/gray/black-box): black-box, query-based — only prediction probabilities/labels from the target model M are used (no gradients/weights).
- Adversary access: query access to the detector; ability to transform source code (identifier renaming, control-structure transformations).
- Adversary capabilities: lexical perturbations (identifier renaming / token substitution via FastText-embedding cosine similarity, following ALERT vocabulary) and syntax perturbations (semantic-preserving control-flow/AST transformations via TXL), coordinated by Particle Swarm Optimization (PSO).
- Attacker budget: query budget (methods compared under query cost); ten independent runs per model averaged.
- Phase (training / inference / deployment): inference-time evasion of a deployed detector.
- Targeted / untargeted: targeted evasion (flip to the "secure" label 1−y).
- Digital / physical: digital (source-code perturbations).
- Adaptive / non-adaptive: attack adaptively switches strategies (stagnation-aware channel switching); it is evaluated against detectors, not against a detector adaptively defended against HogVul.

## Trust assumptions
Assumes LM-based detectors trust surface lexical/syntactic form and can be misled by semantics-preserving edits. Assumes attacker can preserve functionality/compilability (uses semantics-preserving transformations). Assumes query access is available (realistic for deployed detectors).

## Attack or failure mechanism
Failure mode: LM detectors are vulnerable at multiple levels — lexical substitutions shift input token embeddings/early attention; syntactic changes disrupt higher-level structural reasoning. HogVul unifies both in a dual-channel PSO optimization: (1) Diversity-promoting initialization (similarity-guided + randomized identifier substitutions via FastText cosine similarity); (2) PSO-driven lexical perturbation (particles = variable renamings; velocity from inertia + individual-best + global-best; adaptive w,c1,c2); (3) structure-aware transformation (parse with TXL, extract control structures, weight control-flow types by λ=1.8, mask-based gradient-free sensitive-location identification, semantic-preserving transformation e.g. loop restructuring); (4) dual-channel cooperative optimization with a stagnation counter that triggers switching and cross-channel information fusion (each channel warm-starts from the other's best candidate). This expands the search space and avoids premature convergence, yielding more/higher-quality adversarial examples.

## Proposed defense or method
This is an attack paper; it proposes HogVul as an attack/robustness-evaluation framework, not a defense. It positions itself as a tool to "evaluate the robustness" of LM-based vulnerability detectors and expose their weaknesses; no dedicated defense is developed in the extracted text.

## Datasets and benchmarks
Four benchmark datasets (abstract in extracted body); named/referenced include Devign (48,000+ functions) and others in the vulnerability-detection literature (e.g., DiverseVul, D2A referenced). Diverse vulnerability types (CWE, MITRE 2023). One dataset held out entirely unseen for distribution-shift robustness testing.

## Evaluation methodology
Five-part evaluation: (1) effectiveness across three benchmark datasets spanning diverse vulnerability types (ASR); (2) PSO optimization-rationality via search-trajectory visualization; (3) ablation of key components (removing either channel reduces ASR); (4) robustness under distribution shift on a completely unseen dataset without parameter tuning; (5) real-world deployment simulation measuring increase in False Negative Rate (FNR). Ten independent runs per model, averaged; NVIDIA A800 GPU. Compared against SOTA baselines under matched query/optimization budgets; also a diversity metric (CAD) for population-level adversarial-example diversity.

## Metrics
- Attack Success Rate (ASR): fraction of samples where the detector's prediction is flipped.
- False Negative Rate (FNR) increase in deployment simulation.
- Query cost / query-normalized success (for fair budget comparison).
- CAD (population-level diversity of adversarial examples).
- Functionality/compilability preservation constraint (semantics-preserving).

## Main findings
- HogVul achieves an average ASR improvement of 26.05% over SOTA baseline methods across benchmark datasets. (Author claim.)
- Coordinated dual-channel (lexical + syntax) PSO with stagnation-aware switching outperforms isolated single-level attacks (ALERT lexical-only; DIP random dead-code); ablations show each channel is necessary (removing either reduces ASR). (Author claim.)
- HogVul maintains high ASR under distribution shift on a completely unseen dataset without parameter tuning (robust/generalizable attack). (Author claim.)
- Deployment simulation shows meaningful FNR increase when HogVul-perturbed vulnerable code is submitted — i.e., real evasion potential. (Author claim.)
- PSO search-trajectory visualization supports that the optimization guides perturbations toward high-impact configurations.

## Negative results
- Isolated lexical or syntax-only perturbation is insufficient to fully disrupt strongly pretrained models (motivation and ablation) — single-channel variants underperform the combined method.
- Expanded (dual-channel) search space poses a convergence challenge, requiring the stagnation-aware switching/adaptive-PSO mechanisms to avoid suboptimal exploration (an acknowledged difficulty the method must manage).

## Design implications
LM-based code-security tools (vulnerability detectors, and by extension agent code reviewers) are evadable by coordinated multi-level semantics-preserving perturbations; robustness must be evaluated at both lexical and syntactic levels jointly, not in isolation. Directly relevant to agents that rely on LM classifiers to gate/approve code (verifier_gaming / evasion of a safety check). A model that "passes" adversarial code is a confused-deputy risk if an agent trusts its verdict.

## Implementation implications
Hardening LM code detectors should include adversarial training against combined lexical+syntax perturbations, input normalization (identifier canonicalization, dead-code/structure normalization before inference), and ensembling/behavioral (execution-based) checks rather than surface-form classification alone. Rate-limiting and query monitoring can raise the cost of query-based search.

## Evaluation implications
Robustness benchmarks for code/security classifiers should include coordinated multi-channel adversarial attacks, distribution-shift (unseen-dataset) transfer, query-cost-normalized ASR, deployment-style FNR increase, and adversarial-example diversity (CAD). Reporting ASR without query budget can overstate practicality.

## Deployment implications
Deployed LM vulnerability detectors (CI security gates, agent code-approval steps) can be bypassed to let vulnerable code through (raised FNR); do not rely on a single LM detector as a hard security gate. Combine with execution/dynamic analysis, human review for high-risk changes, and monitoring for query-based probing.

## Monitoring and incident implications
Monitor for repeated near-duplicate submissions with identifier-renaming/structure-shuffling patterns and high query volume against a detector — signatures of query-based adversarial search. Track FNR drift over time as an indicator of evasion campaigns. (Reviewer synthesis; not directly measured.)
