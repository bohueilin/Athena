## Research question
Are frontier "defense-in-depth" safeguard pipelines (input + output classifiers wrapped around a model) actually robust to attacks specifically designed to defeat multiple stacked components, or does naive evaluation with existing single-target attacks overestimate their security?

## Problem definition
Frontier developers (Anthropic Opus 4, OpenAI GPT-5) layer safeguards (text classifiers, activation probes) so a harmful request must bypass every layer. There is little prior systematic evaluation or attack for such pipelines. The paper builds an open-source pipeline and a staged attack (STACK) to measure real robustness against catastrophic misuse.

## System or model being studied
Target (guarded) model: Qwen3-14B (thinking disabled). Safeguard components (smaller than the guarded model): open-weight safeguard models used as input/output classifiers — ShieldGemma, Llama Guard 3/4, WildGuard, plus few-shot-prompted classifiers built on Qwen3 and gemma-2-9b ("Gemma2"). The authors contribute a simple few-shot-prompted input/output classifier that outperforms ShieldGemma. Attack: STACK (STaged AttaCK), instantiated with PAP (generative-model jailbreak) + a custom "Confirm" universal classifier jailbreak, plus a repeat-instruction template to make the model emit the output-classifier jailbreak.

## Threat model
- Adversary objective: elicit genuinely harmful (catastrophic-misuse) content that passes both input and output classifiers, judged relative to the original unobfuscated query q0.
- Adversary knowledge: multiple settings formalized along two axes — opacity (white-box weights vs black-box boolean outputs) and separability (per-component access). Main results are under the realistic Black Semi-separable model (attacker sees which component blocked a query, boolean signal only). Transfer setting: white-box separable proxy pipeline, inseparable black-box target.
- Adversary access: can query the pipeline and observe block/allow per component (semi-separable); output-classifier jailbreak is induced via a "repeat this string" instruction.
- Adversary capabilities: universal string-based classifier jailbreaks + a generative-model jailbreak, combined stage-by-stage.
- Attacker budget: multiple independent iterations per datapoint (e.g., 40 for PAP baseline); success if any iteration succeeds.
- Phase: inference/deployment.
- Targeted / untargeted: targeted (specific harmful queries from harmful datasets).
- Digital / physical: digital.
- Adaptive / non-adaptive: STACK is adaptive to the pipeline structure; baseline attacks (Best-of-N, ReNeLLM, PAP) are non-adaptive.

## Trust assumptions
Defender constraints modeled realistically: safeguards must be smaller than the guarded model (latency/cost), and must not over-refuse (thresholds tuned to a fixed, deliberately high 15% refusal rate on benign Llama3Jailbreaks data — favorable to the defender). Harmfulness H approximated by an LLM judge; output-classifier jailbreak strings are stripped before judging to avoid jailbreaking the judge.

## Attack or failure mechanism
STACK breaks the pipeline component-by-component: (1) find a universal jailbreak for the input classifier so the query passes; (2) jailbreak the generative model (PAP) to produce harmful content; (3) make the model prepend/repeat a universal jailbreak string for the output classifier so the harmful response is not flagged. Unlike PRP (defeated by an input classifier) and DUALBREACH (needs direct model access / trained proxy), STACK finds universal jailbreaks for each component and uses only the black-box block signal, so a query carrying both the input-classifier jailbreak and a "repeat the output-classifier jailbreak" instruction defeats input and output filters simultaneously.

## Proposed defense or method
The primary artifact is the open-source pipeline plus the attack; the paper concludes with mitigation recommendations for developers to thwart staged attacks (e.g., addressing the repeat-the-jailbreak channel; recommendations detailed in the paper's conclusion). The contributed few-shot-prompted classifier is itself a defense baseline that reaches 0% ASR on ClearHarm against the three non-adaptive baseline attacks.

## Datasets and benchmarks
- StrongREJECT: 313 harmful queries across illegal goods/services, violence, hate/harassment, disinformation (Souly et al. 2024); used both as data and as the prompted ASR judge.
- ClearHarm: especially harmful, non-dual-use queries designed so any compliant response must contain severely harmful info (Hollinsworth et al. 2025).
- Benign/overrefusal: Llama3Jailbreaks (Bailey et al. 2025) for refusal-rate calibration.

## Evaluation methodology
Pipelines built from open-weight safeguards evaluated against baseline black-box non-adaptive attacks (Best-of-N, ReNeLLM, PAP) on both datasets; thresholds set to a common 15% benign refusal rate. Then STACK evaluated in (a) black-box semi-separable direct attack and (b) white-box→black-box transfer. Success counts only responses judged maximally harmful by the StrongREJECT classifier.

## Metrics
Attack Success Rate (ASR); Refusal Rate (RR) on benign data for overrefusal; computational-resource constraint (safeguards smaller than guarded model).

## Main findings
- Author claim: the Gemma-2 few-shot-prompted classifier ("Gemma2") outperforms all tested open-weight safeguards including ShieldGemma (fine-tuned from the same gemma-2-9b base), reducing baseline-attack ASR to 0% on ClearHarm — i.e., naive evals suggest strong robustness.
- Author claim: black-box STACK reaches 71% ASR on ClearHarm against that few-shot-prompted pipeline, showing the apparent robustness is illusory against staged attacks.
- Author claim: transfer STACK achieves 33% ASR zero-shot against the target pipeline, i.e., staged attacks are feasible with no direct interaction with the target.
- Author claim: many existing pipelines perform poorly even against simple baselines, and are often *more* vulnerable on the more-harmful ClearHarm than on StrongREJECT; PAP is the strongest baseline (attributed to dual-use framing).

## Negative results
PAP (strongest baseline) fails (drops toward 0% ASR) against the few-shot-prompted classifiers on ClearHarm — motivating the need for STACK. This is a reported failure of non-adaptive attacks, used to justify the staged approach.

## Limitations stated by the authors
The 15% benign refusal rate is "impractically high," deliberately favoring the defender; they use output (not transcript) classifiers to avoid ambiguity; they do not use transcript classifiers in this work; results are on a single guarded model (Qwen3-14B) with open-weight safeguards standing in for proprietary pipelines. ## Additional limitations identified during review
_(reviewer synthesis)_
- Open-weight safeguards are a proxy for proprietary constitutional-classifier pipelines; absolute ASRs may not transfer to production Opus/GPT-5 defenses.
- ASR depends on an LLM-as-judge (StrongREJECT classifier); judge calibration bounds the reliability of the "maximally harmful" success criterion.
- The repeat-the-jailbreak channel assumes the pipeline lets model output echo attacker-chosen strings; deployments that constrain or sanitize verbatim repetition may reduce STACK efficacy (untested here).
- Single guarded model; generalization across guarded-model families/sizes not established.

## Design implications
Defense-in-depth for LLMs must be evaluated with attacks designed against the *whole pipeline*, not per-component; component-wise or time-limited human red-teaming can severely overestimate security. Assume attackers can turn the model into a delivery channel for output-classifier jailbreaks (the model can be induced to emit attacker-chosen strings).

## Implementation implications
Break the "model repeats an attacker string that fools the output classifier" pathway (e.g., restrict verbatim echo, classify on hidden/transcript context rather than only the final string, randomize/secure classifier prompts). Do not rely on a single guard model family whose base is shared with the guarded model.

## Evaluation implications
Report ASR under adaptive, staged, and transfer threat models and on non-dual-use catastrophic-misuse datasets (ClearHarm), at a stated benign refusal rate. Track which component blocked (semi-separable signal) because leaking it aids attackers.

## Deployment implications
For agentic settings, the same pipelines guard against prompt injection, tool/API abuse, and LLM-overseer control mechanisms; STACK-style staged bypass implies a single crafted input could pass both input and output guards, enabling policy-violating actions or data leakage. Minimize the block-reason signal exposed to callers.

## Monitoring and incident implications
Log per-component decisions and the presence of "repeat this string" / universal-suffix patterns; alert on outputs containing known classifier-jailbreak signatures; treat repeated per-component probing (semi-separable reconnaissance) as an attack indicator.

## Applicability boundaries
Directly about LLM safeguard/defense-in-depth security — core. Absolute numbers are specific to Qwen3-14B + open-weight guards at 15% RR; treat them as evidence that staged attacks defeat plausible pipelines, not as measurements of specific proprietary systems. Transcript-classifier pipelines were intentionally excluded.
