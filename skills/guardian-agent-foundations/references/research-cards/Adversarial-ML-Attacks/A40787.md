## Research question
Can targeted knowledge manipulation (misinformation / bias injection) via model editing be carried out in Federated Instruction Tuning (FedIT), where a trusted central server controls training and distribution and robust aggregation filters anomalous updates?

## Problem definition
Prior knowledge-manipulation attacks assume the adversary can directly edit and redistribute a model checkpoint. In FedIT, clients only receive server-issued weights, so an attacker must (a) survive dilution by many benign updates and (b) evade robust aggregation. Goal: make the global LLM emit attacker-specified outputs for a target topic across paraphrases, while preserving overall instruction-following utility (stealth).

## System or model being studied
FedIT with N=10 clients (5 sampled/round), LoRA adapters (rank 32, scale 64) on attention + FFN, INT8-quantized base models. Base LLMs: Qwen2.5-3B and Llama3.2-3B (main), plus Qwen2.5-7B and Qwen2.5-14B (scalability). Aggregators include FedAvg, Multi-Krum, Median, Trimmed-Mean, CRFL, RFLBAT, FLAME, SFed, FedSA variants.

## Threat model
- Adversary objective: inject manipulated knowledge (counterfactual misinformation and social bias) so the global model produces attacker-specified responses on a target topic at inference, while preserving utility, evading defenses, and activating across paraphrased queries.
- Adversary knowledge: gray-box — controls a small client subset with full access to their local data/training; does NOT know benign clients' data/updates or server-side config (including which robust aggregation algorithm is used).
- Adversary access: compromised clients (2 of 10; 20% malicious) upload malicious LoRA updates only when selected in a round; no peer-to-peer client communication assumed.
- Adversary capabilities: paraphrase-based editing-dataset construction; partial adapter fine-tuning on the edit set; adaptive per-round clipping of edited parameters based on attack feedback.
- Attacker budget: 2 malicious clients, intermittent participation; standard FedIT round budget.
- Phase: training-time injection (federated tuning) → inference-time activation.
- Targeted / untargeted: targeted (specific knowledge query → specified response).
- Digital / physical: digital.
- Adaptive / non-adaptive: adaptive — clipping threshold ε adjusts using an aggregation indicator/projection coefficient to evade robust aggregators.

## Trust assumptions
Assumes a compromised-client foothold in an otherwise trusted-server FedIT pipeline; assumes edited (clipped) updates staying close to benign values evade norm-clipping and outlier-detection aggregators; assumes paraphrase generalization transfers the edit to diverse query phrasings.

## Attack or failure mechanism
Four stages: (1) Editing Dataset Selection — paraphrase a harmful (x, ŷ) pair into candidate edit sets; select the candidate minimizing convergence steps n_i subject to a generalization-loss constraint L_i ≤ ξ_eval (fast convergence + good generalization, less overfitting/dilution). (2) Adaptive Manipulation — after standard local tuning, partially tune adapter subset ϕ on the edit set with element-wise clipping to bound deviation; an aggregation indicator (projection coefficient p of the manipulation direction δ onto the global-model change) tells whether the edit was incorporated; if p ≤ τ, reduce the clipping bound ε to be stealthier. (3) Model Upload — malicious updates aggregated with benign ones. (4) Attack Activation — benign clients receiving the compromised global model get attacker-specified outputs on paraphrased target queries.

## Proposed defense or method
This is an attack paper. Defenses are the target: eight robust-aggregation algorithms are the evaluated defenses that ShadeEdit evades. Authors also test post-hoc removal by continued clean fine-tuning (a rollback/unlearning style mitigation).

## Datasets and benchmarks
Instruction-tuning data: FinGPT (77K financial sentiment samples), MedAlpaca (34K medical QA). Evaluation benchmarks: financial FPB, FIQA, TFNS; medical MedQA, PubMedQA, MedMCQA. Injected knowledge types: counterfactual misinformation and social bias. Non-IID client split via Dirichlet (α=0.5); 40 local steps/round, AdamW, batch 16, lr 5e-4, cosine annealing.

## Evaluation methodology
Compare ShadeEdit against one data-poisoning baseline and three model-editing baselines under eight robust aggregators; measure manipulation success (ASR) and utility (instruction-following ACC) across models/domains; scalability to 7B/14B; persistence study injecting then continuing 40 rounds of clean-only training.

## Metrics
Attack Success Rate / manipulation success rate (reports average 99.5% across settings); instruction-following accuracy (ACC) on standard benchmarks as the utility/stealth metric; post-removal ASR persistence.

## Main findings
Author claims: ShadeEdit is the first model-editing knowledge-manipulation attack for FedIT; achieves ~99.5% average ASR across eight robust aggregation defenses while preserving instruction-following accuracy; scales to 7B/14B; counterfactual manipulations are largely removable by continued clean fine-tuning (ASR drops >80%), but bias-based manipulations persist strongly (biased knowledge is more compatible with the model's internal representations, resisting removal).

## Negative results
Directly applying existing (centralized) editing methods fails in FedIT due to benign-update dilution and robust-aggregation filtering — the motivating negative result. Counterfactual (but not bias) edits are shown to be partially reversible under clean retraining.

## Limitations stated by the authors
Adversary is deliberately constrained (no server config knowledge, no peer-to-peer, intermittent selection) — framed as realism. Bias persistence is acknowledged as a double-edged finding. A dedicated limitations section was not captured in the extract ("not stated in available extract").

## Additional limitations identified during review
_(reviewer synthesis)_
- Evaluated up to 14B and on two domains; frontier-scale and broader-domain generalization untested.
- Assumes 20% malicious clients — high in some deployments; sensitivity to lower compromise ratios not centered in extract.
- The adaptive clipping relies on an aggregation-indicator signal derived from observing global-model change; visibility of that signal depends on server behavior and may be limited in practice.
- Only aggregation-based defenses are the evaluated countermeasures; provenance/attestation of client updates, differential privacy, or update-signature auditing are not tested against.
- Simulated FL (single-lab) rather than a real federated deployment.

## Design implications
Robust aggregation (norm clipping / outlier detection) is not sufficient to protect a shared LLM's *knowledge integrity*: an adaptive attacker can keep malicious edits within the benign-update envelope. Federated LLM pipelines need integrity/provenance controls on updates, not only anomaly filtering.

## Implementation implications
Defenders should consider signed/attested client updates, per-topic behavioral audits of the global model, and unlearning that targets bias-type edits (shown resistant to naive clean fine-tuning), since utility metrics alone will not reveal the tamper.

## Evaluation implications
Federated-LLM security evaluations must include utility-preserving, defense-adaptive attackers and separately test *bias* vs *counterfactual* persistence; ASR-under-defense and post-removal persistence are both necessary axes.

## Deployment implications
Organizations running FedIT on decentralized private data (finance, medicine cited) risk stealthy misinformation/bias injection that survives robust aggregation and degrades trust without degrading benchmark accuracy — a supply-chain integrity risk for the shared model.

## Monitoring and incident implications
Targeted-topic probing of the global model across paraphrases (red-team canaries) and update-provenance logging are candidate detections; incident response should account for bias edits being hard to remove via standard fine-tuning (may require targeted unlearning/rollback).

## Applicability boundaries
Applies to FedIT / federated LoRA fine-tuning of LLMs with aggregation-based defenses. Should NOT be generalized to centralized training, to non-adaptive attackers, or as evidence that provenance/attestation defenses are bypassable (untested). Adjacent to agent security: model-integrity/supply-chain manipulation transferable to any shared-model agent stack.
