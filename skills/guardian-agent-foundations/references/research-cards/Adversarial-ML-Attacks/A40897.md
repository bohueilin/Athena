## Research question
Can backdoors in generative LLMs be detected in real time, at low cost, using only black-box top-1 token probabilities — overcoming the poor performance and high latency of classification-oriented defenses on the autoregressive, large-output-space setting of LLMs?

## Problem definition
LLM backdoors (embedded via data poisoning / outsourced training) make a model behave normally on clean input but emit an attacker-specified target sequence when a trigger is present, causing misalignment, manipulative content, or harmful code execution in agent systems. Classification-based defenses generalize poorly to LLMs, and output-based detectors need multiple inferences/extra computation (high latency), so a lightweight real-time detector is needed.

## System or model being studied
Generative instruction-tuned LLMs. Victim models: Llama-3.1-8B-Instruct, Qwen2.5-7B-Instruct, Deepseek-7b-chat. ConfGuard is a runtime detector operating on the model's output token-confidence stream.

## Threat model
- Adversary objective: implant a training-time backdoor that makes the model deterministically generate a target sequence when triggered. Two categories: "triggered by attacker" (victim = LLM provider/reputation; can drive agent to harmful actions) and "triggered by user" (common-word triggers spread propaganda/misinformation; victims = end users).
- Adversary knowledge/access: training-time data poisoning (poisoning rate λ, epochs E) — the defense analysis assumes backdoor targets appear far more frequently than clean samples (e.g., 10% poisoning × 3 epochs × 10k samples → target appears 3,000× vs 3× for a clean sample).
- Defender capability: black-box access, only top-1 output probability. Deployable user-side (untrusted provider API) or provider-side (white-box, real-time during inference).
- Defender goal: high True Positive Rate, low False Positive Rate, negligible latency.
- Phase: attack injected at training; detection at inference/deployment.
- Targeted / untargeted: targeted (fixed backdoor target sequence).
- Digital / physical: digital.
- Adaptive / non-adaptive: evaluated against standard (non-adaptive) backdoor attacks; no attacker specifically designed to defeat the confidence signal.

## Trust assumptions
Assumes the defender can observe top-1 token probabilities (available in most commercial APIs' top-k logprobs). Assumes backdoor overfitting produces a distinctive high-confidence generation path. In the provider-side scenario, the provider trusts its own inference stack.

## Attack or failure mechanism (that the defense targets)
"Sequence lock": a backdoored LLM generates its target sequence with abnormally high and consistent top-1 token confidence and no branch points, because the heavily-overfit backdoor target is memorized (linked to membership/memorization effects from Carlini et al. 2021). Benign generation also has high-confidence tokens but includes branch points that break the locked path.

## Proposed defense or method
ConfGuard monitors the stream of top-1 token confidences with a sliding window: increment a counter while consecutive top-1 probabilities exceed threshold P; if the run length reaches threshold L, flag a backdoor sample and stop generation; reset the counter at any low-probability "branch point." Requires only top-1 probabilities and one forward pass (real-time, zero-shot — no external dataset or auxiliary model). Contrasted (Table 1) with ONION (black-box, output), RAP (white-box, full logits), LLMScan (white-box, full logits), Cleangen (black-box, top-1 prob but needs a clean shadow model).

## Datasets and benchmarks
CommonsenseQA (CQA), SocialIQA (SIQA), UltraChat 200k (UC). Attacks (five types): BadNet (rare-word insertion), Syntax (syntactic-structure trigger), Style (Bible/Shakespeare/Poetry style triggers) — plus two additional per "five attack types." Backdoor targets: Script (`wget -q [Trojan Source] -O- | sh`), URL, Web. Baselines compared in experiments: three widely used defenses (ONION, RAP, Cleangen; LLMScan discussed).

## Evaluation methodology
Balanced test sets (equal triggered/clean) to measure TPR and FPR across three models × three datasets × five attacks; sensitivity study over window-length threshold L; separate check on training data to test membership-effect confounding; latency comparison versus baselines. A sample is counted positive only if the output fully contains the backdoor target (not merely the trigger).

## Metrics
True Positive Rate (TPR), False Positive Rate (FPR), and inference latency/overhead.

## Main findings
- Author claim: near-100% TPR with negligible FPR in the vast majority of cases (tables show averages such as ~99.9% TPR / ~0.6% FPR for some settings; per-attack values vary).
- Author claim: real-time detection with almost no additional latency, outperforming ONION/RAP/Cleangen in efficiency and (mostly) effectiveness.
- Author claim: FPR ~0% on training data for the main target, indicating detection keys on backdoor output consistency rather than membership per se.
- Author claim: optimal L is dataset-dependent — ~9 for CQA, ~14 for UC/SIQA; larger L lowers both TPR and FPR.
- Author claim: uniquely handles the "triggered-by-user" scenario since it needs only top-1 probabilities (unlike full-logit methods).

## Negative results
On CQA, TPR begins to decline once L exceeds ~9 while FPR stops improving, so the threshold cannot be pushed arbitrarily high; effectiveness/latency trade-off is dataset-sensitive. Some attack/target/dataset cells show elevated FPR (e.g., Shakespeare-style up to ~21.95% in one Table-5 cell).

## Limitations stated by the authors
Optimal window length L varies across datasets and must be tuned; detection is defined on full-target-containment; some per-setting FPR is non-trivial. (Further detail deferred to the full version.)

## Additional limitations identified during review
_(reviewer synthesis — clearly not author claims)_
- The sequence-lock signal is an evadable heuristic: an adaptive attacker could lower target confidence, inject benign branch points, or use paraphrased/stochastic targets to defeat the confidence-run detector — not evaluated.
- Core assumption is a high poisoning rate / strong overfitting; low-poisoning or few-shot/weight-edited backdoors that don't produce locked high-confidence paths may evade detection.
- "Stop generation on detection" can create availability/false-refusal issues where benign high-confidence outputs (deterministic factual/boilerplate text) trip the detector.
- Evaluated on 7–8B open models and QA/chat datasets; scaling behavior on larger production models and agentic tool-calling contexts is not shown.

## Design implications
A cheap, black-box runtime signal (token-confidence dynamics) can serve as a first-line backdoor tripwire that fits real serving stacks. Backdoor defense for generative models should exploit the autoregressive branch-point structure rather than porting classification-space heuristics.

## Implementation implications
ConfGuard slots into an inference loop as a streaming guard that halts generation on a detected locked sequence, needing only top-1 probabilities — implementable client-side against untrusted providers. Thresholds (P, L) require per-deployment calibration; pair with a fallback/human-review path when generation is halted.

## Evaluation implications
Backdoor-detection evaluations for LLMs should report TPR/FPR under balanced triggered/clean sets, latency overhead, and threshold-sensitivity, and should include adaptive attackers that manipulate output confidence — a gap in the current evaluation.

## Deployment implications
Suits real-time, large-scale LLM serving (low latency, black-box). But because it can halt generation, deployment needs guardrails against false positives on legitimately deterministic outputs, and it should not be treated as coverage against low-overfit or adaptive backdoors.

## Monitoring and incident implications
Provides an inline detection + containment primitive (flag and stop generation) plus a natural audit signal (confidence-run events) for logging suspected backdoor activations; useful as evidence for incident triage of poisoned models.

## Applicability boundaries
_(where these findings should and should NOT be generalized)_
Core to LLM security (training-time backdoors in generative models), with direct relevance to agent systems that could execute backdoor-induced harmful code. The confidence-run heuristic should NOT be assumed effective against adaptive attackers, low-poisoning backdoors, or non-generative/classification settings without re-evaluation. TPR/FPR numbers are specific to the tested 7–8B models, datasets, and non-adaptive attacks.
