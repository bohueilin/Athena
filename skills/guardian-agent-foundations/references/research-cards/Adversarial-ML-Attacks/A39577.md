## Research question
Can a backdoor attack on multivariate time series (MTS) forecasting decouple the trigger from the target pattern in time and across variables — activating the malicious pattern at attacker-chosen delayed, variable-specific positions within the forecast horizon — rather than forcing synchronous, fixed-position activation immediately after the trigger?

## Problem definition
Existing MTS-forecasting backdoors (notably BackTime) enforce strict temporal + dimensional coupling: the target pattern must appear immediately after the trigger and at identical positions across all variables. Real scenarios (traffic, finance, energy) require delayed and asynchronous responses (e.g., congestion 1h later on one road, 30 min earlier on detour roads, 2.5h later near transit hubs). This rigidity limits flexibility and stealth.

## System or model being studied
Downstream MTS forecasting model f_d (any architecture: Transformer/MLP/diffusion/time-series-LLM) trained on a poisoned dataset; a separate surrogate forecasting model f_s selects high-error attack timestamps. Sliding-window input/output pairs (history length h, forecast length f) over X ∈ R^{T×N}.

## Threat model
- Adversary objective: (a) preserve clean-input forecasting accuracy (stealth), (b) on triggered input, produce a predefined target pattern at attacker-specified positions/variables while keeping other dimensions accurate ("controlled manipulation").
- Adversary knowledge: BLACK-BOX w.r.t. the downstream model — no knowledge of its architecture, optimizer, or hyperparameters; but FULL access to the training dataset (data-poisoning threat).
- Adversary access: can modify the training dataset (inject triggers into historical data and target patterns into future data); trigger injection can be physical (e.g., controlling traffic flow) or via manipulating the released/forecast data.
- Adversary capabilities: additive, amplitude-bounded perturbations (‖g‖∞ ≤ Δ^TGR_s, ‖p‖∞ ≤ Δ^PTN_s, budgets proportional to each variable's std) at selected high-error timestamps; per-variable temporal offsets Δt_i^(s).
- Attacker budget: perturbation amplitude bounded per-variable; a subset of timestamps T^ATK poisoned.
- Phase: training (data poisoning) → inference (target activation on triggered input).
- Targeted / untargeted: targeted (specific target pattern at specific positions/variables).
- Digital / physical: both — physical trigger injection (traffic control) or digital data manipulation discussed.
- Adaptive / non-adaptive: standard poisoning; no adaptive defense evasion loop described.

## Trust assumptions
Practitioners train private models on externally provided/public datasets that may be poisoned beforehand — trust in dataset provenance is the exploited assumption. Downstream model internals remain unknown to the attacker.

## Attack or failure mechanism
Poison the clean training set so the model learns trigger→target-pattern association. Trigger injected into history over attacked variables S; target pattern injected asynchronously into the future using per-variable offsets Δt_i^(s). The model, once trained, reproduces the delayed/asynchronous pattern when the trigger appears.

## Proposed defense or method
TDBA (an ATTACK framework) with two core modules:
1. Position-guided trigger generation: a position guidance matrix A_d built from smoothed Gaussian priors centered at each variable's offset provides a differentiable, dimension-aware supervisory signal so the trigger encodes the target pattern's location. Two generator instantiations: GCN-based (adapted from BackTime, with softsign output for stealth) and Inverse-Forecasting generator (generates history triggers by reversing a forecast that embeds the target pattern).
2. Position-aware optimization: a soft-identification weight β(t_i) combining (a) trigger-completeness indicator, (b) target-pattern coverage η(P/t^PTN), and (c) an offset penalty ϕ(Δt)=exp(−λΔt), yielding a loss that focuses optimization on effective backdoor samples and reduces deviation in non-attacked regions.

## Evaluation methodology

## Metrics
- Mpa: attacked-position error (lower = more precise control at target positions ⇒ higher effectiveness).
- Mpc: unaffected-position error (lower = better stealth on non-attacked positions).
Authors report TDBA achieves lowest Mpa while maintaining comparable/lower Mpc vs. baselines (numbers truncated).

## Main findings
- Author claim: TDBA consistently outperforms baselines in effectiveness (precise, delayed, asynchronous target activation) while maintaining good stealth across five real-world datasets.
- Ablation: removing the position guidance matrix (A1) significantly increases both Mpa and Mpc (degrades effectiveness AND stealth), confirming positional information is central; removing position-aware optimization (A2) also degrades performance.

## Design implications
Backdoor triggers can encode WHERE (and in which variable) a malicious pattern activates, not just WHETHER — defenses that assume immediate, synchronous trigger→effect coupling will miss temporally decoupled backdoors. Forecasting pipelines feeding autonomous control (traffic, energy, trading agents) need provenance controls on training data.

## Implementation implications
Position-conditioned trigger generation (Gaussian positional prior + soft-identification weighting) is a reusable recipe; defenders should model delayed activation windows across the full forecast horizon and per variable.

## Evaluation implications
Time-series backdoor evaluation should include delayed/asynchronous activation cases and test against actual detectors; metrics should separate attacked-position control (Mpa) from off-target stealth (Mpc).

## Deployment implications
Systems that consume third-party or public time-series datasets to train forecasters used for decisions (autonomous traffic/energy/financial agents) are exposed; dataset provenance/attestation and forecast-anomaly monitoring are warranted.

## Monitoring and incident implications
Monitor forecasts for implausible cone-shaped/target patterns conditioned on subtle historical perturbations; because activation can be delayed, incident detection must correlate inputs with outputs over long horizons.

## Applicability boundaries
Applies to backdoor/data-poisoning threats against MTS forecasting models (including time-series LLMs as victims). It is an attack, not a defense. Not about LLM prompt/tool-injection directly; adjacent to agent security as a data-supply-chain poisoning threat for forecasting-driven autonomy.
