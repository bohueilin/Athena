## Research question
Can generalization to unseen face-forgery types be improved by mining and retaining the most informative CLIP visual-language residual features into dynamic prototype sets, rather than by relying only on text-prompt quality or on the model's internal feature representation?

## Problem definition
CLIP-based face-forgery detectors focus on text-prompt design and image-text alignment, neglecting subtle image artifacts in regions not covered by text semantics; this limits generalization to unseen forgeries. The task is binary real-vs-forged face classification framed as an out-of-distribution generalization problem across forgery methods and datasets.

## System or model being studied
ResProto-FD, a training/inference framework on frozen CLIP text encoder + fine-tuned ViT-B/16 image encoder. Two modules: (1) Visual-Language Residual Learning (VLRL) — computes a residual feature f_res = f_train − λ·f_text (λ=0.3) to attend to visual cues beyond text semantics, with class-aware log-prior-corrected cross-entropy and a mutual-information regularizer; (2) Gradient-aware Residual Prototypes (GRP) — a dynamic memory that stores per-class prototypes selected by the ℓ2-norm of the loss gradient w.r.t. the residual feature (uncertain/high-risk samples), K-means sub-clustering for the forged class, a time-aware score-decay replacement rule (γ=0.99), capacity 64/class, Top-K=64. Inference classifies via cosine similarity between test features and mixed prototype sets plus the CLIP residual logit.

## Threat model
- Adversary objective: produce forged faces (face-swap, reenactment, entire-face-synthesis, face-editing) that evade detection.

- Adversary access: creates forged media ingested by the detector at inference.
- Adversary capabilities: diverse GAN/diffusion forgery generators (e.g., StyleGAN, Stable Diffusion; six DF40 face-swap methods: SimSwap, InSwap, UniFace, e4s, FaceDancer, FSGAN).

## Trust assumptions
Trusts training face corpus/labels, the frozen CLIP text encoder's semantic space, and the assumption that gradient magnitude on residual features is a good proxy for "informative/uncertain" prototypes worth retaining. Assumes preprocessed cropped-face frames.

## Attack or failure mechanism
Failure being mitigated: detectors that emphasize text-prompt semantic coverage miss subtle image artifacts in semantically-uncovered regions, and static representations fail to represent unknown forgery styles, causing feature drift and poor cross-forgery transfer.

## Proposed defense or method
Learn discriminative residuals decoupled from text semantics (VLRL) and preserve a curated, decaying set of high-gradient real/forged prototypes (GRP) as an explicit reference bank so inference can match unseen forgeries to retained informative exemplars, improving generalization.

## Datasets and benchmarks
Train on FaceForensics++ (c23). Cross-dataset evaluation on Celeb-DF-v2 (CDF), DeepfakeDetection (DFD), DeepFake Detection Challenge (DFDC); frames preprocessed to 256×256. Additionally the DF40 benchmark (40 manipulation methods, incl. six FS methods). Reported baseline comparison set includes Xception, EfficientB4, Face X-ray, F3Net, FFD, SPSL, SRM, CORE, RECCE, UCF, FoCus, PFGDD, LSDA, DiffusionFake, RepDFD, Freqdebias.

## Evaluation methodology
Cross-dataset and cross-forgery frame-level AUC (train on FF++, test on held-out datasets/methods); baselines cited from prior work. Implementation: ViT-B/16, Adam lr 5e-7, wd 1e-6, two RTX 3090, PyTorch 2.5.1; light augmentation (resize-crop, Gaussian blur, random erasing); four K-means sub-centers; ω1=ω2=0.1.

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Fixed prototype capacity (64/class) and decay γ may bottleneck coverage as forgery diversity grows; sensitivity not shown in excerpt.
- Prototype bank is a stored feature memory — a potential poisoning/drift surface if training data are attacker-influenced; not analyzed.
- No adaptive/anti-forensic adversary and no post-processing (compression) robustness in the excerpt (contrast A37553).
- Cross-dataset AUC gains are modest in absolute terms and cited baselines come from prior papers, so comparison conditions may not be perfectly matched.
- Gradient-magnitude prototype selection assumes clean gradients; behavior under label noise is untested.

## Design implications
An explicit, decaying exemplar memory over residual (visual-minus-text) features is a reusable idea for OOD-aware detection. For a verification stack: prototype/memory banks improve unseen-class coverage but introduce a stateful surface (drift, poisoning) that must itself be governed.

## Implementation implications
Memory-bank management (scoring, decay, replacement) adds runtime state; implementers should bound memory, log prototype turnover, and validate that stored prototypes are not attacker-controllable.

## Evaluation implications
Report cross-forgery and cross-dataset AUC plus prototype-bank ablations; add compression/adaptive-attack tests before deployment claims. Ensure baseline numbers are re-run under identical preprocessing when possible.

## Deployment implications
A detection control with residual risk to novel generators and to adversaries who post-process or optimize against it; gate trust decisions, do not treat as authoritative.

## Monitoring and incident implications
Monitor prototype turnover and per-dataset AUC drift as new forgery families appear; treat sudden prototype-bank instability as a data-quality or drift signal.

## Applicability boundaries
Applies to image/frame-level face-forgery detection generalization. Should NOT be generalized to video-temporal detection, adversarial-example robustness, or non-face synthetic media. Adjacent to agent security only via media-authenticity evidence; peripheral to LLM tool-use/prompt-injection concerns.
