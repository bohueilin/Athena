## Research question
Can a source-free domain-adaptation (SFDA) framework perform cross-subject fMRI-to-image brain decoding — adapting to a target subject without accessing source-subject data — while improving modality alignment and reducing the compute cost of high-dimensional CLIP embeddings?

## Problem definition
Brain decoding reconstructs visual stimuli from fMRI. Three obstacles: (1) high across-subject variability limits generalization, and using source-subject data during adaptation raises privacy-leakage risk and storage burden; (2) SoftCLIP-style alignment only matches softmax distributions, not marginal distributions, causing modality misalignment; (3) images and text are aligned to fMRI separately, ignoring their interplay; (4) CLIP embeddings are very high-dimensional, so alignment is costly.

## System or model being studied
An SFDA brain-decoding framework in two phases. Source training: embedder → translator → image/text heads producing predicted CLIP image/text embeddings, aligned with SoftCLIP loss + Maximum Mean Discrepancy (MMD) for marginal-distribution alignment. Target adaptation: uses only source-model parameters (no source data); concatenates predicted image+text embeddings, applies SVD to get unified embeddings, and aligns their distributions with Wasserstein-1 distance; uses DoRA (weight-decomposed LoRA) on the image/text heads to cut tuning cost.

## Trust assumptions
Assumes the source model (parameters) can be shared but the underlying source-subject data cannot/should not be. The privacy benefit is by construction (data minimization: don't access source data), not by any cryptographic or differential-privacy mechanism. No attacker, and no analysis of whether the shared source model itself leaks source-subject information.

## Attack or failure mechanism
No attack. The named risk is privacy leakage from sharing/storing source-subject fMRI (personal information); the method avoids it by never accessing source data during adaptation. This is a design choice, not a demonstrated or defended-against attack.

## Proposed defense or method
Privacy-by-design via SFDA (data minimization). Technical contributions are utility-oriented: MMD marginal alignment, SVD-based unified image+text embedding, Wasserstein-distance distribution alignment, and DoRA for efficiency. No membership-inference, model-inversion, or reconstruction-attack defense is proposed or tested.

## Datasets and benchmarks
Natural Scenes Dataset (NSD): 7-Tesla fMRI from 8 adults viewing COCO images; four fully-scanned subjects used (subj01/02/05/07). Per subject: 8,859 image stimuli / 24,980 fMRI trials (train); 982 stimuli / 2,770 trials (test).

## Main findings
Author claim: the SFDA framework achieves state-of-the-art brain-decoding while (a) not accessing source data during adaptation (privacy/storage benefit), (b) improving modality alignment via MMD + Wasserstein over SoftCLIP-only baselines, and (c) reducing compute via DoRA; t-SNE shows successful cross-subject alignment.

## Negative results
Naive dimensionality reduction (dropping patches/tokens) is noted to sharply drop performance — motivating the SVD/DoRA approach. No adversarial negative results.

## Design implications
For agent/AI security this is a data-minimization case study: source-free adaptation lets a model transfer without moving raw sensitive data — a pattern relevant to privacy-preserving ML on regulated data. But it demonstrates the pattern's utility, not its privacy guarantee; a security design must add measured protections (DP, leakage audits of the shared model) that this paper does not.

## Implementation implications
Sharing a trained source model instead of data still creates a potential exfiltration channel (the model may memorize source-subject signals). Any real deployment would need model-inversion/membership-inference testing before claiming privacy — unaddressed here.

## Evaluation implications
Illustrates the gap between privacy-by-design claims and privacy-by-measurement: the t-SNE "subject-invariant" result is a utility/alignment result, not a privacy-leakage bound. Security evaluations should not treat SFDA as evidence of leakage resistance.

## Deployment implications
Reduces data-storage/data-sharing footprint (a genuine privacy-posture improvement) but leaves the shared-source-model attack surface unevaluated. Biometric-data sensitivity raises the stakes of that gap.
