## Research question
Can a multi-turn jailbreak that transfers *another* (easy-to-jailbreak) model's jailbroken conversation history into
the target model's context exploit LLMs' conversational-coherence bias to induce harmful outputs more effectively and
efficiently than existing single-/multi-turn attacks?

## Problem definition
Modern LLMs resist direct single- and multi-turn jailbreaks; dynamic multi-turn methods are costly (many model
calls) and lose harmful intent over long dialogues; word-masking methods leave detectable placeholder-to-malicious
links. CHASE seeks a cheaper, non-dynamic, fixed-length attack that decouples history generation from the target.

## System or model being studied
CHASE, a black-box multi-turn jailbreak with two phases: History Generation (HG) and History Transfer (HT). Target
LLMs: GPT-3.5, GPT-4, GPT-4o, ChatGLM-4 (closed) and Llama3-70b, Llama3.1-8b, Llama3.2-3b (open). Auxiliary:
Qwen1.5-72b selected empirically as both the MTI (Multi-Turn Input) Generating LLM and the History Generating LLM.

## Threat model
- Adversary objective: elicit harmful/prohibited content from the target LLM.
- Adversary knowledge: black-box (no weights/architecture access) — motivated by realism.
- Adversary access: standard chat interface allowing multi-turn conversation and injected conversation history.
- Adversary capabilities: run a separate easy-to-jailbreak LLM to produce jailbroken histories, then seed the target's
  conversational history with them and issue a fixed follow-up prompt.
- Attacker budget: designed to be low — fixed 8-turn conversations (4 CHASE + 4 History-Generating-LLM turns) and
  fewer computational resources than dynamic baselines (author claim); exact query counts not visible in extract.
- Phase: inference.
- Targeted / untargeted: targeted (specific harmful request), evaluated over harmful-prompt datasets.
- Digital / physical: digital.
- Adaptive / non-adaptive: the injected follow-up prompt is FIXED (non-dynamic w.r.t. the target's replies); it is
  not adaptive to specific target defenses.

## Trust assumptions
Exploits the target LLM's tendency to preserve conversational coherence and to avoid contradicting content it
"believes" it previously produced. Uses GPT-4 Safety Scoring (Qi et al. 2024) to decide whether an HG-phase history
is jailbroken before transfer. Assumes the interface treats supplied history as authentic prior turns.

## Attack or failure mechanism
HG: nest a harmful request in one of three high-coverage scenarios (Scientific Research, Novel Writing, Virtual
Simulation Game); an MTI-Generating LLM (Qwen1.5-72b) produces 4-turn conversation inputs at two obscurity levels
(ambiguous / explicit); 3 scenarios × 2 prompts → 6 MTIs, each run against the History-Generating LLM, yielding up
to 6 candidate conversations; successful ones become "jailbroken histories." HT: transfer one jailbroken history at a
time into the target's context, then append a fixed prompt applying three strategies — Harm Concealment (imply, don't
state, the malicious ask), Rejection Inhibition (forbid refusal), Output Limitation (bar moral/legal disclaimers).
Because the harmful assistant turns now appear to be the target's own history, refusing creates a context
inconsistency the model tends to avoid, so it complies.

## Proposed defense or method
None — this is an offense paper. It surfaces a weakness (history/coherence exploitation) for defenders to address.

## Datasets and benchmarks
AdvBench (520 harmful prompts) and JailbreakBench (100 harmful prompts). Auxiliary datasets used only for MTI/History
LLM selection: WildGuardMix, ToxicChat, RealToxicityPrompts (50 sampled from each). Baselines: single-turn (AttnGCG,
PAIR, LLM-Fuzzer, CodeAttack, DRA) and multi-turn (CoU, CoA, CFA).

## Evaluation methodology
Attack judged successful only if validated as harmful by three evaluators (extract truncates the exact ensemble).
Comparison against 5 single-turn + 3 multi-turn SOTA baselines across 7 target LLMs and 2 datasets, measuring ASR and
resource/efficiency.

## Metrics
Attack Success Rate (majority/triple-judge harmful validation) and efficiency (computational cost / query count).
Exact numeric results are not visible in the extracted text.

## Main findings
(Author claims, abstract-level) CHASE beats SOTA methods in both effectiveness and efficiency in multi-turn jailbreak
scenarios, achieving consistently higher ASR with fewer computational resources across mainstream open and closed
LLMs; it exposes a previously under-examined weakness — extended-dialogue / injected-history coherence exploitation.

## Additional limitations identified during review
_(reviewer synthesis)_
- Effectiveness depends on the availability of an easy-to-jailbreak auxiliary LLM (Qwen1.5-72b here); as such models
  are hardened, HG-phase yield may drop.
- The threat is only realistic where the interface lets an attacker supply multi-turn "assistant" history (API
  message arrays, some chat frontends); pure UIs that don't accept attacker-authored assistant turns limit it — the
  paper does not scope which deployment surfaces are exposed.
- Fixed follow-up prompt is non-adaptive; defenses that detect the specific Rejection-Inhibition/Output-Limitation
  phrasing could blunt it.
- Uses GPT-4 as jailbreak judge, which has known calibration/over/under-flagging issues.
- No defense is proposed or evaluated, so residual risk under existing guardrails (Llama Guard, input filters) is
  only partially characterized.

## Design implications
Conversation history supplied to an LLM/agent must be treated as an **untrusted, integrity-checked asset**, not
assumed authentic. Coherence pressure ("don't contradict your prior turns") is an attack primitive; agent frameworks
should not let injected/forged assistant turns silently become authoritative context.

## Implementation implications
For agents with persistent memory or API-supplied message arrays: authenticate/sign assistant turns, validate that
prior "assistant" content actually originated from the trusted model, and apply safety classification to *history*
(not just the latest user turn). Detect the fixed Rejection-Inhibition / Output-Limitation instruction patterns.

## Evaluation implications
Red-team suites should include cross-model history-transfer and forged-history attacks, and multi-turn coherence
exploits — not only single-turn adversarial suffixes. Measure efficiency (queries), not just ASR.

## Deployment implications
Guardrails that inspect only the final user message are insufficient; run continuous per-turn and whole-context
moderation. Memory-isolation and history-provenance checks reduce exposure. Relevant to OWASP LLM prompt-injection /
excessive-agency risks and to agent memory-poisoning threat models.

## Monitoring and incident implications
Log full conversation history with provenance of each assistant turn; flag conversations whose "assistant" history
contains harmful content the current model never emitted (a signature of transfer attacks). Rejection-Inhibition
phrasing is a monitorable indicator.

## Applicability boundaries
**Core** agent-security relevance (LLM jailbreak / context manipulation). Generalizes to any chat/agent interface
accepting multi-turn history. Does NOT address white-box attacks, tool/agent-to-agent abuse, or provide a defense;
numeric superiority claims are unverified from the truncated extract.
