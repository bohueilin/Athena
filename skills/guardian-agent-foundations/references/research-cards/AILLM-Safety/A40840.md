## Research question
Can a *previous assistant response* injected into the dialogue history act as a contextual primer that steers a target LLM toward policy-violating content — a psychological "priming" vulnerability that current safety alignment overlooks?

## Problem definition
Prior jailbreaks fall into three families with distinct weaknesses: single-turn (modest, brittle ASR), multi-turn (higher ASR but heavy latency/token cost and semantic drift), and static in-context injection (efficient, intent-preserving, but weaker). The paper hypothesizes that fabricated intermediate *responses* placed in the dialogue history are stronger primers than injected user prompts, exploiting the model's preference for coherent continuation of its own apparent prior outputs.

## System or model being studied
Attack framework **Response Attack (RA)** against eight target LLMs: GPT-4.1, GPT-4o, Gemini-2.0-Flash, Gemini-2.5-Flash, Llama-3-8B-Instruct, Llama-3-70B-Instruct, DeepSeek-R1-Distill-Llama-70B, QwQ-32B. Auxiliary attacker model: QwQ-37B-Eureka-Triple-Cubed-abliterated-uncensored (DavidAU).

## Threat model
- Adversary objective: elicit explicit, on-intent harmful content for a given harmful query Q.
- Adversary knowledge: black-box — needs only the ability to supply multi-turn dialogue context (fabricated user+assistant turns) to the target's chat interface/API.
- Adversary access: prompt/context including the dialogue history; formats fake prior turns via chat templates (open models) or API message sequences (proprietary).
- Adversary capabilities: run an uncensored auxiliary LLM to rewrite Q into a benign-seeming Pinit, generate a mildly-harmful injected response Rharm (DRI or SRI), and craft a trigger prompt Ptrig.
- Attacker budget: author claim — a single interaction with the target after constructing the priming dialogue (high efficiency).
- Phase: inference / deployment.
- Targeted / untargeted: targeted (specific harmful behaviors from HarmBench).
- Digital / physical: digital.
- Adaptive / non-adaptive: the attack construction is fixed per query (auxiliary-model-driven), and is additionally evaluated against several representative defenses for robustness.

## Trust assumptions
Assumes the target accepts caller-supplied conversation history and treats injected "assistant" turns as its own prior output (no cryptographic binding of history to actual model generations). Assumes availability of an uncensored auxiliary model to produce the mildly-harmful primer and trigger.

## Attack or failure mechanism
Contextual priming: an injected intermediate response biases subsequent generation. Pipeline (Figure 2): (1) **Initial Prompt Crafting** — auxiliary model πaux rewrites Q into a mildly-harmful Pinit using strategies (academic framing, defensive-security, fiction, historical case), preserving intent/keywords. (2) **Harmful Response Injection** — two modes: **DRI (Direct Response Injection)** where πaux returns a fully elaborated harmful reply Rharm (no suffix), and **SRI (Scaffolding Response Injection)** where a suffix instruction yields only a high-level outline the target is later asked to fill in. (3) **Trigger Prompt Construction** — using Q + (Pinit, Rharm) + templates, build Ptrig (DRI strategies: seeking alternatives, conditional variations, challenging effectiveness; SRI strategies: requesting elaboration / complete process / practical examples). (4) **Attack Execution** — assemble Datk = {Pinit, Rharm, Ptrig} as prior user/assistant turns + final user request; submit to πtgt.

## Proposed defense or method
None — offensive contribution. The authors instead evaluate RA against several representative defense methods to test robustness (results in extracted table/appendix).

## Datasets and benchmarks
- Main: HarmBench (Mazeika et al. 2024).
- Additional (appendix): AdvBench-50 (Chao et al. 2023), JailbreakBench (Chao et al. 2024).

## Evaluation methodology
Attack RA-DRI and RA-SRI vs. nine baselines spanning single-turn (GCG, PAIR, CipherChat, CodeAttack, ReNeLLM, FlipAttack), multi-turn (Crescendo, ActorAttack), and in-context (Many-shot) across eight LLMs. Success judged by GPT-4o judge (score 1–5; success only if score = 5); robustness cross-checked with MD-Judge and Llama-Guard-3-8B. Target/judge temperature 0; auxiliary temperature 1.

## Metrics
- Attack Success Rate (ASR, %), strict (judge score = 5).
- Table 1 averages across the eight models: RA-DRI 94.8%, RA-SRI 89.1%, best baseline ActorAttack 89.1 / Crescendo lower; RA-DRI is highest average. Author claim: RA achieves >10% higher ASR than the nine baselines.
- Per-model RA-DRI reaches 94–96.5% on Gemini-2.5-Flash, GPT-4o, Llama-3-70B, etc.

## Main findings
- Author claim: RA consistently and significantly outperforms nine leading jailbreak baselines across eight SOTA LLMs, with the injected intermediate response being the decisive factor (ablations attribute success to the primer).
- RA preserves stealth (coherent dialogue), efficiency (single target interaction), and originality/fidelity to the harmful intent.
- DRI (full harmful primer → ask for alternatives) outperforms SRI (outline primer → ask to complete) on average.

## Negative results
- SRI underperforms DRI; some models (e.g., GPT-4.1) show lower RA ASR (RA-SRI 62.9, RA-DRI 69.8) than the highest-scoring targets, indicating variation by model. GCG/FlipAttack fail (0 or near-0) on several models, but that concerns baselines, not RA.

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Depends on an uncensored auxiliary model to fabricate the harmful primer; without it the pipeline degrades. Ethical/dual-use: publishes an operational, high-ASR context-injection recipe; no mitigation proposed beyond noting defenses were tested.
- ASR relies primarily on a GPT-4o judge (strict score=5); although MD-Judge/Llama-Guard cross-checks are mentioned, judge-induced bias remains a confound.
- The core enabler — targets trusting caller-supplied "assistant" history — is a property of current chat APIs; the paper does not quantify RA against systems that authenticate/attest conversation provenance.
- Main results are on HarmBench; breadth across harm categories and languages is limited in the extracted text.

## Design implications
Safety alignment must treat *dialogue history* — including apparent prior assistant turns — as untrusted, adversarially controllable context, not as trustworthy self-generated content. Coherence pressure ("continue your own prior answer") is an exploitable alignment gap.

## Implementation implications
Chat serving layers should distinguish model-generated turns from caller-supplied history (e.g., signed/attested transcript, server-side session state) so injected assistant messages cannot masquerade as genuine prior outputs. Guardrails should re-screen the *entire* assembled context, especially prior-assistant content, before generating.

## Evaluation implications
Jailbreak benchmarks should include response-priming / history-injection attacks and report efficiency (turns/queries). Use multiple judges and strict criteria; single-turn robustness does not imply history-injection robustness.

## Deployment implications
Any deployment that accepts client-provided conversation history (common in stateless chat APIs and agent frameworks) is exposed; server-authoritative history and context-level content filtering materially raise attack cost.

## Monitoring and incident implications
Detect anomalies where "assistant" turns in submitted history contain harmful scaffolding/outlines followed by short elaboration triggers ("expand this outline", "what are other methods"). This DRI/SRI signature is a candidate detection pattern for logging and blocking.

## Applicability boundaries
Applies to multi-turn text LLM chat interfaces that accept caller-supplied history. Does NOT cover multimodal inputs, white-box optimization, or settings with server-authoritative, attested conversation state. ASR figures are specific to the eight targets, HarmBench, and the judge configuration used.
