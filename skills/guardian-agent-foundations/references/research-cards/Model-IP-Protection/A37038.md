## Research question
Can a membership inference attack (MIA) tailored to the formal syntax of programming languages more reliably detect whether specific code samples were included in an LLM's pretraining data — supporting copyright/transparency/accountability auditing — than text-based MIAs that treat code as plain text?

## Problem definition
Open-source code carries usage obligations (e.g., copyleft/GPL); using it in LLM pretraining raises legal/ethical concerns and emerging litigation. Detecting pretraining membership is critical for transparency and copyright compliance. Existing MIAs treat all code tokens equally; many require shadow/reference models (expensive, and pretraining data is often unavailable, especially for commercial LLMs), and general-text MIAs on LLMs perform only marginally better than random (Duan et al. 2024). Existing code MIA benchmarks use synthetic/assumed members/non-members, giving unreliable ground truth.

## System or model being studied
Reference-free, token-probability-based MIA against code LLMs (four evaluated models; GPT-Neo/GPT-J/StableLM families referenced in citations). SynPrune leverages the LLM's own per-token predicted probabilities (from logits) plus Python's Abstract Syntax Tree (via the `ast` module).

## Threat model
- Adversary objective (auditor's perspective): infer whether a given code function was a member of the LLM's pretraining corpus (to surface unauthorized use of copyrighted/licensed code).
- Adversary knowledge: black-box-ish — needs token-level output probabilities/logits; no shadow model, no access to pretraining data required.
- Adversary access: query the model to obtain per-token probabilities for a candidate function.
- Adversary capabilities: tokenize, decompose sub-tokens, parse the AST, prune syntactically-required consequent tokens, compute a pruned membership score.
- Attacker budget: low relative to shadow/surrogate-model MIAs (no auxiliary model training).
- Phase: pretraining (the target ingestion event) probed at inference (querying the trained model).
- Targeted / untargeted: targeted membership decision per candidate function.
- Digital / physical: digital.
- Adaptive / non-adaptive: static detector; not evaluated against a vendor actively evading membership inference.

## Trust assumptions
The (mis)using party is the LLM vendor that may have trained on copyrighted code without authorization. The auditor trusts that syntactically-mandated tokens carry no authorship signal and can be excluded, and that the benchmark's members (Pile) truly appear in training while non-members (post-cutoff sources) do not.

## Attack or failure mechanism
LLMs memorize training data (overfitting), so members tend to receive higher token probabilities. But many code tokens are syntactically forced (e.g., closing brackets/parentheses, `:` after compound statements, `self`, indentation), inflating scores regardless of membership and diluting the authorship signal that MIA relies on.

## Proposed defense or method
SynPrune — a syntax-pruned MIA for code. It (1) tokenizes and decomposes sub-tokens to align with 47 hand-curated Python syntax conventions (from the Python 3.11 Language Reference, categorized into data model, expressions, single statements, compound statements); each convention is a ⟨condition, consequence⟩ tuple; (2) prunes tokens whose sub-tokens all match syntactically-required "consequent" tokens, validated against the AST hierarchy (label ℓ(x)∈{0,1}); (3) computes the Syntax-Pruned MIA Probability SPP(x) = −(1/|X1|) Σ log p(x_i) over retained tokens X1, thresholded at ε to decide membership. Used as a transparency/attribution (IP-protection) tool, not for exploitation.

## Datasets and benchmarks
A newly constructed benchmark of authentic, verifiable Python functions: Members sampled from The Pile (widely used in LLM pretraining); Non-members collected from sources published after the models' release cut-off dates (guaranteeing non-membership). Table 2: Members 1,000 functions (avg 14.03 LOC); Non-members 1,000 functions across 214 files (avg 25.34 LOC). Contrasted with WikiMIA/MIMIR (general text) and CodeXGLUE-based prior benchmarks (synthetic/assumed labels).

## Evaluation methodology
Compare SynPrune vs state-of-the-art MIA baselines (e.g., MIN-K% prob and others) across 4 models and 3 member/non-member ratios; robustness analysis across varying function lengths; ablation across the four syntax-convention categories.

## Metrics
AUROC (primary); membership decision via threshold ε; evaluation across ratios and function-length buckets.

## Main findings
- Author-reported: SynPrune consistently outperforms SOTA MIA techniques, with an average AUROC improvement of 15.4% across four models and three member/non-member ratios.
- SynPrune remains robust across varying function lengths.
- Ablations show contributions from each of the four syntax-convention categories.
- The authentic member/non-member benchmark provides reliable ground truth often absent in prior code-MIA work.

## Negative results
Consistent with prior literature (Duan et al. 2024), unpruned/text-based MIAs on LLMs perform only marginally better than random; the paper's gains come from removing syntactically-forced tokens. (No explicit case where SynPrune underperforms is reported in the extracted text.)

## Limitations stated by the authors
Scoped to research/copyright-risk evaluation, not exploitation; responsible-disclosure framing. Syntax conventions were manually curated for Python only (47 conventions from the Python reference), with a third author resolving disagreements.

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Python-only; the 47 conventions and AST pruning do not transfer to other languages without re-derivation.
- Requires token-level probabilities/logits — unavailable from many closed commercial APIs, limiting real-world copyright auditing of the very vendors of concern.
- MIA membership signals remain fuzzy at scale; AUROC gains are relative and may not translate to legally decisive per-sample attribution.
- Benchmark members from The Pile assume actual inclusion in each evaluated model's training; non-membership relies on cut-off dating, which can be imperfect (data contamination/leakage).
- No adaptive-vendor evaluation (e.g., deduplication, canary suppression, or MIA-aware training).

## Design implications
For model-IP/provenance auditing, exploiting domain structure (formal grammar) sharpens membership signals: authorship-bearing tokens should be weighted over grammar-forced tokens. This principle generalizes to other structured modalities (markup, config, other programming languages).

## Implementation implications
A practical copyright/pretraining-data auditor can be built from token probabilities + AST pruning without shadow models — cheaper and more deployable than surrogate-model MIAs — provided the target exposes logits/probabilities.

## Evaluation implications
Code-MIA evaluations should use authentic, cut-off-dated member/non-member sets (not synthetic labels) and report AUROC at low FPR and across ratios/lengths; syntax pruning is a strong baseline going forward.

## Deployment implications
Supports transparency/accountability and copyright-compliance workflows (e.g., IP owners probing whether their licensed code was used). Effectiveness is gated by API access to token probabilities; closed models may resist auditing.

## Monitoring and incident implications
Provides an evidence-generating detector for unauthorized training-data use (audit_records / provenance). Results are probabilistic and should feed governance/legal review rather than serve as standalone proof.

## Applicability boundaries
Applies to detecting membership of Python code in LLM pretraining for copyright/transparency purposes. Should NOT be generalized to natural-language membership, other programming languages without re-derived conventions, or to closed APIs that withhold token probabilities. Adjacent to agent security (touches training_data and ip assets) but not an agent/tool-runtime method.

## Evidence strength
Moderate — a principled, cheaper detector with a new authentic benchmark, multi-model/multi-ratio evaluation, and ablations (author-reported +15.4% AUROC); tempered by Python-only scope, dependence on token probabilities, the inherently fuzzy MIA signal at scale, and no adaptive-vendor testing.

## Confidence notes
The +15.4% average AUROC is author-reported. The core insight (prune syntactically-forced tokens) is well-motivated and likely robust within Python; cross-language and closed-API generality are the main open questions.
