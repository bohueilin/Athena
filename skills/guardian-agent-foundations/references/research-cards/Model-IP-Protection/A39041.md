## Research question
Is the "box-free" model-watermarking design — which encapsulates a generator (GNet) and a hiding network (HNet) inside a single black-box operation network (ONet) so only marked outputs are released — actually secure, or can an adversary with only input/output access reverse-engineer it to remove the watermark and recover the unmarked generator outputs?

## Problem definition
Box-free watermarking protects image-to-image generative model IP by embedding a watermark into the released outputs (handling high-entropy image outputs, extractable solely from outputs). GNet's clean output bi is never released; users see only the marked b'i. The paper reveals a vulnerability: query-based reverse engineering can leak the private bi and strip the watermark, enabling watermark-free surrogate training. This is an **attack / red-team paper** against box-free IP watermarking.

## System or model being studied
- Victim defenses: two SOTA box-free watermarking schemes — VWu (Wu et al. 2020) and VZhang (Zhang et al. 2024, an improved version of Zhang et al. 2021 with structure-consistency robustness), on image deraining and Stable-Diffusion-based image editing.
- Proposed attacks (two):
  1. Inverse HNet attack: train HNet⁻¹ (an inversion network) from curated (b'j, bj) pairs to map marked→unmarked; simple but degrades image quality.
  2. Forward HNet attack: exploit the additive-equivalent property b'i = bi + δ'bi (first-order Taylor expansion of HNet around δ=0), train a forward surrogate SNet≈HNet, then estimate the unmarked image via b̂i = ai − (SNet(ai) − b'i). Better image-quality preservation.
- Both rely on crafting queries bj that satisfy GNet(bj)≈bj (approximate identity), bypassing GNet to expose HNet's watermarking behavior. Also proposes a query-screener API defense.

## Threat model
- Adversary objective: remove the watermark from ONet outputs and recover the unmarked GNet output bi, enabling watermark-free surrogate model training and IP theft.
- Adversary knowledge: black-box — only the input ai and the marked output b'i are observable; ENet (extraction) and intermediate bi are inaccessible. ONet functionality (task) is publicly known; HNet architecture is unknown.
- Adversary access: query access to the deployed cloud ONet API with chosen inputs.
- Adversary capabilities: craft identity-inducing queries (e.g., rain-free images for a deraining GNet; masked images for a generation GNet), collect (bj, b'j) pairs, train surrogate networks.
- Attacker budget: a bounded number of queries (paper states within an acceptable range to train HNet⁻¹/SNet; 6,000 image pairs available per side in the dataset split).
- Phase: inference / deployment (query-time, post-deployment).
- Targeted / untargeted: targeted removal of the specific watermark.
- Digital / physical: digital.
- Adaptive / non-adaptive: non-adaptive on the defender side (victim schemes fixed); the attack itself is a tailored, structure-exploiting strategy.

## Trust assumptions
Assumes box-free defenders publish only marked outputs and treat the black-box encapsulation as the security boundary. Assumes the watermark embedding is effectively additive (residual δ'bi = b'i − bi still carries the extractable watermark, verified via ENet(δ'bi)=δ). Assumes the attacker can find inputs that make GNet act as near-identity.

## Attack or failure mechanism
Because GNet and HNet are coupled only through the unobservable bi, the attacker breaks the coupling by querying with bj such that GNet(bj)≈bj, so ONet(bj)≈HNet(bj,δ)=b'j — directly exposing HNet's mapping. The additive equivalence (Eqs. 9–11) shows the watermark acts as an additive latent residual; the residual retains extractable watermark but loses most semantic content. Using the surrogate SNet of the forward HNet and the known ai, b'i, the attacker estimates bi (Eq. 16) with all quantities known. An ablation shows bypassing GNet is necessary: training on (ai, b'i) pairs without the identity trick fails (HNet⁻¹ degrades quality; forward HNet fails to remove the mark).

## Proposed defense or method
The paper's contribution is offensive, but it discusses a query screener deployed at the API to detect the specially curated identity-inducing queries and defend against these attacks (recommended, high-level; effectiveness not deeply benchmarked in the extracted text).

## Datasets and benchmarks
- Deraining: PASCAL VOC (Everingham et al. 2010) with algorithmically generated raindrop noise — 12,000 images (6,000 noised + 6,000 derained), split evenly for victim training and attack.
- Image generation/editing: 12,000 Stable-Diffusion-generated images, split evenly. All images 256×256 RGB.
- Baselines compared: JPEG-20/50%, AWGN-20/30 dB, Lattice (interval 2/8), WEvade-B-Q, Regeneration-VAE, Regeneration-Diff.

## Evaluation methodology
Attack success and fidelity measured against VWu and VZhang for both tasks. Fidelity of watermark-removed b̂i vs unknown ground-truth bi via PSNR and MS-SSIM. Removal success rate SRRemove = 1 − SRExtract, where an extraction is "successful" if normalized correlation between ENet output and ground-truth watermark δ > 0.96. Includes ablation on the need to bypass GNet and verification of the additive approximation δ'ai ≈ δ'bi.

## Metrics
- PSNR (dB), MS-SSIM (image quality of removed vs ground truth).
- Correlation (watermark match).
- SRRemove (watermark removal success rate).
- Headline author claims: 100% removal success rate with highest PSNR up to 34.69 dB, substantially outperforming prior removal attacks (JPEG, AWGN, Lattice, WEvade, Regeneration).

## Main findings
- Both proposed attacks achieve 100% (or near-100%) removal success on VWu and VZhang for deraining and generation, while preserving image quality far better than baselines (e.g., Forward HNet reaches PSNR 34.69 dB on VZhang deraining).
- Forward HNet generally beats Inverse HNet on image quality (leverages additive property to avoid learning a hard inverse).
- The additive-equivalence hypothesis is quantitatively verified (δ'ai ≈ δ'bi; ENet extracts watermark from the residual).
- Ablation: bypassing GNet is essential; without the identity-query trick, both attacks fail (either quality collapse or no removal).
- Some baselines that remove watermarks (e.g., high-noise AWGN, Lattice-Interval8) do so only at severe quality cost, unlike the proposed attacks.

## Negative results
- Inverse HNet removes watermarks but with inferior image quality (motivating the second attack) — attributed to the difficulty of learning an optimal inverse of a highly non-linear HNet with unknown architecture and shifting data distribution.
- Attacking VWu leaves some dispersed residual noise dots (qualitative imperfection).

## Limitations stated by the authors
Authors note the necessity of API-side detection as a countermeasure and acknowledge the inverse attack's quality limitation. They frame the work as revealing a vulnerability that needs "more effective countermeasures." (No dedicated itemized limitations section in the extracted text.)

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Only two victim watermarking schemes and two tasks (deraining, SD editing) are evaluated; generalization to other box-free schemes (e.g., discriminator-based ownership verification, structure-consistency variants) is asserted but not exhaustively shown.
- The additive-equivalence exploitation depends on the first-order Taylor approximation being accurate; strongly non-additive/non-linear embedding could weaken the forward attack.
- The proposed query-screener defense is discussed but not rigorously evaluated (no adaptive attacker that varies query statistics to evade the screener).
- Success requires the attacker to construct near-identity inputs for the specific GNet task; tasks where identity-inducing inputs are hard to craft may resist the attack.
- Ground-truth bi is unknown in a real deployment; PSNR-vs-bi is measured in a controlled setup where the authors trained the victim, which is favorable to reproducibility but not to real-world unknowns.

## Design implications
Encapsulating a generator and a watermark-hiding network in one black box does NOT make the watermark secure: if the watermark embedding is (approximately) additive and the generator can be induced into near-identity behavior, both the mark and the private clean output are recoverable from input/output access alone. Box-free IP protection should avoid additive-separable marks and should not assume the black box hides the intermediate clean output.

## Implementation implications
API-level defenses (query screening / anomaly detection on suspicious near-identity inputs, rate limiting) are necessary complements to the watermark itself; ownership verification should be resilient to surrogate-model training on de-watermarked outputs.

## Evaluation implications
Robustness claims for box-free watermarking must include query-based reverse-engineering adversaries with task-aware identity queries, not only signal-processing/regeneration attacks; reporting SRRemove alongside fidelity (PSNR/MS-SSIM) against the true clean output is the right bar.

## Deployment implications
MLaaS providers using box-free watermarking for image-to-image model IP are exposed to watermark stripping plus clean-output leakage, which further enables watermark-free model extraction. Deploy query monitoring, limit high-throughput/near-identity query patterns, and treat the watermark as one layer among access control and legal provenance.

## Monitoring and incident implications
Unlike offline asset purification, this attack is query-driven, so provider-side telemetry (input distribution monitoring, per-account query auditing) can surface the identity-query signature — the paper's suggested screener — making logging/telemetry a genuine detection surface here.

## Applicability boundaries
Specific to box-free watermarking of image-to-image generative models exposed as query APIs. The additive-equivalence and identity-query insights transfer within image-generation IP protection but not to text/LLM watermarking or agent-action provenance. Agent-security relevance is **adjacent**: it demonstrates that black-box encapsulation is not a security boundary and that query APIs leak protected intermediate state — a general lesson for any agent/tool that exposes a wrapped model behind an API.
