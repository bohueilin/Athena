## Research question
Can an LLM text watermark simultaneously (a) preserve generation fluency, (b) support both zero-bit attribution (is this AI-generated?) and multi-bit provenance payloads (which model/instance?), and (c) remain robust to rewriting/paraphrasing — without external synonym dictionaries, hashing tricks, or prompt engineering?

## Problem definition
Conventional logit-based (green-list) watermarks (Kirchenbauer et al. 2023) pseudo-randomly split the vocabulary into green/red lists and boost green logits. Random splitting can exclude the highest-probability token, eroding fluency and lexical diversity. Prior fixes (WatME lexical-redundancy clusters via WordNet/LLM prompting; LSH over embeddings) depend on external resources and are brittle (dictionary coverage, polysemy, prompt sensitivity, hash collisions, semantic drift). Most schemes are zero-bit only, lacking richer payloads needed for provenance tracing (e.g., tracking leaked fine-tuning data or identifying which model instance produced disinformation). Regulatory motivation: EU AI Act disclosure obligations (expected 2026), SynthID-Text, OpenAI's internal detector.

## System or model being studied
WaterMod (Watermarking via Token-rank Modular Arithmetic): a decoding-time logit-biasing watermark. At each step the vocabulary is sorted in descending model probability; ranks are partitioned by residue class rank mod k. Zero-bit (k=2): an entropy-adaptive gate chooses even- or odd-parity ranks as the green list (p_odd = (H_t/H_max)^{H_scale}, selected via a key-derived uniform u), then a fixed bias δ is added to green logits. Because the top-2 ranks fall in different parities, at least one high-probability token remains available. Multi-bit (k>2): a PRF permutes payload digits; the previous token's hash selects a digit position p; the payload digit d = m[p] selects the residue class rank mod k = d whose logits are biased, embedding one base-k digit (log2 k bits) per step. Detection uses a z-score over green-token counts (binomial null; ε=0.5 for k=2, p0=1/k for k>2); multi-bit recovery uses per-position majority vote over color tallies (repeated observations act as error correction).

## Threat model
- Adversary objective: Remove/erase the watermark (evade detection) while preserving text meaning; or defeat provenance tracing.
- Adversary knowledge: Not explicitly formalized; the evaluated attack is text rewriting/paraphrasing (implicitly does not know the secret key). Detection requires the secret key K and access to the generating model's logits (green list is reconstructed at detection via re-running the model).
- Adversary access: Post-generation text edits (rewriting/paraphrase attacks).
- Adversary capabilities: Rewriting/paraphrasing of generated text; the paper argues most rank-adjacent alternatives retain their intended color so the mark survives.
- Attacker budget: Not quantified.
- Phase (training / inference / deployment): Inference (decode-time embedding) and deployment (post-hoc detection).
- Targeted / untargeted: Watermark removal is untargeted evasion.
- Digital / physical: Digital (text).
- Adaptive / non-adaptive: Non-adaptive with respect to the watermark algorithm (paraphrasing attacks are generic rewriting, not key-aware or scheme-aware optimization).

## Trust assumptions
- Detector must possess the secret key K and be able to recompute the model's per-step logits (i.e., reconstruct the probability-sorted ranks and the entropy gate). This implies detection-time access to the same model — a strong assumption for third-party verification.
- Assumes the model's probability ranking of tokens is a meaningful proxy for semantic interchangeability ("adjacent ranks are contextually similar").
- Assumes the generator honestly applies the bias; spoofing/forgery of the watermark by an adversary is not the focus.

## Attack or failure mechanism
Failure mode addressed: fluency degradation when the random green list excludes the top token. WaterMod's residue-class partition deliberately spreads near-synonyms (rank-adjacent tokens) across color classes so each class retains a high-probability candidate. Attack studied: strong rewriting/paraphrasing — the paper argues that because many high-rank tokens remain unreplaced, most rank-adjacent alternatives keep their color and the watermark survives.

## Proposed defense or method
Probability-ranked palette + modular coloring (rank mod k). Zero-bit: entropy-driven parity gate (H_scale controls how sharply p_odd rises with entropy, protecting fluency in low-entropy contexts) + fixed logit bias δ on the selected parity; z-score detection with null proportion ε=0.5. Multi-bit: k-residue color partition, PRF-permuted payload positions, per-step base-k digit embedding, majority-vote recovery + z-score (null p0=1/k). Single hyperparameter k moves the scheme from binary attribution to log2 k bits/step. No synonym dictionaries, hashing, or prompt engineering required — builds only on the model's own probabilities.

## Datasets and benchmarks
- Natural-language continuation: C4 (news-like subset), 500 sampled instances (simulating fake-news continuation).
- Mathematical reasoning: GSM8K, 1,319 test instances (chain-of-thought).
- Code generation: MBPP+, 378 problems (~100 test cases each; functional correctness via pass@1).
- Baseline for multi-bit: MPAC (state-of-the-art multi-bit watermark). Models referenced include Qwen2.5 (per references). These three domains span differing entropy regimes (math reasoning tends to be low-entropy).

## Evaluation methodology
Compare detection power and generation quality in both zero-bit and multi-bit settings across the three domains; multi-bit compared head-to-head with MPAC on quality (perplexity, accuracy, pass@1) and detectability (AUROC). Robustness assessed under rewriting/paraphrasing attacks. ROC/AUROC obtained by varying the z-score threshold τ.

## Metrics
- Detection: z-score, AUROC (area under ROC).
- Quality: perplexity (C4), accuracy (GSM8K), pass@1 (MBPP+).
- Payload recovery: per-position majority-vote digit recovery (multi-bit).

## Main findings
- (Author claim) WaterMod attains strong watermark detection while maintaining generation quality in both zero-bit and multi-bit settings, across NLG, math reasoning, and code.
- (Author claim, multi-bit vs MPAC) On C4, WaterMod slightly improves perplexity and achieves higher AUROC. On GSM8K, accuracy improves by 26.94% while exceeding MPAC's detectability. On MBPP+, AUROC 98.29 vs MPAC 48.40 (a 103.07% relative improvement) and pass@1 improves by 27.18% over MPAC — indicating effectiveness even in low-entropy, syntactically rigid code.
- (Author claim) Under strong rewriting attacks, near-perfect detection is maintained because rank-adjacent alternatives largely retain their intended color.

## Additional limitations identified during review
_(reviewer synthesis — clearly not author claims)_
- **Detection requires model access + secret key**: reconstructing the green list needs the same model's per-step logits at detection time, limiting third-party/black-box verification (a practical deployment burden the extracted text does not resolve).
- **Non-adaptive robustness only**: attacks tested are generic paraphrasing; the paper does not evaluate key-recovery, scheme-aware, or optimization-based removal/spoofing (e.g., emoji/format attacks, back-translation loops, or an adversary that deliberately targets top-2-parity tokens). Robustness claims should be read as "against the tested rewriting threat model."
- **Spoofing/forgery not addressed**: an adversary planting a watermark to falsely attribute content is out of scope.
- **Fixed δ / entropy assumptions**: fluency safeguard relies on the model's probability ranking being a good semantic-interchangeability proxy; degenerate distributions may weaken this.
- Extracted text truncates the full experimental tables (only multi-bit vs MPAC and qualitative rewriting-robustness statements are visible).

## Design implications
- Rank-based (probability-sorted) partitioning is a clean way to guarantee a high-probability token in the green set at every step, decoupling watermark placement from external lexical resources — a reusable principle for provenance marking of agent/LLM outputs.
- The single-parameter k unification (attribution ↔ multi-bit payload) fits provenance systems that must scale from "is this AI?" to "which model instance / which licensed dataset."

## Implementation implications
- Embedding is a lightweight per-step logit transform (sort ranks, compute entropy gate, add δ to a residue class) — deployable inside a decoding loop with minimal overhead.
- Multi-bit payloads enable instance/tenant-level provenance; error correction comes for free via repeated per-position observations + majority vote.

## Evaluation implications
- Watermark evaluations should span entropy regimes (code/math are low-entropy stress tests where many green-list schemes collapse — WaterMod's largest gains are exactly there).
- Report AUROC and quality jointly; a watermark's value is the detectability-at-fixed-quality frontier.

## Deployment implications
- Provenance/disclosure use cases (EU AI Act 2026 alignment) are the intended fit. Deployers must plan for detection-time model+key access, and treat robustness claims as scoped to non-adaptive rewriting.
- For agent systems, decode-time watermarking can tag agent-generated text for downstream attribution and misuse tracing.

## Monitoring and incident implications
- Multi-bit payloads support tracing "which model instance produced this disinformation" and "was leaked fine-tuning data used" — directly useful for incident attribution and evidence-logging, subject to key custody.

## Applicability boundaries
_(where these findings should and should NOT be generalized)_
- **Core to agent/LLM security** (output provenance/attribution). Applies to autoregressive text generation where the defender controls decoding and holds the key. Does NOT provide robustness against key-aware/adaptive removal or spoofing, and does NOT extend to non-text modalities. Detection assumes access to the generating model's logits — not a black-box, model-agnostic detector.
