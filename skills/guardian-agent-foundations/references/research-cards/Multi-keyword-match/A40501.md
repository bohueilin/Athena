## Research question
Can LLM event-reasoning performance be improved without relying on a curated, predefined schema library, by automatically extracting and predicting event schemas at inference time?

## Problem definition
Two core event-reasoning tasks: Contextual Event Classification (CEC — infer an event given a query event and relation) and Contextual Relation Reasoning (CRR — infer the semantic relation between two events), each at instance-level and schema-level, over six relation types {Causes, IsResult, Before, After, IsSubevent, HasSubevent}. Prior schema-guided methods depend on curated schema libraries, hurting scalability and lightweight deployment.

## System or model being studied
SGER, a three-stage plug-and-play framework: (1) Schema Extractor (BART-large seq2seq) abstracting concrete events into event types; (2) Schema Predictor (Llama3.2-3B fine-tuned with LoRA, rank 16, scaling 32, contrastive learning with negative samples) predicting reference event types/relations; (3) Event Reasoner integrating history + predicted schema into prompt templates fed to a downstream LLM (GPT-4o, GPT-3.5, and open-source 3B–7B models).

## Trust assumptions
The framework trusts the training data (EV2 instance/schema splits), the base models, and the prompt pipeline. No adversarial or integrity threat to inputs, schemas, or model outputs is considered.

## Attack or failure mechanism
Not a security failure. The addressed failure is functional: LLMs weakly model explicit event structure, degrading event reasoning; predefined schema libraries limit scalability.

## Proposed defense or method
Decouple event understanding from reasoning via a schema-abstraction layer. Extractor maps instances to abstract types (cross-entropy training); predictor uses contrastive learning to generate reference schemas/relations; reasoner conditions the LLM on predicted schemas through structured prompts (task instruction + contextual information + schema guidance).

## Datasets and benchmarks
EV2 (Tao et al. 2025): I-CEC, I-CRR, S-CEC, S-CRR splits (train/test counts in Table 1, e.g., I-CEC 98/393). MCNC (Li, Ding, Liu 2018) five-choice narrative-cloze task used for out-of-distribution generalization. Accuracy is the sole metric. Hardware: Nvidia A800, Python 3.10, PyTorch 2.6, CUDA 12.1; lr 5e-5, batch 8, greedy decoding, max 512 new tokens.

## Evaluation methodology
Compare "Vanilla" LLM vs SGER-augmented LLM across four task dimensions; baselines include GPT-4o, GPT-3.5, Qwen2-7B, Baichuan2-7B, Orca2-7B, Chatglm2-6B, Internlm2-7B, Llama2-7B, Vicuna-7B, Llama3.2-3B. Plus ablations (gold event types as extractor proxy, predictor-only), generalization test on MCNC, and a case study on Llama2-7B.

## Metrics
Accuracy and delta accuracy (∆) between Vanilla and SGER per task.

## Main findings
- SGER improves accuracy for most models/tasks; large open-source gains (e.g., Llama2-7B S-CEC +26.55, S-CRR +23.81; several +15 to +21 points).
- Closed-source gains are smaller (GPT-4o S-CEC +3.61; GPT-3.5 S-CEC +8.25).
- Using gold event types yields 55.04% (I-CEC) and 62.93% (I-CRR), comparable to SGER, indicating the extractor produces high-quality schemas.

## Negative results
GPT-3.5 I-CEC decreased by 1.49% and S-CEC by 1.49% (author attributes this to GPT-3.5 failing to follow schema guidance / compliance restrictions). Orca2-7B S-CEC decreased 4.53%. Some tasks show model-dependent regressions.

## Limitations stated by the authors
Instruction-alignment robustness is an open issue (some models fail to utilize correct schema guidance); future work will explore robust instruction alignment. Generative schema extraction is hard to evaluate directly (they use gold types as a proxy).

## Design implications
For agent-security work this is mainly a reminder that intermediate "schema" representations inserted into prompts are an additional trusted channel; any system adopting such an abstraction layer should treat extractor/predictor outputs as untrusted content that flows into a downstream LLM prompt.

## Implementation implications
The decoupled extractor/predictor/reasoner pattern is a modular pipeline; a security implementation would need integrity checks on the schema-guidance segment injected into prompts.

## Evaluation implications
Demonstrates that model-dependent regressions occur when a model does not follow injected guidance — relevant to any guardrail that assumes an LLM will comply with structured instructions.

## Deployment implications
None security-specific. Lightweight small-model schema predictor is deployable, but no safety controls are defined.
