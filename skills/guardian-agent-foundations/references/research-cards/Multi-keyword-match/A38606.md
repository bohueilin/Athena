## Research question
How can an attacker perform a Profile Pollution Attack (PPA) against a sequential recommender that is simultaneously potent (induces targeted mispredictions, promotes a target item) and stealthy (minimal, hard-to-detect distributional shift), by minimally tampering with individual users' interaction histories rather than injecting many fake profiles?

## Problem definition
Given a sequential recommender Φθ trained on interaction sequences, perturb a subset S of sequences into S' by replacing a small number (≤K) of items with a target item v*, so as to maximize the exposure ratio of v* in recommendations while minimizing detectable distribution shift. Formulated as a bi-level optimization: upper level maximizes perturbation utility over a "pattern horizon" (attributional trace over sequential-pattern dependencies); lower level constrains stealthiness.

## System or model being studied
Target: sequential recommenders (SASRec-style / next-item predictors). Attack system: CREAT — a Constrained REinforcement driven ATtack with (a) a Perturbation Masker Mψ producing step-wise binary replacement masks; (b) a Pattern Balanced Rewarding Policy (PBRP) with a Pattern Inversion Reward (directionality via Euclidean distance to target embedding; diversity via log-det of a Gram matrix) and a Distribution Consistency Reward via Dual-Level (co-)Optimal Transport (DLOT); (c) Constrained Group Relative Reinforcement Learning (C-GRRL) with dynamic barrier constraints, a Lagrangian min-max formulation, and group-shared experience replay.

## Threat model
- Adversary objective: targeted promotion of a specific item v* (maximize its exposure ratio) via induced mispredictions; stealthy manipulation
- Adversary knowledge (white/gray/black-box): gray-to-black-box — attacker assumed to know model architecture and loss, OR to obtain a surrogate via model extraction (paper cites data-free model extraction for recommenders, e.g., Sim4Rec/Yue et al.); black-box recommenders "can be reliably approximated"
- Adversary access: ability to tamper with a subset of individual users' interaction records (profile pollution), replacing ≤K items per polluted sequence; no need for large-scale fake accounts
- Adversary capabilities: craft item replacements guided by RL policy; compute embeddings via surrogate encoder
- Attacker budget: small per-sequence perturbation budget M≤K; polluting a subset S of sequences (fine-grained, individual-level)
- Phase (training / inference / deployment): pollution of interaction data that influences model training/re-training (bi-level lower-level trains θ̂ on polluted data); operates at the data layer feeding the recommender
- Targeted / untargeted: targeted (specific target item)
- Digital / physical: digital
- Adaptive / non-adaptive: adaptive — RL policy adapts perturbations under a dynamic stealth constraint; explicitly designed to evade distribution-shift detection

## Trust assumptions
Assumes the recommender ingests user interaction records that can be individually tampered (a compromised/malicious-user or man-in-the-data-stream position). Assumes surrogate models transfer to the victim (justified via recent model-extraction results). Assumes a detector monitoring distributional shift exists and is the thing to be evaded.

## Attack or failure mechanism
Prior PPA operates at the "sequence horizon" (coarse, user-level), which needs many sequences and causes detectable shifts. CREAT reframes to the "pattern horizon": it identifies pivotal sequential sub-patterns whose semantic distribution diverges from the target, then inserts the target item adjacent to them to forge spurious attributional paths linking varied user intents to the target — exploiting synergistic/cascading pattern effects so a few edits generalize to many similar patterns. Stealth is enforced by minimizing DLOT distance (sequence- and pattern-level optimal transport) between polluted and benign representations, with a dynamic barrier balancing attack efficacy vs. stealth.

## Proposed defense or method
This is an attack paper; it proposes no defense. It positions against detection-based defenses (distribution-shift detectors) and substitution-based PPA defenses (Yue et al. 2022), which it aims to evade.

## Design implications
For agent/recommender security: (1) integrity of the individual interaction/behavior stream is a first-class trust boundary — capability to edit a few user records can be leveraged for targeted, stealthy manipulation; (2) detectors keyed only on global distribution shift are insufficient because fine-grained "pattern-horizon" edits keep aggregate distributions close while altering local transitions; (3) model-extraction feasibility undermines "security by black-box obscurity" for recommenders.

## Implementation implications
Defenders should monitor local sequential-transition patterns and per-user edit patterns (not only global statistics), rate-limit/attest interaction writes, and treat surrogate-extraction as an assumed adversary capability. Provenance/authentication on interaction events (who wrote this history) is relevant.

## Evaluation implications
Stealthy-attack evaluation should include detectors at multiple granularities (instance- and pattern-level, e.g., OT-based) and adaptive defenders; single-granularity distribution-shift detection can be gamed.

## Deployment implications
Recommenders exposed to user-editable histories (clicks, views) in adtech/e-commerce are realistic PPA targets; deployers should assume targeted item-promotion attacks and instrument for them. The ByteDance/TikTok author affiliation underscores industrial relevance.

## Monitoring and incident implications
Suggests monitoring for anomalous target-item exposure spikes and local pattern inversions; incident response should consider that a small number of tampered sequences can cascade. Detection based purely on aggregate distribution consistency is explicitly evaded by this attack.

## Applicability boundaries
_(where these findings should and should NOT be generalized)_
Findings apply to sequential recommender systems and, by transfer, to sequence-modeling ML pipelines where per-instance history can be tampered. They should NOT be over-generalized to LLM prompt-injection or tool-abuse (different surface), though the meta-lesson — fine-grained, stealth-constrained, RL-driven data manipulation that evades single-granularity detectors — is transferable to agent memory/history poisoning. Adjacent (ML security transferable to AI systems), not core agent security.
