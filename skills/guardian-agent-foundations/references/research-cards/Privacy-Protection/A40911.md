## Research question
In surrogate-driven privacy protection for cloud MLLM image editing (private regions replaced by synthetic surrogates before upload), how can the intended edit be faithfully recovered onto the original image locally — the "recovery" half that prior work overlooked?

## Problem definition
To use a cloud MLLM for image editing without exposing sensitive image content, sensitive regions are replaced with synthetic surrogates before upload. But edits applied to the surrogate deviate from edits on the original, and the edited surrogate retains synthetic content (e.g., a fake license plate) rather than the original. Prior surrogate methods prioritize privacy over content consistency and never address recovering the intended edit on the original image. The paper defines and solves this post-surrogate recovery task.

## System or model being studied
- SPPE (Surrogate Privacy Protected Editable) dataset / SPPE-Bench.
- SOER (Surrogate-to-Original Editable Recovery): a Diffusion Transformer (DiT)-based generative framework with Multimodal Attention that fuses four guidance signals (semantic/text, visual, restore/mask, edit) to reconstruct the MLLM edit on the original image locally.
- Cloud editing performed by SmartEdit (an MLLM image editor); surrogate generation via SDXL inpainting.

## Threat model
- Adversary objective: the untrusted party is the cloud MLLM service that could capture/expose private visual content in uploaded images.
- Adversary knowledge/access: the cloud MLLM sees only the surrogate image (private regions already replaced); it is restricted to interacting solely with the surrogate.
- Adversary capabilities: can observe/process whatever is uploaded (the surrogate); the defense's goal is that no original private content is uploaded.
- Attacker budget: not quantified (honest-but-curious cloud model assumed implicitly).
- Phase: inference / deployment (cloud MLLM editing service).
- Targeted / untargeted: not applicable (privacy protection, not attack).
- Digital / physical: digital (image content).
- Adaptive / non-adaptive: non-adaptive; no adversary tries to invert surrogates or de-anonymize.

## Trust assumptions
Local device is trusted (surrogate generation, mask computation, and final recovery all run locally). Cloud MLLM is untrusted with the raw image but trusted to perform editing on the surrogate. Surrogate inpainting (SDXL, guidance scale 0.5) is assumed to conceal private content while preserving semantic coherence. Privacy mask M (difference between I and surrogate S) and edit map (difference S vs S′) are reliable region signals.

## Attack or failure mechanism
Failure being solved: edited surrogate S′ reflects the synthetic content, not the user's original; naively pasting back breaks visual-semantic consistency. Privacy failure of alternatives: differential-privacy and inference-time text-surrogate methods (ReVision, MARRS) lack concrete visual input for editing, so they cannot support direct image manipulation.

## Proposed defense or method
SOER recovers the intended edit locally without uploading the original. Given (I, S, S′, C, M, P), a recovery model R generates Î≈I′ (the edit the MLLM would have produced on the original). Four guidance cues: semantic (text encoder on instruction), visual (shared VAE encoder over I, S, S′), restore (privacy mask M via VAE + transformer F_m), edit (edit map |S′−S|² via VAE + transformer F_e). Embeddings concatenated and denoised by a DiT with Multimodal Attention; trained with Conditional Flow Matching loss and region-aware, mask-reweighted alternating supervision (preserve original content in sensitive regions, reproduce edits elsewhere).

## Datasets and benchmarks
SPPE: 55,696 instances (largest in Table 1 comparison), 36 fine-grained → 10 high-level privacy types → 3 modality classes (textual, visual, multimodal); 65 edit prompts; each instance a 7-tuple (C, P, I, M, S, S′, I′). Also evaluated on a subset of InstructPix2Pix (934 unique prompts; full-image surrogates since it lacks region annotations). Baselines: VISII, Prompt-Diffusion (P-Diff), Edit-Transfer (E-Trans). Prior datasets compared: VISPR, VizWiz-Priv, Redactions, DIPA/DIPA2, BIV-Priv-Seg, Multi-P2A, ReVision, HR-VISPR.

## Evaluation methodology
Two evaluation axes: Edit Consistency (how well Î matches the MLLM-intended edit I′) and Source Integrity (how well Î preserves original content vs I). All baselines trained on the SPPE training split; tested on SPPE test set and InstructPix2Pix subset. Ablations on guidance signals and spatial-representation strategies (transformer vs CNN vs single CLS token); attention-map visualizations across DiT blocks/denoising steps.

## Metrics
SSIM, PSNR, CLIP-Sim (CSIM), Directional Similarity DirS/DirI (edit-direction alignment). Reported (Table 3, author-reported) SOER best across metrics vs baselines, e.g., visual split SSIM 0.8049 / PSNR 23.00 / CSIM 0.8482 vs next-best E-Trans SSIM 0.7483; multimodal split SSIM 0.8166 / PSNR 22.92. Source Integrity considered jointly with edit metrics (since minimal edits inflate integrity).

## Main findings
(Author claims) SOER outperforms VISII, P-Diff, E-Trans across all edit-consistency metrics on SPPE and generalizes to InstructPix2Pix (unseen prompts). All four guidance signals are complementary (removing text prompt causes significant degradation; removing spatial cues degrades localization; no-visual-guidance collapses). Restore guidance attends to privacy-sensitive regions; edit guidance attends to edit-target regions. Achieves a strong balance between privacy protection and MLLM editing usability with minimal retraining.

## Negative results
(Author-reported ablation) The no-visual-guidance configuration collapses (excluded from tables due to performance collapse). CNN or single-CLS-token spatial encoders cause notable performance drops vs the transformer encoder.

## Limitations stated by the authors
Privacy protection depends on surrogate generation quality (moderate guidance scale 0.5 chosen as a privacy/utility trade-off). For datasets without region annotations (InstructPix2Pix), full-image surrogates are used. (No extensive dedicated limitations section in the extracted text.)

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- No adversarial privacy evaluation: there is no test of whether an attacker can invert the surrogate or infer original private content from S, Î, or the recovered output; "privacy preservation" is argued via the paradigm (original never uploaded), not measured against a de-anonymization adversary.
- Privacy metric is qualitative/structural (concealment shown in figures); no quantitative leakage/re-identification metric reported.
- Recovery fidelity is bounded by SmartEdit's behavior consistency between S and I; if the MLLM edits surrogate and original differently in ways not captured by S→S′, recovery may fail.
- SPPE ground-truth edits (I′) are themselves MLLM-generated (SmartEdit), so "fidelity to intended edit" is fidelity to a specific model.
- Sensitive-region masks assume accurate localization from source datasets; mis-segmentation would leak or over-blur.

## Design implications
For agents/apps that offload multimodal work to an untrusted cloud model, apply a redact-then-recover pattern: replace sensitive regions with surrogates before upload (capability isolation of the private content from the model provider) and reconstruct the intended transformation locally. The model provider never receives raw private data — separating "what the model can act on" from "what the user owns".

## Implementation implications
Local recovery needs explicit region signals (privacy mask + edit map) plus multimodal fusion to disentangle preserve-vs-modify regions; region-reweighted training is important for keeping sensitive regions faithful while reproducing edits elsewhere.

## Evaluation implications
Privacy-preserving editing must be scored on both edit fidelity and source integrity jointly (minimal edits trivially maximize integrity), and — reviewer note — should add adversarial de-anonymization tests to substantiate the privacy claim.

## Deployment implications
Enables privacy-compliant use of cloud MLLM editing services (faces, license plates, signatures, IDs, passports) by keeping originals on-device. Practical for regulated/consumer settings; effectiveness hinges on surrogate concealment quality.

## Monitoring and incident implications
Attention-map visualization of restore vs edit guidance offers interpretability for auditing where private content is preserved vs where edits are applied; the privacy mask provides a per-request record of protected regions.

## Applicability boundaries
Applies to visual-surrogate privacy protection for MLLM image editing where private content is region-localizable and the cloud model is honest-but-curious. Adjacent to agent security: it addresses protecting user_data from an untrusted model provider (a data-boundary control), but is not about prompt injection, tool abuse, or agent autonomy. Do NOT read the privacy claim as robustness against an active de-anonymization/inversion adversary — none is evaluated. Textual/non-localizable privacy is handled only via full-image surrogates.
