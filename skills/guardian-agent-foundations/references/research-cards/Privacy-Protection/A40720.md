## Research question
How can a steering vector (SV) constructed from sensitive data be shared with an untrusted service provider under a rigorous differential-privacy guarantee, without the high-dimensional DP noise destroying its utility — and for *training-based* SV construction (not just training-free)?

## Problem definition
A data owner derives an SV from private records via a local LLM and transmits it to a service provider. The SV is a dense, high-dimensional (e.g., >20,000-D for Llama-2-7B: 5 layers × 4096) representation that can leak private info. Naively adding DP noise post-hoc requires noise scaling with dimensionality, overwhelming utility. Existing DP-for-SV (PSA) only covers training-free construction. Goal: a paradigm-agnostic DP mechanism preserving utility.

## System or model being studied
Steering vectors added to hidden states (h_mod = h_orig + λ·Δh) at inference. PrivSV wraps arbitrary SV construction. Evaluated on LLaMA, Qwen, Mistral, Gemma families.

## Threat model
- Adversary objective: infer sensitive attributes / membership from the transmitted SV (Figure 1: adversary crafts queries to reconstruct private info encoded in the SV).
- Adversary knowledge: the service provider (or interceptor) holds the sanitized SV; local DP protects "regardless of an adversary's auxiliary knowledge."
- Adversary access: the transmitted (sanitized) SV; can issue malicious queries to the steered LLM.
- Adversary capabilities: membership-inference attack (empirically evaluated); re-identification using auxiliary knowledge even after PII removal.
- Attacker budget: standard MIA; noted PII-scrubbing is insufficient.
- Phase: deployment / inference (SV shared and used).
- Targeted / untargeted: attribute/membership inference (targeted at individuals in the private set).
- Digital / physical: digital.
- Adaptive / non-adaptive: LDP gives a worst-case (adaptive-robust) guarantee; empirical MIA is a specific instantiation.

## Trust assumptions
Data owner is trusted and runs the privacy mechanism locally before transmission (local DP model). Service provider is untrusted (honest-but-curious / malicious). Service provider may supply *non-sensitive* task descriptors and a public task-aligned corpus; these contain no user data. Synthetic privacy-free demonstrations are generated (e.g., by GPT-4) without private content.

## Attack or failure mechanism
The SV condenses sensitive information; if unprotected it can be intercepted/analyzed to reconstruct private attributes (contravening GDPR). Post-hoc DP fails because required noise ∝ dimensionality overwhelms a 20k-D vector.

## Proposed defense or method
PrivSV = three synergistic methods under Metric-LDP (εd-LDP via generalized planar Laplace mechanism):
1. **Layer-wise Noise-Resilient Reduction (LNR²)** — a structure-aware Hierarchical Convolutional Compactor (HCC, 1D-conv encoder–decoder over the D×L reshaped SV) compresses the SV to a low-dim latent before noise injection, drastically reducing required perturbation; trained via Privacy-Decoupled Task Feedback (PDTF) using a public Task-Aligned Corpus.
2. **Directional Prior Compensation (DPC)** — builds a reference SV from synthetic privacy-free inputs capturing task format/topic/style, then interpolates X_f = αX′ + (1−α)X_r to steer the noisy SV back toward the task direction.
3. **Privacy-Aware Optimal Parameter Determination (POPD)** — analytically models the noise-error vs information-error trade-off as a constrained optimization with a closed-form optimal α.
Provides εd²-LDP for the SV (author claim).

## Evaluation methodology
Compare PrivSV vs. state-of-the-art DP-SV methods (e.g., PSA) across varying privacy budgets ε; measure downstream task performance (utility) and empirical membership-inference resistance.

## Metrics
Task utility (accuracy) vs. privacy budget ε; membership-inference attack success (privacy). Author claim: PrivSV outperforms SoTA across various privacy budgets while providing formal εd²-LDP and compatibility with arbitrary (incl. training-based) SV construction.

## Main findings
- (Author claim) LNR² compression makes DP feasible for high-dimensional SVs; DPC restores utility lost to noise; POPD's closed-form α optimally balances the trade-off.
- Outperforms prior DP-SV (PSA) across privacy budgets on four model families.
- Provides a formal local-DP guarantee (εd²-LDP), with cumulative budget kε over k training epochs by composition.

## Negative results
Naive post-processing DP on the raw high-dim SV is shown fundamentally impractical (noise overwhelms utility) — the motivating negative result. Trade-off dilemma: large α ⇒ excess noise error; small α ⇒ excess information error.

## Limitations stated by the authors
The utility–privacy tension is intrinsic; α must be chosen carefully (addressed by POPD). Reliance on a public task-aligned corpus and synthetic privacy-free data supplied/curated by the service provider. (Full limitations truncated.)

## Additional limitations identified during review

- Only membership inference is empirically evaluated; attribute-reconstruction/model-inversion (the Figure 1 scenario) is not clearly quantified as an attack.

- DPC's reference vector is derived from synthetic data whose fidelity to the true task affects both utility and whether residual private direction leaks — not stress-tested adversarially.

## Design implications
When sharing dense model-derived artifacts (SVs, embeddings, activations) with an untrusted party, apply DP *after structure-aware dimensionality reduction* and *compensate* with a public-data prior — reducing effective sensitivity/dimensionality is key to usable DP on high-dim vectors.

## Implementation implications
Requires training a compressor (HCC) on a public task corpus, a synthetic-data generator for the reference SV, and a closed-form α solver. Local-DP means the mechanism runs on the data owner's side before transmission.

## Evaluation implications
Report utility across a range of ε and pair the formal DP guarantee with empirical attack (MIA and ideally inversion) results; the formal εd²-LDP does not by itself bound every attack of interest.

## Deployment implications
Directly relevant to federated/cross-org agent settings where an owner offloads steering to a third-party LLM service (provider-as-adversary, cf. A40534). Enables privacy-preserving personalization/alignment via shared SVs under a stated DP budget.

## Monitoring and incident implications
Track cumulative privacy budget (kε) across repeated SV releases/epochs; budget exhaustion is an incident condition. No runtime monitor proposed.

## Applicability boundaries
Applies to sharing SVs/dense activation artifacts under local DP with an available public task corpus. Metric-LDP guarantees are relative to the chosen metric and do not transfer to arbitrary threat models. Adjacent to agent security (privacy of model-control artifacts), not about prompt/tool injection.
