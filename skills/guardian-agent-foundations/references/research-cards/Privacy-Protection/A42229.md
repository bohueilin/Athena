## Research question
Can argumentative explanations (structured grounds + counterarguments) be generated end-to-end over encrypted data using homomorphic encryption (CKKS) — without decrypting sensitive inputs — at practical runtime and with acceptable explanation faithfulness?

## Problem definition
Argumentative explanations expose supporting grounds and counterarguments for a model decision, but these often contain personal data, so the explanation process itself can disclose private information. Federated learning reduces raw-data exposure but not computation-time exposure; homomorphic encryption (HE) allows computation on ciphertext but is far slower and incompatible with common pipeline steps (ReLU, hard cluster assignment under CKKS), so encrypted argumentative explanation is considered impractical beyond tiny models.

## System or model being studied
An end-to-end CKKS-encrypted inference + explanation pipeline over a multilayer perceptron (MLP). Model is trained in plaintext, then inference and argumentative-explanation generation run in the encrypted domain. Clustering (for argument aggregation) uses a soft k-means variant; weight aggregation follows Ayoobi, Potyka & Toni (2023, SpArX).

## Threat model
- Adversary objective: recover sensitive input data or personal information contained in inputs/explanations.
- Adversary knowledge (white/gray/black-box): not explicitly parameterized; the confidentiality target is the plaintext input/features observed during computation and explanation.
- Adversary access: an honest-but-curious compute host / explanation service that processes user data — implied by the HE motivation (compute without revealing original inputs).
- Adversary capabilities: observe ciphertext and computation; cannot decrypt without the key (standard HE assumption).
- Attacker budget: not stated in paper.
- Phase (training / inference / deployment): inference/deployment; training is done in plaintext (out of the protected boundary).
- Targeted / untargeted: confidentiality-focused (protect inputs); not an attack paper.
- Digital / physical: digital.
- Adaptive / non-adaptive: not stated in paper.

## Trust assumptions
Model weights are known/fixed and used as plaintext in ciphertext–plaintext operations; the training phase is trusted/plaintext. The party holding the decryption key is trusted; the computation environment need not see plaintext inputs. Standard CKKS security assumptions are inherited (not analyzed in the abstract).

## Attack or failure mechanism
Failure being prevented: sensitive personal data embedded in argumentative explanation grounds/counterarguments (or inputs) is disclosed during explanation generation. This is a privacy-leakage failure of explanation pipelines, not an active exploit.

## Proposed defense or method
An HE (CKKS) pipeline that runs inference + argumentative-explanation end-to-end on ciphertext: (i) replace ReLU with a low-degree polynomial p(x)=x^2+x; (ii) replace hard argmin clustering with a soft k-means using Newton's-approximation reciprocals/normalization so it runs on ciphertext; (iii) linear layers via ciphertext–plaintext multiply/add and rotation–accumulation; (iv) GPU parallelization of CKKS multiplication/rotation bottlenecks to cut runtime. This is a confidential-computation (cryptographic privacy) defense rather than a TEE.

## Datasets and benchmarks
Breast Cancer tabular classification task. Three MLP sizes: MLP-S (3 layers × 30 nodes), MLP-M (5 × 50), MLP-L (7 × 100). Inference/explanation tested on 16 held-out samples. CKKS with n = 2^12 slots. Hardware: Intel Core Ultra 9, RTX 5090, 64 GB RAM (OpenFHE-family HE tooling referenced).

## Evaluation methodology
Compare plaintext baseline vs encrypted (Ours) on GPU and CPU for runtime, and plaintext vs ciphertext explanation quality (unfaithfulness) across the three MLP sizes; extend structural-unfaithfulness metric to the soft-k-means setting by reconstructing activations from probabilistic memberships.

## Metrics
- Runtime: inference and explanation-generation time (seconds), CPU vs GPU. Reported GPU-vs-CPU speedups ≈ 300× (MLP-S), 470× (MLP-M), 670× (MLP-L) for explanation generation. Example absolute figures: MLP-L explanation on GPU 645.19 s vs CPU 438,213.15 s.
- Faithfulness: input–output unfaithfulness (IO, ↓) and structural unfaithfulness (↓). E.g., IO baseline→Ours: MLP-S 0.0108→0.0387, MLP-M 0.0098→0.0819, MLP-L 0.0499→0.4454; Structural MLP-L 0.4300→0.5172.

## Main findings
Author claims: (1) end-to-end encrypted argumentative explanation is feasible without decrypting inputs; (2) GPU acceleration yields ~470–670× speedup over CPU for encrypted explanation; (3) explanation fidelity stays close to plaintext up to MLP-M but degrades severely for MLP-L, so faithfulness worsens as model size grows.

## Negative results
Explanation fidelity degrades substantially for the largest model (MLP-L) — both IO and structural unfaithfulness rise markedly. Even GPU-accelerated encrypted explanation remains slow in absolute terms (hundreds of seconds for MLP-L), i.e., not yet interactive.

## Limitations stated by the authors
Fidelity drop for larger models (MLP-L) is the key limitation; scalability and reliability for complex models remain open. Future work: HE-friendly clustering beyond soft k-means and further GPU kernel optimization to approach interactive latency while preserving faithfulness. Positioned explicitly as a proof-of-concept / initial step.

## Additional limitations identified during review
_(reviewer synthesis)_
- Single small tabular dataset (Breast Cancer), 16 test samples, and MLPs only — no image/text/LLM models; generalization is unestablished.
- No formal privacy/leakage analysis or threat-model parameterization beyond invoking HE; the honest-but-curious adversary and key-management model are implicit, not specified.
- Polynomial ReLU (x^2+x) and soft-k-means approximations are the likely cause of fidelity loss but their error is not decomposed/bounded.
- No comparison against alternative PETs (DP, MPC, TEE) on the same task; the privacy/utility/latency trade-off is characterized only within HE.
- Runtime is still far from real-time for the useful (larger) models, limiting practical deployment.

## Design implications
Confidential computation can, in principle, cover the *explanation* path and not just prediction — useful where explanations themselves carry PII (credit, healthcare). HE-friendly redesign of nonlinearities and clustering is the enabling design move.

## Implementation implications
Non-HE-friendly ops must be swapped for low-degree polynomial / soft approximations; GPU parallelization of CKKS multiply/rotate is essential to bring runtime into range. Expect a faithfulness penalty that scales with model depth/size.

## Evaluation implications
Encrypted-explanation systems should report BOTH runtime (CPU vs GPU) and explanation-faithfulness across model sizes — this work models a useful evaluation pattern; faithfulness must be measured, not assumed preserved.

## Deployment implications
Practical today only for small-to-medium models where fidelity holds and latency is tolerable; large-model encrypted explanation is not yet interactive or faithful. Key management / trust boundary for the decryption key must be handled separately.

## Monitoring and incident implications
Not addressed. HE hides plaintext from the compute host, reducing exposure logging needs there, but provides no runtime monitoring or abuse detection of its own.

## Applicability boundaries
_(where to and NOT to generalize)_
**Adjacent** to agent security: a privacy-preserving-inference / confidential-computation technique transferable to AI systems that must explain over sensitive data, but the paper studies classical MLPs on tabular data, not LLMs, agents, tools, or MCP.
