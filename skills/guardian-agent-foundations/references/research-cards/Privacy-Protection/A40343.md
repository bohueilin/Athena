## Research question
Can LLM machine unlearning remove harmful/private knowledge *thoroughly from the parameters* — not merely suppress its output — so that the knowledge cannot be recovered by a lightweight fine-tuning (relearning) attack?

## Problem definition
Given a forget set D_forget and a retain set D_retain, optimize model parameters to eliminate the forgotten knowledge as thoroughly as possible while preserving utility, such that after a Retraining-on-T (RTT) attack — fine-tuning on a subset T of D_forget — the model still cannot generate the knowledge in a disjoint subset V. Existing methods only adjust a small number of "cover layers" that mask, not erase, the knowledge.

## System or model being studied
Open-weight instruction LLMs: Zephyr-7B and LLaMA3-8B. Method KUnBR (Knowledge Density-Guided Unlearning via Blocks Reinsertion) operates on Transformer MLP layers grouped into blocks.

## Threat model
- Adversary objective: recover ("relearn") knowledge that was supposedly unlearned.
- Adversary knowledge: white-box — has model weights and can fine-tune (RTT is a parameter-modification-level attack).
- Adversary access: full parameter access; a subset T of the forget set for re-training.
- Adversary capabilities: fine-tune the unlearned model on T; also referenced jailbreak-style prompt attacks as motivation.
- Attacker budget: "minimal re-training" on a subset of the forget set (per Deeb and Roger 2025).
- Phase: post-training / deployment (attack applied to a released unlearned model).
- Targeted / untargeted: targeted (specific forgotten facts).
- Digital / physical: digital.
- Adaptive / non-adaptive: RTT is a fixed, known attack; KUnBR is designed against it (non-adaptive evaluation — no attacker that adapts to KUnBR's mechanism).

## Trust assumptions
Defender controls training and can run full-parameter fine-tuning. The released model may fall into an adversary's hands who can fine-tune it. Utility must be preserved for benign users. No cryptographic assumptions.

## Attack or failure mechanism
Existing gradient-ascent-family unlearning (GA, GD, RMU, NPO) modifies a small set of "cover layers" that suppress harmful outputs; residual knowledge persists in unmodified layers, so RTT fine-tuning restores it. Cover layers also obstruct gradient propagation to knowledge-dense layers during unlearning.

## Proposed defense or method
KUnBR, three steps: (1) warm-up unlearning via Gradient Difference on all parameters; (2) **knowledge density estimation** — score each layer by the expected L1 norm of the forget-set loss gradient (larger gradient magnitude ⇒ more forgettable knowledge), normalize across layers, group layers into M blocks, select Top-K highest-density blocks while excluding the last two layers (output-generation artifacts); (3) **re-insertion strategy** — extract knowledge-rich blocks from the unlearned model, graft them back into the *original* (un-unlearned, frozen) model, and re-apply Gradient Difference so gradients propagate without cover-layer obstruction, then revert. Iterated over all selected blocks.

## Datasets and benchmarks
Forget/eval: WMDP-Deduped, Years, Random Birthdays (Deeb & Roger 2025). Utility: MMLU, and the RKWU utility framework (Reasoning via Big-Bench-Hard, plus other core metrics). Baselines: GA, GD, RMU, RIA, NPO.

## Evaluation methodology
Multiple-choice Forget Accuracy (A_Unlearn) after unlearning, A_RTT after RTT attack, and Recovery A_Recover = A_RTT − A_Unlearn (lower is better robustness). Compared across two backbones and four datasets against five baselines; utility measured on MMLU / RKWU.

## Metrics
Forget accuracy (↓ better forgetting), RTT accuracy (↓), Recovery accuracy (↓ = more robust). Utility accuracy (↑). Author claim: KUnBR achieves lowest forget and (in most settings) RTT accuracy, i.e., state-of-the-art thorough forgetting while retaining general capability.

## Main findings
- (Author claim) KUnBR substantially reduces post-RTT recoverable knowledge vs. baselines on Random Birthdays, WMDP-Deduped, and Years across both backbones (e.g., large drops in Forget./RTT. accuracy in Table 1).
- Re-insertion into the frozen original model bypasses cover-layer gradient obstruction, enabling deeper erasure.
- MMLU utility is largely maintained relative to baselines.
- Case study: only KUnBR both forgets and stays forgotten under RTT while producing readable output.

## Negative results
On some columns KUnBR's Recovery is not the lowest (e.g., certain Years/WMDP cells show higher Rec. than a baseline), indicating the improvement is not uniform across all datasets/backbones. (Author-reported in Table 1.)

## Limitations stated by the authors

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Only one relearning attack (RTT) is evaluated; no adaptive attacker aware of KUnBR's re-insertion, no soft-prompt/embedding-space or jailbreak attack quantified despite being cited as motivation.
- "Thorough" removal is evidenced by an accuracy proxy under one attack, not by a certified or information-theoretic guarantee; residual knowledge may remain recoverable by stronger attacks.
- Only 7–8B models; scaling behavior unknown.
- Knowledge-density metric (gradient L1 norm on forget set) is a heuristic; no ablation isolating it from the re-insertion trick is summarized in the extracted text.

## Design implications
Unlearning as a privacy/safety control should be validated against *weight-level relearning*, not just output suppression. Locating and directly optimizing knowledge-dense layers (rather than whole-model gradient ascent) is a useful design pattern for deeper erasure.

## Implementation implications
Gradient-norm-based layer scoring is cheap to compute (one backward pass over the forget set). Re-insertion requires holding both original and unlearned checkpoints and swapping blocks — memory/engineering overhead to budget for.

## Evaluation implications
Recovery-under-RTT should be a standard axis in any unlearning/right-to-be-forgotten deployment claim; report utility (MMLU/RKWU) jointly to catch collateral damage.

## Deployment implications
Relevant to "right to be forgotten," removing hazardous (WMDP) knowledge, and PII deletion. Because robustness is shown only against one known attack, deployment claims should say "reduced recoverability under the RTT threat model," not "removed."

## Monitoring and incident implications
Operators shipping unlearned checkpoints should assume adversaries may fine-tune; periodic re-audit with relearning probes is warranted. No runtime monitor is proposed here.

## Applicability boundaries
Applies to open-weight LLM unlearning where the defender can do full/partial fine-tuning and the threat is weight-level knowledge recovery. Does NOT cover closed-API models, agentic tool/memory leakage, or inference-time-only settings. Findings should not be generalized to "provably forgotten."
