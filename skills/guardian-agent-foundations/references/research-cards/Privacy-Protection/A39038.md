## Research question
Can a single framework support both fine-grained ("meta") and whole-client federated graph unlearning while (a) removing the target entity's own contribution and (b) purging *residual knowledge that permeated to other clients* via gradient exchange and graph-structural dependencies — without retraining from scratch and without degrading utility on retained data?

## Problem definition
Federated Graph Learning (FGL) trains a shared GNN across clients holding local subgraphs. The "right to be forgotten" requires removing (i) specific nodes/edges/features within a client's subgraph (**Meta Unlearning**) and (ii) an entire departing client's contribution (**Client Unlearning**). Authors state prior work handles these in isolation and neglects cross-client "residual knowledge permeation," so sensitive information may still be extractable after nominal unlearning. Goal: approximate the retrained-from-scratch model θ* by an unlearned model θ̄ = FGU(θ°; C; G; ΔC; ΔG), minimizing ||θ̄ − θ*|| while preserving utility.

## System or model being studied
PAGE (Prototype-guided Adversarial Graph Eraser), a three-stage FGU framework over FedAvg-style FGL:
1. **Prototype Matching for Local Unlearn** — each client uploads class-prototype (feature-centroid) vectors; server builds a Gram–Schmidt orthogonal prototype space, projects the unlearn prototype onto it, extracts a "pure private knowledge guiding vector" ppriv orthogonal to retained knowledge, and the unlearning client fine-tunes toward it (MSE loss).
2. **Adversarial Graph Generation** — server holds original and unlearned models, and via gradient ascent generates an adversarial graph (perturbed adjacency + features) that maximizes output discrepancy between the two, acting as a sensitive probe for residual knowledge.
3. **Negative Knowledge Distillation for Influenced Unlearn** — prototype similarity (cosine) identifies "influenced clients"; targeted distillation using the adversarial samples removes permeated knowledge. For client unlearning, a randomly initialized noise model serves as the unlearned model and only stages 2–3 run.

## Threat model
- Adversary objective: recover/verify that "forgotten" data still influences the model (i.e., detect incomplete unlearning); the paper frames privacy risk via membership inference.
- Adversary knowledge (white/gray/black-box): Membership-inference verifier queries the model's responses to distinguish training vs non-training records (black-box query access as described); not fully specified.
- Adversary access: query access to the (un)learned model for verification.
- Adversary capabilities: build an inference model over model outputs; also motivational threats cited (data-poisoning against FL, Tolpegin et al. 2020) but not evaluated here.
- Attacker budget: not stated in paper.
- Phase (training / inference / deployment): unlearning operates during/after federated training (deployment-time model editing); verification is inference-time.
- Targeted / untargeted: targeted removal of specified nodes/edges/features/clients.
- Digital / physical: digital.
- Adaptive / non-adaptive: non-adaptive; no adaptive attacker that reacts to PAGE is evaluated.

## Trust assumptions
Central server is honest and coordinates prototype aggregation, adversarial-graph generation, and distillation; server retains only global model parameters, not raw data (per FGL setup). Clients honestly compute and upload model parameters and prototype vectors. No malicious/colluding server or client is modeled. The unlearning verifier (membership inference) is the adversary against which "forgetting integrity" is judged.

## Attack or failure mechanism
Failure being remedied: **residual knowledge permeation** — during federated rounds, gradients and graph-structural dependencies carry information about to-be-forgotten data into *other* clients' models, so local-only unlearning leaves recoverable traces. Also **incomplete unlearning support** — no unified mechanism spans node/edge/feature and whole-client removal. The adversarial graph is the mechanism used to *expose* residual behavioral differences between original and unlearned models.

## Proposed defense or method
See "System or model being studied." Key ideas: (1) prototypes as privacy-preserving knowledge carriers (avoid raw-graph manipulation, preserve structure); (2) orthogonal-projection separation of private vs shared knowledge; (3) difference-maximized adversarial graph as a residual-knowledge probe; (4) negative knowledge distillation to influenced clients. Presented as both a standalone client-unlearn engine and a plug-in enhancement for existing meta-unlearn methods.

## Datasets and benchmarks
8 benchmark graph datasets (named partially in text/figures): includes Cora, CS, Chameleon, Minesweeper; others in the extended version. Covers small- and large-scale graphs. Baselines: graph-unlearning methods (GIF, IDEA, D2DGN, MEGU, FedLU, FedDM) and federated-unlearning methods (FedEraser, FUSED, MoDe, ReGEnUnlearn), plus RFPS in robustness plots. Full setup deferred to Ai et al. 2025 (arXiv:2508.02485).

## Evaluation methodology
Comparison against SOTA FU and GU methods under multiple unlearn requests (Q1); augmentation/ablation study of the influenced-unlearn component as a plug-in (Q2); robustness across unlearn ratios and adversarial edge-attack ratios (Q3). Unlearning is verified via membership-inference-style analysis; utility via prediction accuracy.

## Metrics
- Prediction accuracy (utility) and "unlearning performance" (forgetting integrity; exact definition deferred to extended version).
- Reported gains: +5.08% accuracy (client unlearn), +1.50% (meta unlearn), up to +11.84% on large-scale graphs; as a plug-in, up to +4.49% prediction and +7.22% unlearning performance (on CS); +2.82%/+4.64% on Cora.
- Robustness curves vs client-unlearn ratio (0.1–0.9) and edge-attack ratio.

## Main findings
Author claims: PAGE achieves SOTA across 8 datasets on both unlearn requests; the influenced-unlearn component works standalone (client unlearn) and as a plug-in (meta unlearn); PAGE stays stable as unlearn intensity and adversarial edge-attack ratio increase, with "counter-intuitive" accuracy gains at high forgetting intensities on Chameleon.

## Negative results
Author-acknowledged: PAGE slightly underperforms RFPS at low unlearn intensities on Chameleon. No case where residual permeation is fully measured to be zero; forgetting is approximate (objective is to minimize ||θ̄ − θ*||, not attain it).

## Limitations stated by the authors
Conclusion states future work must "prioritize integrated frameworks harmonizing local and influence unlearning for comprehensive permeation mitigation" — i.e., permeation mitigation is not yet complete. Much experimental detail is deferred to the arXiv extended version.

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Privacy verification relies on membership inference as the sole adversary; no reconstruction, attribute-inference, or *adaptive* attacker that targets prototype/adversarial-graph leakage is evaluated. "Forgetting integrity" numbers are not clearly defined in the conference text.
- Prototype vectors and gradients themselves are uploaded to the server; the paper asserts this "avoids direct raw graph manipulation" but provides no formal privacy guarantee (no DP, no MPC) that prototypes/adversarial graphs do not leak forgotten-data information.
- Honest-server, honest-client trust model; a curious server sees prototypes and both model versions and could itself attempt reconstruction — not analyzed.
- No formal unlearning guarantee (unlike certified-unlearning lines, e.g., IDEA); results are empirical.
- Truncated experimental section (in this text) obscures dataset list and metric definitions.

## Design implications
Unlearning in *federated* + *graph* settings must treat cross-client knowledge propagation as a first-class residual-risk channel, not just edit the target client. Orthogonal separation of "private" vs "shared" representation is a reusable pattern for scoping what to erase. Adversarial "difference-maximizing" probes are a promising design for *evidence that unlearning happened* — a verification artifact, not just a training trick.

## Implementation implications
Prototype-centroid exchange is cheaper than raw-graph or full-gradient replay; a plug-in influenced-unlearn module can be added to existing meta-unlearn pipelines. Implementers should log which clients were flagged "influenced" and the adversarial-probe discrepancy as an audit trail.

## Evaluation implications
Membership inference alone is a weak privacy oracle; unlearning claims should be tested against reconstruction and adaptive attackers, and the exact "unlearning performance" metric must be specified. Report residual-permeation directly (e.g., attack success on influenced clients before/after), not only downstream accuracy.

## Deployment implications
Fits "right to be forgotten" / GDPR / CCPA compliance workflows for federated GNN services (social, financial, recommendation). Because forgetting is approximate and unguaranteed, it should support—not replace—retraining for high-assurance deletion, and should be paired with a curious-server threat analysis before production use.

## Monitoring and incident implications
The adversarial-probe discrepancy and prototype-similarity "influenced client" list are natural monitoring signals: a persistently high post-unlearn discrepancy indicates incomplete erasure and should trigger re-distillation or escalation to full retraining. Maintain audit records of every unlearn request, affected clients, and verification outcome.

## Applicability boundaries
Findings apply to federated GNN training over partitioned graphs with an honest server and honest clients. They should NOT be generalized to (a) malicious/colluding servers or clients, (b) formal/certified deletion guarantees, (c) non-graph or non-federated unlearning, or (d) LLM/agent memory unlearning without re-validation. This is ML-privacy work (adjacent to agent security), not agent/tool/prompt security.
