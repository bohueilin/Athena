## Research question
In multi-party / federated deep learning, how can model execution be bound to the JOINT authorization of all
participating parties, so that no single party (or an attacker who steals the model or one party's secrets) can
activate the model without all parties' consent?

## Problem definition
Existing IP-protection is either passive (watermarking, verify ownership after theft) or single-party proactive
(encryption/keys, single fixed trigger). Single-party proactive controls fail under single-point key/trigger leakage
or insider compromise. The paper defines a "Consensus Learning Paradigm" requiring (1) Joint Authorization — all
parties must contribute valid trigger factors; missing/forged components leave the model inert — and (2)
Collaborative Embedding — trigger signals injected during training to form an indivisible distributed access
credential.

## System or model being studied
Collaborative Perturbation Trigger Method (CPTM). Each of N federated clients sequentially injects identity-bound
perturbations into shared data to produce Consensus Triggered Data (CTD). Perturbations combine: chained single/
multi-stage affine transforms (each client's transform composes on the previous output), pixel-level nonlinear
sinusoidal perturbation δ = α·sin(βx+γy+φ), a fixed structured "noise lock" image, and frequency-domain (FFT)
high-frequency patch embedding. The model is trained on three dataset types — Invalid Set (random/forged
perturbations, wrong labels), Initial Set (clean inputs, random labels → stay inert), and Authorized Set (full
valid CTD, correct labels) — so it produces correct outputs only on fully-authorized CTD. No model-architecture
modification is required.

## Threat model
- Adversary objective: bypass multi-party authorization to use/deploy/steal the model.
- Adversary knowledge: may obtain a full copy of the trained model (white-box weights) via transmission interception
  or server compromise; may know one party's trigger data/perturbation parameters/protocol.
- Adversary access: (1) single-party information leakage; (2) full model acquisition; (3) partial trigger forgery
  from accessible samples and known patterns.
- Adversary capabilities: craft forged/fused triggers from partial (e.g., 3-of-5) client information; brute force.
- Attacker budget: brute-force complexity argued as combinatorial (e.g., >2^270 for N=5, 32×32 images), exceeding a
  2^64 threshold.
- Phase: inference/deployment (activation-time access control); triggers embedded during training.
- Targeted / untargeted: targeted access control.
- Digital / physical: digital (image classification / face recognition).
- Adaptive / non-adaptive: partial-leakage and trigger-fusion attackers are evaluated (Acc-Single, Acc-Fusion);
  a fully adaptive attacker who re-optimizes against the trained detector is not shown.

## Trust assumptions
Each participant independently generates and keeps its own perturbation parameters/point-sets locally; parameters
are neither stored centrally nor shared publicly (decentralized secrecy). Security relies on all parties' affine
matrices being required to reconstruct CTD ("chain breaks if any remain private").

## Attack or failure mechanism
Unauthorized use / model theft / IP infringement via: stolen model weights, leaked single-party trigger, or forged/
fused partial triggers. The defense's failure mode would be a forged CTD that still activates the model.

## Proposed defense or method
CPTM + Consensus Learning training regime (Invalid/Initial/Authorized sets). Model activates (produces meaningful
predictions) only when input carries the complete multi-party CTD; otherwise output accuracy collapses.

## Datasets and benchmarks
MNIST, CIFAR-10, CIFAR-100, Face-LFW. Architectures: VGG16, ResNet18, DenseNet121, WideResNet50-2. Hardware: NVIDIA
Tesla V100. Client counts: 5, 10, 15, 20.

## Evaluation methodology
Compare authorized-input accuracy (Acc-Pro) vs baseline clean accuracy (Acc-Clean); measure unauthorized-input
accuracy under Acc-Origin (clean/no trigger), Acc-Single (attacker with one client's info), Acc-Fusion (attacker
fuses 3-of-5 clients). Scalability tested by varying client number.

## Metrics
- Authorized accuracy within ~2% of unprotected baseline (e.g., ResNet18 CIFAR-10 Acc-Pro ≈ 93.24 vs Acc-Clean
  93.08).
- Unauthorized accuracy driven low: CIFAR-10 Acc-Origin ≈ 0.4–1.3; Acc-Single ≈ 1.9–5.1; Acc-Fusion ≈ 4.4–15.1
  (varies by architecture). MNIST stays ~10–17 (near chance). Author claims unauthorized accuracy "below 10%".
- Brute-force complexity: combinatorial argument > 2^270 for N=5.

## Main findings
Author claims: negligible accuracy loss on authorized data; strong suppression of unauthorized/forged/partial-fusion
inputs; robustness to partial (single- and 3-of-5) authorization leakage; stable across 5–20 clients.

## Negative results
Some Acc-Fusion values on CIFAR-10 (e.g., VGG16 ≈ 15.08) are meaningfully above chance, indicating partial-trigger
fusion leaks a nonzero amount of usable accuracy for certain architectures; the paper frames these as still low but
they are not zero.

## Additional limitations identified during review
_(reviewer synthesis — not author claims)_
- Demonstrated only on vision classifiers (image classification / face recognition), NOT on LLMs or agentic systems;
  transfer to generative/agent models is unshown.
- The brute-force complexity is a combinatorial counting argument over affine point-sets, not a cryptographic
  reduction; it does not bound a learning-based attacker who approximates a valid trigger without exact points.
- No adaptive white-box attacker (who has the model AND optimizes an input to activate it via gradient search) is
  evaluated; access control that lives in learned weights may be susceptible to such optimization.
- "Model can only be activated with full consensus" is an empirical accuracy claim, not a guarantee; residual
  Acc-Fusion shows partial activation is possible.
- Fixed structured noise + FFT patch are content-agnostic and identical across images, which could aid an attacker
  in isolating the trigger component.

## Design implications
A pattern for machine/model identity + multi-party authorization: bind execution rights to an indivisible,
distributed credential rather than a single key. Conceptually adjacent to "no single party can act alone" designs
(threshold authorization) for AI model access.

## Implementation implications
Access control embedded in training (as a learned trigger) avoids architecture changes but couples security to model
weights; key rotation means retraining. Consider combining with cryptographic access control for hard guarantees.

## Evaluation implications
Evaluations should include adaptive, gradient-based activation attacks and near-miss trigger approximation, not only
fixed forged/fused triggers, to characterize residual risk.

## Deployment implications
Relevant to federated/collaborative model ownership where the shared global model is transmitted in plaintext and
insiders/interceptors are in scope. Residual Acc-Fusion argues for defense-in-depth (encryption + monitoring).

## Monitoring and incident implications
Log activation attempts and unauthorized-input accuracy; a rise in accuracy on non-consensus inputs signals trigger
leakage/forgery. Model theft still exposes weights, so provenance/watermarking remains complementary.

## Applicability boundaries
Applies to multi-party access control for classification/recognition DNNs. Do NOT read the results as a security
proof or as covering LLM/agent access control; the threat model omits adaptive weight-level optimization attacks.
