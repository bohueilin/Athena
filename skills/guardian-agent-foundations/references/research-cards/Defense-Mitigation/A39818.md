## Research question
Can a lightweight, low-compute, multimodal Real-Time-Strategy (tower-defense) environment serve as a benchmark for
evaluating LLM-as-agent long-term planning and decision-making — and additionally measure "hallucination" (invalid/
inconsistent actions) — while avoiding the high compute cost of StarCraft II-based benchmarks?

## Problem definition
Existing RTS LLM benchmarks (TextStarCraft II, LLM-PySC2, VLMs Play StarCraft II) rely on SC2LE (~30 GB disk, 2 GB
RAM, GPU) and are costly; existing lightweight RTS envs (ELF, DeepRTS, Gym-µrts) lack textual observation/action
interfaces and so are incompatible with LLMs. There is no dedicated, sufficiently challenging tower-defense (TD)
environment with multimodal observations for LLM agents.

## System or model being studied
TowerMind — a Unity + Unity ML-Agents environment (OpenAI Gym-compatible) for the TD subgenre of RTS. Observations are
pixel-based, textual (JSON with named fields), and structured (flattened array). Hybrid action space
`a=(x,y,c)` with continuous coordinates in [−3,3] and 12 discrete action types; sparse reward (−1 per enemy reaching
base); fog-of-war partial observability; 15 enemy types; "misleading" tower points; five built-in difficulty levels
with a quantitative difficulty metric `D(l)=d_r+d_t+d_e+d_re`. Evaluated LLMs (several widely-used commercial and
open-source; e.g. GPT-4/Claude/Gemini/Qwen-VL/Llama families are referenced) plus RL baselines Ape-X DQN and PPO.

## Threat model
Not an adversarial-security paper — no attacker/defender model. The nearest security-adjacent notions are:
- "Hallucination" = LLM outputs that are invalid or inconsistent with game state/rules (executability failure), used
  as a reliability metric, not an attack.
- "Misleading information" = deliberately deceptive map features (misleading tower points, fog of war) that stress-test
  robustness of the agent's planning under partial/deceptive observations.
- Data-contamination mitigation = the level editor lets researchers author novel levels to reduce benchmark
  contamination / memorization.

## Trust assumptions
Assumes textual/structured observations faithfully encode game state (JSON with semantic field names) and that
invalid-action detection (rule/state checks) is a reliable ground truth for measuring hallucination.

## Attack or failure mechanism
N/A (no adversary). Observed LLM failure modes (author claims): inadequate planning validation, lack of multifinality
in decision-making (not generating diverse means to an end), and inefficient action use — plus hallucinated (invalid)
actions.

## Proposed defense or method
A benchmark/environment rather than a defense. Contributions: (1) lightweight multimodal TD environment (0.15 GB
disk/RAM, CPU-only vs. SC2LE's ~30 GB/GPU); (2) hallucination evaluation via action executability; (3) customizable
level editor to reduce data contamination; (4) five difficulty-graded benchmark levels with a difficulty metric.

## Datasets and benchmarks
Five built-in TowerMind levels (increasing difficulty). Comparison table vs. ELF, DeepRTS, Gym-µrts, Mini HoK on
pixel/text observation, stochasticity, partial observability, level editor, Gym interface. No external ML datasets.

## Evaluation methodology
Evaluate several LLMs across the five levels under different multimodal input settings; compare to human experts on
both capability and hallucination dimensions; additionally train/evaluate Ape-X DQN and PPO as RL baselines. Actions
executed every 16 game steps (~187 actions/min, similar to SC2LE).

## Metrics
In-game score (enemies stopped / base health) as capability; action executability / invalid-action rate as the
"hallucination" indicator; comparison against human-expert performance. Numeric values not visible in extracted text.

## Main findings
- Author claim: a clear performance gap remains between LLMs and human experts on both capability and hallucination.
- Author claim: commercial LLMs outperform open-source ones, but all show behavioral shortcomings (inadequate planning
  validation, lack of multifinality, inefficient action use).
- Author claim: visual input can enhance LLM capability; correctness relates to effectiveness; LLMs are sensitive to
  misleading information.
- Author claim: TowerMind is challenging for classic RL (Ape-X DQN, PPO), broadening RL benchmark diversity.
- Numeric results: not visible in extracted text.

## Additional limitations identified during review
_(reviewer synthesis)_
- "Hallucination" here is narrowly operationalized as rule-invalid actions in a game; this does not measure factual
  hallucination or safety-relevant deception, so security relevance is limited.
- Deterministic, predefined enemy waves and fixed tower points make the environment a controlled planning testbed but
  a weak proxy for adversarial/agent-security threats (no injection, tool abuse, or multi-agent collusion surface).
- Benchmark-contamination mitigation relies on researchers authoring new levels; the built-in five levels remain
  contamination-exposed once public.
- As a single-agent PvE setting, it does not test agent-to-agent deception or environment-injection risks that matter
  for agent security.

## Design implications
Lightweight, contamination-resistant, multimodal simulators are a practical way to probe LLM-agent planning and
action-validity at low cost; executability/invalid-action rate is a cheap, useful reliability signal for agent action
interfaces.

## Implementation implications
Encoding state as JSON with named semantic fields aids LLM comprehension; a hybrid continuous+discrete action space
plus explicit valid-action checking gives a clean substrate for measuring and gating invalid agent actions.

## Evaluation implications
Agent evaluations should separate capability from reliability (invalid-action/hallucination), test robustness to
misleading observations and partial observability, and use author-editable tasks to control benchmark contamination.

## Deployment implications
The invalid-action-detection pattern (rule/state validity gating before execution) transfers directly to production
agent action-guards: verify each proposed action against environment state/rules before executing — "models propose,
environment verifies, gate decides."

## Monitoring and incident implications
Tracking invalid-action rate over time is a lightweight runtime health/hallucination monitor for deployed agents; a
spike can flag degraded planning or prompt/observation corruption.

## Applicability boundaries
This is a capability/reliability benchmark for LLM-as-agent planning, NOT an adversarial-security study. Its findings
generalize to agent planning/decision-making evaluation and action-validity gating, but should NOT be read as evidence
about prompt injection, tool abuse, privilege escalation, or multi-agent security. Peripheral to the guardian-agent
threat model except for the transferable action-validity-gating and contamination-control patterns.
