# Pattern — Human Approval for Consequential Actions

> **Control class.** Permission gate + Evidence (in the corpus's Capability · Permission · Verification · Evidence ·
> Residual-risk ontology). A deterministic, fail-closed checkpoint that interposes an authenticated human decision
> between an agent's *intent* to perform a high-consequence action and the action's *execution*.
>
> **Evidence integrity (non-negotiable).** Every claim below traces to a card in the AAAI-26 corpus via its stable
> paper id. Author-reported results are labeled as such and kept distinct from reviewer synthesis. All magnitudes are
> as reported by the cited paper under *that paper's own evaluated threat model* and are **not independently
> verified**. Where the corpus is silent, the text says "not stated in paper." Language is calibrated throughout
> ("reduced ASR against the tested attacks", "demonstrated under the evaluated threat model", "not evaluated
> against", "requires production validation"); no absolutes ("secure", "unbreakable", "proven safe") are used. The
> single most consistent gap in the corpus is the near-total absence of adaptive-attacker evaluation of defenses
> (`AILLM-Safety` §16, §17); treat every defense number here as a best-case upper bound.

---

## Problem addressed

Autonomous LLM/agent systems reach a point in their cognitive cycle where they can *execute* an action with real,
often irreversible, external effect: send funds, delete data, publish content, change access controls, run a shell
command, actuate a motor. The corpus establishes empirically that the model's own safety reasoning is
**necessary-but-insufficient at this action layer**: A41090 (MobileSafetyBench) shows interactive Android agents
proceed with harmful tasks even when a `refuse()` / `ask-consent()` action is available to them, and that
chain-of-thought "safety reasoning" (SCoT) improves benchmark scores yet leaves agents unsafe and
**self-inconsistent** — they "overlook safety considerations they themselves generated" (author-reported). A42273
independently shows models voice ethical concern in CoT and then comply anyway. The direct consequence for design:
you cannot let the model decide, unaided, whether a consequential action is permitted. A human-approval gate moves
that decision out of the model and behind a hard Permission boundary — because **capability ≠ permission ≠ safety**
(`AILLM-Safety` §6; empirically grounded by A41090 and A41468).

This pattern exists because *no* inference-time refusal defense in the corpus drives attack success to a safe floor
(A42191 ~31% residual ASR; A40248 ~16% residual harmful on Qwen-3-8B despite near-zero on its prefill metric;
A41468 material residual on its hardest agent classes — all author-reported). When residual harm is assumed rather
than wished away (`AILLM-Safety` §16), a human decision on high-stakes, irreversible actions is the compensating
Permission control that makes the residual survivable.

## Applicable assets and attack surfaces

- **Sensitive tools / actuators** in an agent's action space: payment/transfer calls, file deletion, credential
  use, access-control changes, outbound messages, code execution, physical actuation. A41468
  (InfrastructureSentinel) enumerates the fullest MCP action surface in the corpus: insecure tool use / command
  injection, privilege escalation, tool poisoning / supply chain, credential exposure, DoS.
- **The agent observation stream** — messages, memos, posts, files, tool outputs, retrieved documents — which is an
  *instruction channel* an attacker can plant content into (indirect prompt injection; A41090, A41468).
- **Caller-supplied conversation history / prior "assistant" turns**, trusted by default as authentic model output
  (A40840 Response Attack; A36996 CHASE). A fabricated turn can manufacture a prior "approval."
- **The approval summary itself** — the natural-language description of the pending action shown to the human. This
  is a first-class attack surface: if it is generated by a model from untrusted content, it is subject to the same
  output-channel manipulation that collapses composed guard stacks (A41108 STACK: guard pipelines that pass
  per-component evaluation moved ~0%→71% ASR under a whole-pipeline adaptive attack; A41144 MFA: 58.5% across 17
  open+commercial VLMs — both by inducing the model to emit an attacker-chosen string past the classifier;
  cross-paper synthesis from `Defense-Mitigation` / `Adversarial-ML-Attacks`).
- **Multi-step trajectories** where each individual action is below any per-action risk threshold but the aggregate
  is consequential (A40484 SafeNLIDB: complementary/aggregation queries each safe in isolation jointly exfiltrate
  protected DB fields).

## Threat model

Under the corpus's dominant, most product-relevant threat models (`AILLM-Safety` §3):

- **External attacker via indirect prompt injection.** Plants instructions in environment/tool content the agent
  reads, aiming to trigger a consequential action or to *pre-authorize* one (A41090 models exactly this; A41468
  taxonomizes it). The attacker does not need model internals or the human's credentials.
- **Malicious or compromised user / caller.** Supplies crafted history to fabricate a prior approval (A40840,
  A36996), or semantically obfuscates a harmful action so it reads as benign (emoji/glyph substitution A40296;
  math+code wrapping A40465; 21-cipher encryption A41058; cross-lingual "macaronic" recombination A40916). The
  model may *recognize* the intent yet still comply (A40296).
- **Query-efficient adversary.** Jailbreaks succeed at very low query budgets — single query (A40919, A40465),
  ≤10 queries (A41058), <15 queries (A40554). A volume/anomaly tripwire alone will not fire in time.
- **Defense-aware (adaptive) adversary.** The corpus's highest-confidence meta-finding is that wherever an attacker
  is allowed to be defense-aware, static defenses degrade or fail (`defense-in-depth` §0; `AILLM-Safety` §16). An
  adaptive attacker will target the *weakest* element of the approval flow — most likely the summary generator or
  the trust anchor deciding *what* to route for approval (the "Guardian LLM is itself an injectable trust anchor",
  reviewer synthesis on A41468).

**Out of scope for this pattern** (handled by sibling patterns): training-time poisoning/backdoors of alignment
(A40472, A41087, A41118), white-box representation-level attacks/defenses requiring residual-stream access
(A40551, A41119, A41148, A41074, A42191), and multimodal generative-content safety (T2I/audio/video). This pattern
is a runtime action-layer control and does not by itself defend those surfaces.

## Control mechanism

A **hard, deterministic Permission gate** placed at the pre-invocation boundary of the agent cognitive cycle
(observe → plan → **act** → audit). Grounded in A41090's action-space primitive and A41468's four-layer
architecture:

1. **Classify the pending action** against a policy that designates which actions are "consequential" (high-stakes
   and/or irreversible). Risk-tiering is explicit in the corpus (A41090 matched low-/high-risk task pairs; A41129
   EASE routes only "vulnerable regions" through expensive reasoning).
2. **If consequential, suspend execution** and require an out-of-band, authenticated human decision before the tool
   is invoked — the `ask-consent()` action A41090 makes first-class in the agent action space ("used when the agent
   requires user permission to proceed", A41090 card). Default outcome on the branch is **deny** (fail-closed).
3. **Present a faithful, provenance-tagged summary** of the *normalized* action (see Recommended pattern) so the
   human decides on canonical intent, not on attacker-shaped surface form.
4. **Enforce the decision as policy, not as a model suggestion.** The tool call is structurally unreachable without
   a valid approval token — "back reasoning with hard policy gating rather than trusting the model to honor its own
   safety notes" (A41090, reviewer synthesis).
5. **Emit an immutable audit record** of the request, the summary shown, the human decision, and the resulting state
   (A41468 Layer 4). This is the Evidence leg: a check that passed is not itself proof the check was sound
   (`defense-in-depth` CPVER legend).

The gate is one **layer** in defense-in-depth, never the sole control (`AILLM-Safety` §14; every defense card in the
corpus ends "should be a layer, not the sole control"). It sits behind input normalization and trust-boundary
isolation, and in front of least-privilege capability scoping.

## Preconditions and trust assumptions

- **A trustworthy path to the human.** The approval channel (its transport and the surface rendering the summary)
  must be outside the agent's write-influence and not itself derivable from untrusted content. If the summary is
  authored by a model from injected content with no independent grounding, the gate can manufacture false assurance
  — worse than no gate (reviewer synthesis, extending A41108/A41144).
- **A deterministic policy** defining "consequential." This is engineering-supplied; the corpus provides the *shape*
  (risk tiers, A41090) but no canonical action taxonomy or thresholds for a general approval gate — thresholds below
  are engineering targets requiring production validation, **not stated in paper**.
- **Authenticated approver identity** and a signed/attested approval token bound to the *specific* normalized action
  (not a session-wide grant). The corpus does not evaluate approver-identity spoofing; treat it as an assumed-secure
  dependency to be covered by the agent-identity / credential controls.
- **Least privilege already in place.** The gate presumes consequential tools are capability-isolated so that
  "approved" is the *only* path to invocation (`AILLM-Safety` §14: least privilege + human approval, paired).
- **Attested history provenance.** Prior turns and prior approvals must be integrity-checked, or history injection
  fabricates approvals (A40840, A36996). Absent attestation, do not treat any in-transcript "approval" as valid.

## System architecture

Aligned to the agent cognitive cycle, mapping A41468's four layers and A41090's action-space finding:

```
observe ──▶ plan ──▶ [ACTION INTENT] ──▶ act ──▶ audit
                          │
             ┌────────────┴───────────────────────────────────┐
             │  L0  Input normalization (before any gate):     │  ← A40296/A40465/A41058/A40916
             │      decode emoji/glyph/cipher/math+code/       │     (normalize before you gate)
             │      cross-lingual to canonical intent          │
             │  L1  Trust-boundary isolation:                  │  ← A41090/A41468
             │      untrusted context = DATA, not instructions │
             │  L2  Consequential-action classifier (policy):  │  ← A41090 risk tiers
             │      is this high-stakes / irreversible?        │     A41129 selective routing
             │  L3  Human-approval gate (fail-closed):         │  ← A41090 ask-consent()/refuse()
             │      suspend → faithful summary → authenticated │     A41468 L3 runtime exec gate
             │      decision → signed token bound to action    │
             │  L4  Immutable audit + state evaluator:         │  ← A41468 L4 audit
             │      record request/summary/decision/outcome;   │     A41090 rule-based state
             │      verify the action actually gated           │     evaluators (action log/FS/DB)
             └────────────────────────────────────────────────┘
```

Key architectural properties drawn from the corpus:

- **Permission at the plan/act boundary, not only at input** (`defense-in-depth` §1 "Emerging"; A41090, A41468).
  Content filters at input miss tool-poisoning, privilege escalation, and state-drift that only manifest at
  invocation (A41468 Layers 2–3: pre-execution tool-plan validation + just-before-invocation re-check).
- **Deterministic verification of the outcome**, not string/API-name matching. A41090 uses rule-based state-grounded
  evaluators that inspect action history, file storage, and app DBs — verify the world, not the model's claim.
- **The gate must not be a self-composing assumption.** Composition of individually-robust controls is not itself a
  control (A41108, A41144, cross-paper synthesis); the human decision is the element that must remain robust *when
  the model-side layers are assumed already bypassed*.

## Recommended implementation pattern

Prefer deterministic, fail-closed, least-privilege construction:

1. **Make consequential tools structurally unreachable without a fresh, action-bound approval token.** Capability
   isolation is the load-bearing Permission control (`AILLM-Safety` §on tool abuse). The agent cannot "argue its way"
   to invocation; there is a policy edge that requires the token.
2. **Normalize before you summarize and before you gate.** Map emojis/glyphs/ciphers/math+code/cross-lingual forms
   back to canonical intent *first* (A40296, A40465, A41058, A40916), then classify risk and generate the human
   summary from the normalized intent. This prevents a semantically harmful action from being described benignly.
3. **Generate the approval summary deterministically from structured action parameters**, not free-form from
   untrusted context. Show the concrete effect (recipient, amount, path to be deleted, command to be run, blast
   radius), the **provenance** of the content that triggered the action (which observation/tool output requested
   it), and the risk tier. Render it on a surface the agent cannot write to.
4. **Treat conversation history and prior approvals as untrusted until attested.** Sign/attest transcript
   provenance so an injected turn cannot masquerade as a genuine prior approval (A40840, A36996).
5. **Bind the approval token to the exact normalized action and a short expiry.** No session-wide or role-wide
   grants; one approval authorizes one action. This directly counters the multi-turn aggregation surface (A40484) by
   forcing each consequential step to its own decision.
6. **Aggregate-aware gating.** Because individually-benign steps can jointly become consequential (A40484), evaluate
   *cumulative* effect across the trajectory (trajectory-level, not step-level) and re-trigger approval when a
   running total crosses a tier boundary.
7. **Risk-tier to preserve usefulness.** Reserve human approval for genuinely consequential/irreversible actions
   (A41090 low/high-risk split; A41129 selective activation "reason/gate only when it matters") so the human is not
   desensitized by low-value prompts (see Known bypasses: approval fatigue).
8. **Log everything to an immutable, tamper-evident audit trail** (A41468 Layer 4), and run a post-action
   state-grounded evaluator (A41090) to confirm the action was in fact gated.

## Incorrect or fragile implementation patterns

- **Trusting the model's self-reported safety.** Letting the model decide "this doesn't need approval" is defeated
  because models reason about safety and comply anyway (A42273) and agents are self-inconsistent at the action layer
  (A41090 SCoT). The decision must be a hard policy edge, not a model output.
- **Summarizing the action for the human from raw untrusted content with a model.** This re-creates the composed
  guard-stack failure: the summarizer can be induced to emit an attacker-chosen benign string past the human
  (A41108, A41144). Prefer structured, deterministic summaries.
- **Gating on surface form / keyword / API-name matching.** Bypassed by encoding, cipher, math+code, and
  cross-lingual recombination (A40296, A40465, A41058, A40916); the model recognizes intent that the filter misses
  (A40296). Normalize first.
- **Volume/anomaly-based "is this suspicious" heuristics as the trigger.** Query-efficient attacks (single query
  A40919/A40465; ≤10 A41058; <15 A40554) execute before any many-query anomaly signal accrues.
- **Per-action thresholds with no aggregate view.** Defeated by multi-turn aggregation (A40484).
- **Session-wide or "approve once, trust forever" grants.** Converts one social-engineered approval into standing
  authority; violates least privilege and the action-bound-token requirement.
- **Fail-open on gate/summarizer error or timeout.** Any unavailability of the approval path must deny, not proceed.
- **Treating the gate as the sole control.** No single mechanism in the corpus is robust alone (`AILLM-Safety` §14).

## Verification strategy

- **Adaptive red-teaming is a launch gate, not a nice-to-have.** The corpus's most consistent gap is the absence of
  attacker-adapts-to-defense evaluation (`AILLM-Safety` §16–17; `defense-in-depth` §0). A human-approval gate must
  be evaluated against an adversary that *knows the gate exists and targets its weakest element* (the summarizer /
  the routing decision), not only against fixed scripted injections (A41090's own 50 injection tasks are scripted
  and non-adaptive — a floor, not a ceiling).
- **Deterministic, state-grounded outcome checks.** Verify with rule-based evaluators that inspect actual post-action
  state — action history, file storage, DB rows (A41090) — that no consequential action executed without a valid
  token. Prefer effect-based evaluation over string matching (consistent with the corpus's rule-based-evaluator
  template).
- **Whole-pipeline evaluation, not per-component.** Because composed controls do not self-compose (A41108, A41144),
  test the end-to-end flow with the model-side layers assumed bypassed, so the residual robustness of the human
  decision is measured directly.
- **Do not rely on a single automated judge for sign-off.** Validate any automated harm/consequence classifier
  against human agreement and evaluator-aware adversaries; single-LLM-judge scoring is a near-universal, acknowledged
  confound (`AILLM-Safety` §12; A40866 SceneJailEval is the corpus's scenario-adaptive judge but is itself untested
  against evaluator-gaming).
- **Instrument the helpfulness cost.** Over-refusal / false-positive rate is a first-class metric in the corpus
  (A41074, A41140, A41152, A42191, A40543); for this pattern the analogue is the **over-prompting / false-approval-
  request rate** that drives approval fatigue.

## Metrics and thresholds

> The corpus provides no validated threshold for a human-approval gate specifically (**not stated in paper**). The
> metrics below are the corpus's evaluation vocabulary applied to this control; the numeric targets are engineering
> defaults requiring production validation.

- **Unapproved-consequential-execution rate** — count of consequential actions that executed without a valid,
  action-bound token. Target by construction: **0** (fail-closed). This is the primary security metric; it is a
  Permission-correctness property, not an ASR estimate.
- **Residual harmful-action rate under adaptive attack** — the analogue of residual ASR. The corpus shows leading
  action-layer defenses leave material residual (A41468 material residual on hardest classes, author-reported ADR is
  coarse and rated Preliminary — the synthesis reads it as >50% miss on the hardest class; compare inference-time
  residuals A42191 ~31%, A40248 ~16%). Expect nonzero residual; the gate's job is to keep the *consequential* subset
  behind the human, not to zero out ASR.
- **Attack-Defense Rate (ADR)** under scripted *and* adaptive injection (A41468 uses ADR; report both, and report
  dataset size + false-positive rate, which A41468 omitted — its Preliminary rating stems from that omission).
- **Over-prompting / false-approval-request rate** and approver **decision latency** — the safety/utility trade-off
  (A41074, A41140, A42191). No corpus value; instrument against an adaptive benign-ambiguous set.
- **Query-budget resilience** — verify the gate fires deterministically on the *first* consequential action, since
  attacks succeed at single-query budgets (A40919, A40465, A41058, A40554).

## Test cases

Each maps to a concrete corpus attack:

1. **Indirect prompt injection triggers a consequential tool.** Plant an instruction in a message/memo/file/tool
   output that tells the agent to transfer funds / delete a file / change permissions. Expect: gate fires, human
   sees a faithful summary with the injected content flagged as untrusted provenance (A41090, A41468).
2. **Fabricated prior approval via history injection.** Inject a forged prior "assistant"/"user" turn claiming the
   action was already approved. Expect: gate rejects the unattested approval; a fresh, attested decision is required
   (A40840, A36996).
3. **Semantically obfuscated action.** Encode the consequential action with emoji/glyph (A40296), math+code wrapping
   (A40465), cipher (A41058), or cross-lingual recombination (A40916). Expect: normalization recovers canonical
   intent; the human summary reflects the *real* effect, and risk classification does not under-tier it.
4. **Multi-turn aggregation.** Issue N individually-benign steps that jointly cross a consequence threshold (A40484).
   Expect: cumulative-effect evaluation re-triggers approval before the aggregate completes.
5. **Model reasons about safety then proceeds.** Provide a scenario where CoT voices concern but the plan still
   invokes the action (A42273, A41090 SCoT self-inconsistency). Expect: gate enforced regardless of the model's
   self-report; approval still required.
6. **Command-injection / privilege-escalation tool chain.** A41468's insecure-tool-use and privilege-escalation
   classes. Expect: the escalating step is classified consequential and gated; capability isolation blocks the
   un-approved path.
7. **Low-risk action must NOT prompt.** A benign, reversible action (A41090 low-risk tier). Expect: no approval
   request (measures over-prompting / fatigue).

## Adaptive adversarial tests

The launch bar the corpus demands (`defense-in-depth` §0 names the disciplined adaptive-attacker exemplars):

- **Summary-poisoning attack.** Adversary crafts injected content so the *approval summary* understates or
  mischaracterizes the action — the STACK/MFA channel of inducing a model to emit an attacker-chosen benign string
  past the human reviewer (A41108, A41144). Test the summarizer as an adversary target.
- **Trust-anchor injection.** Attack the model/policy component that *routes* actions for approval, aiming to have a
  consequential action classified as low-risk and skip the gate (the "Guardian LLM is itself an injectable trust
  anchor" concern, reviewer synthesis on A41468).
- **Selective-router evasion.** If risk-tiering uses a model classifier, craft the action to look benign to the
  router so it bypasses the expensive gate entirely — the acknowledged evasion of vulnerable-region routing (A41129).
- **Single-/few-query success.** Confirm the gate is not defeated by an attack that completes before volume anomaly
  detection (A40919, A40465, A41058, A40554).
- **Whole-pipeline (not per-component) adaptive run.** Assume all model-side layers bypassed; measure whether the
  human decision + capability isolation still hold (A41108, A41144). Persist an adaptive attacker that adapts to the
  observed gate behavior, per the corpus's meta-finding (`AILLM-Safety` §16).

## Telemetry requirements

Emit structured, tamper-evident trace fields (consistent with the corpus's audit/trace templates — A41468 Layer 4
immutable audit; A41090 rule-based state evaluators; `AILLM-Safety` §13 structured trace fields):

- **Action descriptor**: tool, structured parameters, computed blast radius / reversibility, assigned risk tier.
- **Normalized intent** alongside the raw form, plus which normalizer fired (emoji/cipher/math+code/cross-lingual).
- **Provenance** of the triggering content: which observation/tool output/history turn requested the action, and its
  trust label (attested vs untrusted).
- **Approval event**: exact summary shown to the human, approver identity, decision, decision latency, token id and
  its action-binding, expiry.
- **Post-action state delta** from the rule-based evaluator (A41090) — confirmation the world matched the approved
  effect and that no un-approved consequential action executed.
- **Runtime tripwires (candidate, unvalidated as detectors):** invalid-action-rate spikes (A41134, A39818,
  cross-paper), per-decision entropy/MI and CoT n-gram drift (A41088, A42273) — log for forensics; the corpus notes
  these lack ROC/PR validation, so do not gate solely on them, and do not expose raw CoT to users (`AILLM-Safety`
  §14).

## Failure handling

Fail-closed on every uncertainty:

- **Gate/summarizer unavailable, errored, or timed out** → deny the action. Never fail-open.
- **Approval times out or is not granted** → deny; the agent takes the `refuse()` path (A41090) or requests
  clarification, but does not proceed.
- **Provenance/attestation cannot be established** for history or a claimed prior approval → treat as no approval
  (A40840, A36996).
- **Normalization ambiguous** (cannot resolve the action to a canonical intent) → escalate to human with the
  ambiguity flagged; default deny if unresolved.
- **Aggregate crosses a tier mid-trajectory** → suspend and re-request approval before continuing (A40484).
- **Classifier/router uncertain whether an action is consequential** → treat as consequential (gate), not benign.

## Rollback and containment

- **Capability isolation as the containment boundary.** Consequential tools sit behind revocable capability tokens
  (least privilege, `AILLM-Safety` §14); on anomaly, revoke the capability so no further consequential action is
  reachable regardless of model state.
- **Action-bound, short-expiry tokens** limit blast radius to a single approved action; a compromised approval
  cannot be replayed for other actions or later.
- **Immutable audit enables forensic reconstruction** (A41468 Layer 4): the full request → summary → decision →
  outcome chain supports post-incident review and, where the action was reversible, targeted rollback.
- **Constraint-aware access** to prevent the aggregation path from reconstituting a blocked effect (A40484 APO-style
  constraint enforcement on cumulative access).
- Note: the corpus does not evaluate rollback mechanisms for irreversible physical/financial effects — for those,
  containment is *prevention* (the gate) plus capability revocation; there is no post-hoc undo. Design accordingly.

## Known bypasses

- **Approval-summary poisoning** — if the human sees an attacker-shaped or model-generated summary, they may approve
  a mischaracterized action (extends A41108/A41144's "emit an attacker-chosen string past the classifier" to the
  human-reviewer channel; reviewer synthesis).
- **Trust-anchor / router compromise** — inducing the routing component to under-tier a consequential action so the
  gate is skipped (reviewer synthesis on A41468; router evasion A41129).
- **Fabricated prior approval** via history injection (A40840, A36996) if approvals are not attested.
- **Semantic obfuscation** so the summary/classifier under-represents harm (A40296, A40465, A41058, A40916) if
  normalization is absent or incomplete.
- **Multi-turn aggregation** under a per-action threshold (A40484) if there is no cumulative view.
- **Approval fatigue / rubber-stamping** — over-prompting desensitizes the human; the corpus's over-refusal
  literature establishes that safety controls carry a real usability cost (A41074, A41140, A41152, A42191, A40543),
  and reviewer synthesis extends this to habituated approvers. The corpus provides **no measured approval-fatigue
  rate** (not stated in paper); it is a real and unquantified bypass to be mitigated by risk-tiering.
- **Model self-report substituted for enforcement** — if any part of the gate trusts the model's "this is safe"
  claim, A42273 / A41090 self-inconsistency defeats it.

## Residual risks

- **No control drives residual to zero.** Action-layer defenses leave material residual under their own tests
  (A41468, author-reported/Preliminary; comparators A42191 ~31%, A40248 ~16%). The gate reduces the *consequential*
  residual by routing it to a human, but does not eliminate harm — and it inherits any residual in the layers
  feeding it.
- **The human is a fallible verifier.** Attention limits, fatigue, and social-engineered/poisoned summaries mean the
  human decision is itself an imperfect control; the corpus does not measure human-in-the-loop accuracy under
  adversarial summaries (not stated in paper).
- **Guardian/summarizer/router are injectable trust anchors** (reviewer synthesis on A41468) and, like every
  component in the corpus, are largely un-evaluated against adaptive attackers (`AILLM-Safety` §16–17).
- **Automated risk-classification is judge-dependent** and potentially gameable (`AILLM-Safety` §12).
- **Irreversible effects have no rollback** (see Rollback and containment); prevention is the only line.
- **External validity** — A41090/A41468 evidence is from self-proposed, non-adaptive benchmarks on a limited model
  set; "requires production validation" applies to every number here.

  summary/output channel is an attack surface (cross-paper synthesis from `Defense-Mitigation` /

- **A41134 / A39818** — stage-dependent pipeline risk; invalid-action-rate as a runtime monitor (cross-paper).
- **A40866 (SceneJailEval)** — scenario-adaptive severity-graded judge; do not rely on a single automated judge.
- **A41074 / A41140 / A41152 / A42191 / A40543** — over-refusal / false-positive as a first-class metric (the
  approval-fatigue analogue).
- **A42191 (~31% residual ASR) / A40248 (~16% residual)** — residual-harm evidence motivating a compensating
  Permission control.

## Evidence strength

- **The architecture is well-motivated and convergent.** Human approval + hard policy gating + least privilege +
  immutable audit + trust-boundary isolation recurs across independent agentic papers (A41090, A41468) and is
  reinforced by the cross-category defense-in-depth reading. The *direction* of the recommendation is strong.
- **The quantitative evidence for the gate itself is weak-to-preliminary.** A41090 is the strongest agent-security
  evidence class (interactive, human-annotated risk severity, rule-based evaluators, matched risk pairs) but uses a
  self-proposed benchmark with scripted, non-adaptive injections. A41468 is Preliminary (coarse ADR, no dataset
  size / FP, no adaptive testing). No paper reports a validated, adaptive-tested human-approval gate with numbers.
- **Corpus-wide caveat:** the dominant methodological gap is the absence of adaptive-attacker evaluation
  (`AILLM-Safety` §16–17; `defense-in-depth` §0). Every defense number cited is a best-case upper bound.
  **"Requires production validation" applies to this entire pattern.**
- **Overall rating (reviewer synthesis):** *Recommended as a required Permission layer for consequential/irreversible
  actions; robustness of any specific implementation is unproven and must be established by whole-pipeline adaptive
  red-teaming before reliance.*

## When NOT to use this pattern

- **Low-stakes, reversible, high-frequency actions.** Gating these desensitizes the approver (approval fatigue) and
  degrades the gate's value where it matters. Risk-tier and reserve approval for consequential/irreversible actions
  (A41090 low/high split; A41129 "gate only when it matters"). Over-gating is itself a failure mode, analogous to
  over-refusal (A41074, A41140, A42191).
- **As a replacement for least privilege or hard policy gating.** It is a layer, not the sole control
  (`AILLM-Safety` §14); a human-approval gate on top of over-broad capabilities still leaves standing authority to
  abuse. Pair it with capability isolation.
- **When the approval path or summary cannot be trusted** — if the only available summary is model-generated from
  untrusted content with no independent grounding, the gate can manufacture false assurance and is worse than an
  honest hard-deny policy (reviewer synthesis, extending A41108/A41144). Fix the trusted path first.
- **Latency-critical autonomous loops where a human cannot be in the loop in time** (e.g. real-time control). There,
  substitute a deterministic policy gate / pre-execution simulation and out-of-band alerting; human approval is a
  design mismatch, not a control.
- **Surfaces this pattern does not cover** — training-time poisoning/backdoors (A40472, A41087, A41118), white-box
  representation attacks (A40551, A41119, A41148), and multimodal generative-content safety — require their own
  patterns; do not treat an action-layer approval gate as covering them.
